jq コマンドで「has no keys」エラーが発生する場合、stdin の入力形式を確認する必要があります。

jq はデフォルトで JSON 入力を期待しますが、テキストファイル（特に YAML フロントマター付き）を cat または別のコマンドでパイプすると、最初に遭遇する非 JSON 形式（例：YAML 行）が文字列として扱われ、キー選択操作（.key, .key | keys など）が失敗します。

エラー例：
  cat tool-results.txt | jq ".lastSessionNumber"
  # 出力: jq: error: string ("---\nname:...") has no keys

原因：tool-results.txt がマークダウンの YAML フロントマター（"---" で囲まれた部分）から始まっている場合、最初の行が文字列扱いになる。

解決方法：
1. JSON 形式であることを事前確認
   jq empty file.json && jq ".key" file.json

2. または tail/sed で JSON 部分だけを抽出
   tail -n +N file.txt | jq ".key"

3. または JSON 検証フィルタを前置
   cat file.txt | jq -R "fromjson? | .key"
   （fromjson は JSON パースに失敗するとフィルタリング）

jq に入力する前に、その形式が JSON か、YAML フロントマター・テキストを含まないかを確認すること。
