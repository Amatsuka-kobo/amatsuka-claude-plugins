prompt-smith の runLoop で新しいオプション（例：timeoutSeconds）を追加する際は、それを downstream 関数（improveDescription 等）に pass through する必要があります。

問題: runLoop が timeoutSeconds を受け取っても improveDescription に pass しないと、test は期待値と異なる値（undefined など）を見て失敗します。

対策:
1. runLoop のオプションパラメータを improveDescription の呼び出しに明示的に pass する
   例: callClaude = callClaudeText, callOptions = { timeoutSeconds }, improveDescription({ ..., ...callOptions })
2. test で vi.mock.calls を使う場合は、mock.calls[0] アクセス時に type guard を使う
   例: improve.mock.calls[0]?.[0].timeoutSeconds（optional chaining）または bounds check
3. TypeScript は mock.calls の型を最初 [] で推論するため、配列アクセスの before/after に型ガードが必須

この実装パターンは prompt-smith では頻繁に出現するため、add/modify 時は必ず downstream pass-through を確認する。
