スクリプトの stdout を JSON としてパースする前に、そのプロセスが成功したことを確かめる。

コマンドが起動に失敗したり異常終了した場合、stdout は空か途中で切れる。パイプ先の Python/jq はそれを「不正な JSON」として報告するため、エラーがデータの問題に見える。実際の原因は実行そのものの失敗である。

例 (誤)：
  node scripts/run-eval.mjs --skill ... | python3 -c "import json,sys; json.load(sys.stdin)"
  # 起動失敗時: JSONDecodeError が出るが、真因は Cannot find module

例 (正)：
  node scripts/run-eval.mjs --skill ... > /tmp/out.json 2>/tmp/out.err
  echo "exit=$?"           # 終了コードを先に見る
  head -3 /tmp/out.err     # 失敗していれば理由がここにある
  python3 -c "import json; json.load(open('/tmp/out.json'))"

stdout と stderr を必ず分けて受け、終了コードを確認してからパースする。JSONDecodeError を見たら、まず入力が本当に JSON のつもりで生成されたものかを疑う。

スクリプトを相対パスで起動する場合は、直前の cd で cwd がずれていないかも確認する(ab-2026-0801-001 と併発しやすい)。
