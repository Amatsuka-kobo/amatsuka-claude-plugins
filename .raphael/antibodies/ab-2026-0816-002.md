Node.js スクリプトをシェルコマンドから起動する際、process.argv[1] に JSON データを渡す場合、シェルの引数展開とスクリプト側のパース処理の層を分けて考える必要があります。

シェル変数展開やコマンド置換（$(...) や $(cat ...)）がファイルパスやテキストを評価してしまい、その結果が process.argv に渡されると、JSON ではなく文字列（例：/tmp/filename）が渡されて JSON.parse が失敗します。

例 (誤)：
  node /tmp/script.mjs "$(cat /tmp/data.json || echo PLACEHOLDER)"
  # 失敗時: process.argv[1] = "PLACEHOLDER" → JSON.parse fail

例 (正)：
  # 方法1: JSON ファイルを直接読む
  cat /tmp/data.json | node /tmp/script.mjs
  # スクリプト内: const data = JSON.parse(require("fs").readFileSync(0, "utf8"))

  # 方法2: JSON を変数に格納してから渡す
  json=$(cat /tmp/data.json)
  node /tmp/script.mjs "$json"

  # 方法3: shell の set -e で失敗時に早期終了
  set -e
  json=$(cat /tmp/data.json)  # 失敗時ここで exit
  node /tmp/script.mjs "$json"

Node.js スクリプトに JSON を引数経由で渡す場合、シェルの置換後に実際のデータが process.argv に到達することを確認してから JSON.parse を呼ぶ。または JSON をファイル/stdin 経由で読むことを検討する。
