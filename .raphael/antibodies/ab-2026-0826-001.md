python3 -c でファイルを read_text() し、marker/addition のような python 文字列変数で複数行の TypeScript コード片を組み立てて write_text() で書き戻す方式は、波括弧・クォート・改行の対応が入り組むほど生成後の構文を壊しやすい。

問題: python の assert s.count(marker)==1 などは「置換対象の文字列が存在するか」しか検証せず、置換後に生成されたコードの構文（波括弧の対応、クォートのネスト）は検証しない。そのため python 自体は正常終了するが、書き込んだ .ts ファイルが構文エラーになり、後続の biome format / vitest / esbuild が失敗する。

例（実際の失敗）:
  python3 -c "...; addition='''  it(\"...\", () => {\n ... \n  })\n'''; ...; p.write_text(s)" \
    && pnpm exec biome format --write xxx.test.ts
  → 'Code formatting aborted due to parsing errors'

対処:
1. 可能な限りこのプロジェクトの規約どおり、TypeScript/JavaScript/Markdown の編集は Serena の編集ツールを使い、python3 -c による文字列置換編集を避ける。
2. どうしても文字列置換で編集する場合は、追加するコード片の波括弧・括弧の対応を書く前に数える。
3. write_text() 実行後、&& で vitest 等の重いコマンドへ連結する前に、まず軽量な構文検証（pnpm exec biome format --write 単体、または tsc --noEmit）を挟んで結果を確認する。
4. 失敗したら git diff で実際に書き込まれた内容を確認してから再修正する。大きな一括置換より、小さな単位の編集を積み重ねる方が安全。
