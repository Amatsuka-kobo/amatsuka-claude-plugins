metatron の stage-* から commit-* までの間に staging の有効期限(既定 30 分)が切れると、commit が次のエラーで失敗する。

エラー: "staging ... は有効期限(...Z)を過ぎています。stage からやり直してください。"

**期限切れは異常ではない。** stage-* の応答自身が「diff を全文提示してユーザーの承認を得るまで commit を実行しないこと」と返す。承認を待つ運用では期限切れが起こりうる。承認を省いて stage と commit を連続実行することで回避しない。

取る手段:

1. 期限が切れたら、同じ入力ファイルで stage をやり直す。CLI へ渡した入力 JSON を一時ファイルへ残しておけば、同じ diff が再現する。
2. 再 stage の内容が承認済みの diff と一致することを機械で確かめてから commit する。目視で済ませない。
3. 承認ゲートを持たない経路(テスト・自動化されたバッチ)でだけ、stage と commit を連続実行してよい。

staging は単一ターゲットであり、期限切れで失敗しても対象ファイルは 1 バイトも変わらない。やり直しは、まだ済んでいないステップから続ければよい。
