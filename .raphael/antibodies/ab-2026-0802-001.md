公式 skill-creator の run_eval.py / run_loop.py を、description の質の測定に使わない。

この 2 つは測りたいものを測っていない。

1. find_project_root() が実リポジトリのルートを cwd にする。そのリポジトリの全スキルが同席した状態で測るので、出るスコアは description の質ではなく手元のカタログとの競争結果になる。このリポジトリでは 45 のプロジェクトスキルが同席する。
2. 本文を捨てた description だけの薄いファイルを測定対象にする。本番の SKILL.md とは別物を測っている。

この結果に合わせて description を書き換えると、本番を改悪する。

代わりに移植版を使う。

  node plugins/prompt-smith/scripts/run-trigger-eval.mjs \
    --skill-path <スキルのディレクトリ> \
    --eval-set <eval JSON> \
    --model claude-opus-5 --runs-per-query 3

  node plugins/prompt-smith/scripts/run-loop.mjs \
    --eval-set <eval JSON> \
    --skill-path <スキルのディレクトリ> \
    --model claude-opus-5 --max-iterations 5

登録先(.claude/skills/ と .claude/commands/)は判別要因ではない。2026-08-09 の対照実験で両経路とも 10/24 だった。「commands に登録するから自然文の依頼で発火しない」という以前の説明は否定されている。

詳細は plugins/prompt-smith/docs/skill-creator-port-rationale.md を参照する。
