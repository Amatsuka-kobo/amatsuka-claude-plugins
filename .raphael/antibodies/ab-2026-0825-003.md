pnpm --dir フラグで実行ディレクトリを変更した後、後続のコマンド（vitest、npm run など）が EACCES（パーミッション不足）で失敗する。

pnpm --dir /path/to/project vitest run ... で実行すると、cwd が /path/to/project に変更されるが、そのディレクトリから見た相対パスやアクセス権限が異なるため、実行に失敗することがある。特に vitest など node_modules を参照するコマンドは、--dir 指定時に node_modules への相対パス解決が正しくならない可能性がある。

例 (誤)：
  pnpm --dir /home/user/project vitest run ./tests/test.ts
  # 出力: [ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL] spawn /home/user/project EACCES

例 (正)：
  # 方法1: cd で cwd を変更してから実行
  cd /home/user/project && pnpm vitest run ./tests/test.ts

  # 方法2: 絶対パスで node_modules を明示
  pnpm --dir /home/user/project run vitest -- tests/test.ts

  # 方法3: (確実) cd でディレクトリに移動してから実行
  (cd /home/user/project && pnpm vitest run ./tests/test.ts)

pnpm --dir は特定の workspace パッケージ実行に有用だが、vitest などの node_modules 依存コマンドには相性が悪い。cd 経由または -C フラグでの実行を検討する。
