Bash commands passed to Claude Code's Bash tool with multi-line structure and backslash continuations (e.g., `git add -- \ file1 \ file2`) get normalized: actual newlines convert to literal `\ ` (backslash-space), breaking argument parsing. Additionally, if listed files do not exist (e.g., generated lockfiles not created by prior npm install success), git add fails with "pathspec did not match any files" exit code 128. Workaround: ensure all files exist before listing them, use `git add -A` to stage all changes at once, or pass files via stdin (e.g., `printf '%s\n' file1 file2 | xargs git add --`).
