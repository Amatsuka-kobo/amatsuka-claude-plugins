grep や rg コマンドでグロブパターン(*)を含む引数を指定する場合、シングルクォートで囲まれていない文字列内のパターンは、コマンド実行前にシェルが展開されることを期待している。該当ディレクトリ内のファイルが 0 件マッチする場合、grep/rg はシェルが展開した後のリテラル文字列(例: /path/*2026-10-05*)をそのままパスとして解釈しようとし、ENOENT で exit code 2(エラー)で失敗する。対策として、(1) シェルオプション shopt -s nullglob で無マッチ時に空文字列を返す設定にする、(2) grep/rg 実行前に test -d でディレクトリ存在を確認する、(3) find や ls で事前にパターンマッチを確認する、(4) grep/rg に到達する前にグロブが展開される環境を確認する。
