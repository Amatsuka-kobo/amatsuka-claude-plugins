テストケース内でファイルシステム操作（特に一時ディレクトリや tmpdir への書き込み）に失敗する場合、その操作の本来の原因（ENOENT、EACCES、EAGAIN など）がテストエラーメッセージとして保持されていることを確認する必要があります。

テスト内でファイル書き込みやディレクトリ作成が失敗した際、例外をキャッチしている場合は、そのエラーメッセージを transcript や出力に記録し、テスト失敗時にその理由が明確に示されることを確認する。単に「file not found」と報告するだけでなく、「why the file operation failed」という根本原因を残す。

例:
  // 誤り: エラー理由がマスクされる
  try {
    await readFile(transcript_path)
  } catch (e) {
    throw new Error("transcript not found")
  }

  // 正しい: 元の理由を保持
  try {
    await readFile(transcript_path)
  } catch (e) {
    throw new Error(`transcript operation failed: ${e.message}`)
  }

特にテスト中の一時ファイル操作では、cleanup や file lock による失敗も考慮され、単純な「file missing」として片付けない。
