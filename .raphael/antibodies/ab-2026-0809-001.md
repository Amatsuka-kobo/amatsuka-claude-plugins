複雑な JSON をシェルコマンドで printf '%s\n' '...' 形式で stdin 経由で渡す場合、バックスラッシュと引用符のエスケープ層が深くなる。

シェルが解釈する層とJavaScript（またはNode.js）が解釈する層が重なるため、単純な置換では対応できない。

例（誤り）：
  printf '%s\n' '{"key":"value with \"quotes\""}' | node ...
  # 問題: バックスラッシュエスケープがシェル層で先に処理される

例（正しい）：
  # 方法1: Bash変数を使う
  json='{"key":"value"}'
  printf '%s\n' "$json" | node ...

  # 方法2: HEREDOC を使用
  node ... << 'EOF'
  {"key": "value"}
  EOF

  # 方法3: jq または node -e で JSON を直接組み立てる
  node -e 'console.log(JSON.stringify({key:"value"})' | ...

シェルコマンドから CLI に引き数を渡す場合、文字列層とデータ層を明確に分離し、エスケープ順序を検討する。
