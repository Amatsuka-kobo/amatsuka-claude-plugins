node -e や python3 -c でスクリプトをダブルクォートで囲んで渡す場合、スクリプト中にバッククォート（テンプレートリテラルや、挿入する TypeScript コード片のバッククォート）が含まれていると、JavaScript/Python のパーサーに届く前にシェルがバッククォートをコマンド置換として評価してしまう。

問題: node -e "...`text`..." や python3 -c "...`${a}-${b}`..." のように、ダブルクォート内にバッククォートを含めると、シェルがバッククォート間の文字列をコマンドとして実行しようとし、意図した文字列（テンプレートリテラルや挿入先の TypeScript コード）が壊れる。python3 -c で TypeScript コード片を組み立てて write_text() する場合も同様で、生成されるコードにバッククォートが含まれると esbuild の Transform エラーなど後続ビルドが失敗する。

解決策:
1. シングルクォートを使用: node -e 'const s = `text`'（python3 -c も同様）
2. ダブルクォート内でバッククォートをエスケープ: node -e "const s = \\`text\\`"
3. JSON 引数経由で渡す: node -e 'JSON.parse(process.argv[1])' '{"key":"value"}'

原因: シェルの引用符層とスクリプト言語のパーサー層が混在するため、複数レイヤーのエスケープが必要。ダブルクォート内のバッククォートは常にシェルのコマンド置換として先に評価される。
