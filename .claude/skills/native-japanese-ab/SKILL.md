# native-japanese の前後比較

規律を変える前と後のプラグインで同じ題材を書かせ、決めた型の件数と本文を比べる。

## 題材と型を用意する

- 題材と型は、変えた項目ごとに作る。`assets/example-prompts.json` と `assets/example-patterns.json` は形式の例示であり、内容は今回変えた項目に合わせて書き換える。
- 作ったファイルは scratchpad に置く。
- 題材は、変えた項目が当たる場面を会話の依頼文として書く。数値・条件・固有の名前を依頼文に含める。
- 題材は 1 項目につき 2〜3 本、合計で 10 本前後にする。
- 題材の話題は、規律の本文にある例文の話題と重ねない。
- 型は、減らしたい形と増やしたい形の両方を正規表現で書く。
- 正規表現で書けない項目(語の選び方など)は型にせず、「結果を読む」の手順で本文を読んで比べる。

## 採取する

リポジトリのルートで実行する。次は例示であり、値は実際の内容に置き換える。

```bash
python3 tools/native_japanese_ab.py run \
  --before <変更前のコミット> --after <変更後のコミット> \
  --prompts <題材の JSON> --patterns <型の JSON> --out <scratchpad のディレクトリ> \
  --models opus,sonnet --runs 3
```

- 変更をまだコミットしていないときは、`--after WORKTREE` を渡す。
- 採取はバックグラウンドで実行する。
- `--out` は実行ごとに新しいディレクトリにする。題材かモデルを変えたときに、前の応答が混ざるためである。
- 終了時に `timeout` か `error` が出たら、同じ引数でもう一度実行する。保存済みの応答は採り直されない。
- 2 回実行しても失敗が残るときは、失敗した本数を報告に書き、残りで比べる。

## 結果を読む

- `run` の最後に出る表を読む。型ごとに、一致の件数と、一致を含む応答の本数が前後で並ぶ。
- 件数に差が出た型は、`report --patterns <型の JSON> --out <dir> --show <型の id>` で一致した文を読み、誤って拾った文を除いて数え直す。
- 型を直したときは `report` だけを実行し直す。
- 型にしなかった項目は、`<out>/text/before/` と `<out>/text/after/` から同じ題材の応答を 3 本ずつ読んで比べる。
- 「Skill を起動した本数」が応答の本数より少ないときは、規律を読まずに書いた応答が混ざっている。その本数を報告に書く。
- 一致を含む応答の本数の差が 3 本以下の型は、差があると言い切らず、「差は確かめられなかった」と書く。

## 報告する

報告には次を書く。

- 前後のコミット、モデル、題材の数、回数、失敗した本数
- 型ごとの前後の件数の表
- 差が出た型ごとに、一致した文の実例を前後 1〜2 文ずつ
- 除いた誤検出の件数と理由
- 本文を読んで比べた項目の所見
- 変えた項目ごとの判定(効いた・差は確かめられなかった・逆に動いた)
