# native-japanese の前後比較

規律を変える前と後のプラグインで同じ題材を書かせ、決めた型の件数と本文を比べる。

## 題材と型を用意する

- 題材と型は、変えた項目ごとに作る。
- `assets/example-prompts.json` と `assets/example-patterns.json` は、可能性の言い方・変化の「になる」・製品の用語・「得る」の 4 項目を変えたときに使ったもので、判定しない型も含む。形式の見本として読み、別の項目を変えたときは題材も型も作り直す。
- 作ったファイルは scratchpad に置く。
- 題材は、変えた項目が当たる場面を会話の依頼文として書く。数値・条件・固有の名前を依頼文に含める。依頼文はそのままモデルへ渡る。
- 題材は 1 項目につき 2〜3 本、合計で 10 本前後にする。
- 題材の話題は、規律の本文にある例文の話題と重ねない。
- 型は、減らしたい形と増やしたい形の両方を正規表現で書く。判定に使う型には `"want"` へ「増やす」か「減らす」を書く。
- 傾向を見るだけで判定しない型には `"want"` を書かない。表には出るが、判定の対象にしない。
- 正規表現で書けない項目(語の選び方など)は型にせず、「結果を読む」の手順で本文を読んで比べる。

## 採取する

リポジトリのルートで実行する。次は例示であり、値は実際の内容に置き換える。

```bash
python3 tools/native_japanese_ab.py run \
  --before <変更前のコミット> --after <変更後のコミット> \
  --prompts <題材の JSON> --patterns <型の JSON> --out <scratchpad のディレクトリ> \
  --models opus,sonnet --runs 3
```

- `--before` には規律を変えた最初のコミットの親を、`--after` には最後のコミットを渡す。
- 変更をまだコミットしていないときは、`--after WORKTREE` を渡す。
- 採取は Bash の `run_in_background` で実行し、完了の通知が届いてから結果を読む。120 本(10 題材 × 2 モデル × 3 回 × 前後)で 5〜10 分が目安である。
- 新しい比較は、リポジトリの外の新しい `--out` で始める。`--after WORKTREE` で採った後に作業ツリーを編集したときも、新しい `--out` にする。同じ `--out` では初回の複製が使われる。
- 終了時に `timeout` か `error` が出たら、同じ引数と同じ `--out` でもう一度実行する。保存済みの応答は採り直されない。
- 2 回実行しても「採れなかった本数」が残るときは、その本数を報告に書き、残りで比べる。
- 採取は `--out` の下の空のディレクトリで動き、ユーザーの設定とこのリポジトリの CLAUDE.md を読まない。`--out` は、祖先のディレクトリに CLAUDE.md が無い場所に置く。

## 結果を読む

- `run` の最後に出る表を読む。型ごとに、一致の件数と、一致を含む応答の本数が前後で並ぶ。
- 判定には「含む本数」を使う。件数は 1 本の応答に偏るので、判定に使わない。
- 含む本数が前後で違う型は、`report --patterns <型の JSON> --out <dir> --show <型の id>` で一致した文を読む。
- 誤って拾った文があるときは、型の正規表現を直して `report` を実行し直す。正規表現で除けないときは、`--show` の出力から手で数え、除いた件数を控える。
- 型にしなかった項目は、その項目の題材を 1 つ選び、`<out>/text/<before|after>/<モデル>/<題材>-<回>.txt` をモデルごとに前後の全回ぶん読む。変えた項目の文面どおりの形で書かれているかを比べる。
- 「Skill を起動した本数」が応答の本数より少ないときは、規律を読まずに書いた応答が混ざっている。比較からは外さず、その本数を報告に書く。

`want` を書いた型の判定は次の表で決める。差は、誤検出を除いた後の含む本数を応答の本数で割った割合の、前後の差とする。この判定は目安であり、報告には前後の本数を添える。

| 判定 | 条件 |
| --- | --- |
| 効いた | 差が `want` の向きで、10 ポイントを超える(前後 60 本ずつなら 7 本以上)。一致した文を読み、狙った形だと確かめている |
| 逆に動いた | 差が `want` と逆の向きで、10 ポイントを超える |
| 差は確かめられなかった | 上のどちらでもない |

## 報告する

報告には次を書く。

- 前後のコミット、モデル、題材の数、回数、採れなかった本数
- 型ごとの前後の件数の表
- 差が出た型ごとに、一致した文の実例を前後 1〜2 文ずつ
- 除いた誤検出の件数と理由
- 本文を読んで比べた項目の所見
- 変えた項目ごとの判定
