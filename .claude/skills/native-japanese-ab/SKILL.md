# native-japanese の前後比較

規律を変える前と後のプラグインで同じ題材を書かせ、台帳にある型の件数と本文を比べ、目安に届いたかを判定する。

## 台帳に今回の題材と型を足す

`assets/prompts.json`・`assets/patterns.json`・`assets/targets.json` は、これまでの改修で測った題材・型・目安をためた台帳である。採取と集計は、台帳の全部を対象に行う。

- 今回変えた項目の題材と型を、台帳の末尾に足す。
- 台帳にある題材と型は消さない。型が誤って拾うときは、その型の正規表現だけを直す。
- 足す題材と型には、`"since"` に今回の改修の日付と題を書く(「2026-11-12 可能性の言い方」の形)。同じ日の別の改修と区別できる題にする。
- 題材は、変えた項目が当たる場面を会話の依頼文として書く。数値・条件・固有の名前を依頼文に含める。依頼文はそのままモデルへ渡る。
- 題材は 1 項目につき 2〜3 本足す。
- 題材の話題は、規律の本文にある例文の話題と、台帳にある題材の話題に重ねない。
- 型は、減らしたい形と増やしたい形の両方を正規表現で書く。型には `"item"` に、その型で測る項目の名前を書く。`item` は台帳を読む人のための欄で、表には出ない。
- 判定に使う型には `"want"` へ「増やす」か「減らす」を書く。
- 傾向を見るだけで判定しない型には `"want"` を書かない。表には出るが、判定の対象にしない。
- 型をどこに当てるかは `"unit"` で決める。

| `unit` | 当てる先 | 使う場面 |
| --- | --- | --- |
| 省略か `text` | 応答の全文 | Markdown の書式やコードの中も数える型 |
| `prose` | コードフェンス・表の行を除き、インラインコードを 1 字に置き換えた本文 | 地の文の語や形を数える型 |
| `sentence` | `prose` の本文を分けた 1 文ずつ。行頭の見出し・箇条書きの記号と `**` を落とし、句点・`!`・`?`(全角を含む)で切る。番号は後ろに空白があるものだけを落とし、閉じ括弧の直前では切らない。閉じていないコードフェンスは末尾までを除く。ひらがなを含む 8 字以上のものだけを文とする | 文頭・文末の形を数える型。件数は当たった文の数になる |

- 特定の題材だけで測る型には、`"prompts"` に題材の id の配列を書く。
- 正規表現で書けない項目(語の選び方など)は型にせず、「結果を読む」の手順で本文を読んで比べる。
- 変えた項目が台帳の題材と型で既に測れるときは、足さない。

### 目安を足す

目安は、項目ごとに「この値に届けば合格」とする基準である。今回変えた項目には、目安を 1 つ以上足す。

- 目安の値はユーザーと決める。手順は次のとおりである。
  1. 今回の題材と型を台帳に足す。今回の目安も `targets.json` に足すが、`op`・`value`・`basis` は省く。
  2. 「採取する」のコマンドに `--before-only` を付けて採る。改修後の列と判定を除いた表が出る。値を省いた目安は、「目安」の列に「未定」と出る。
  3. 表から今回の目安の行をユーザーに示し、値を決める。
  4. 決まった `op`・`value` と、その根拠の `basis` を `targets.json` に書く。`report --patterns <型の JSON> --targets <目安の JSON> --out <dir>` を同じ `--out` で実行する。採り直しは要らない。
- 今回の目安を足さないときは、`--before-only` を付けずに採る。
- 目安の `basis` には、値を決めた根拠を 1 文で書く。今回決めた目安なら「改修前は 60 本のうち 2 本」、規律の文面から決まる目安なら「規律は 2 箇所までと定める」のように書く。`basis` は台帳に残す欄で、表には出ない。
- 届かなくても直さないとユーザーが決めた目安には、`note` にその決定を書く。判定が「届かない」のときに表へ出る。
- 値が決まった目安には `id`・`since`・`item`・`basis`・`metric`・`op`(「以上」か「以下」)・`value` を書く。`item` は表の「指標」の列にそのまま出るので、何を数えた値かが分かる短い名前にする。
- `metric` は次の表から選ぶ。`patterns` には型の id を、`prompts` には対象を絞る題材の id を書く。

| `metric` | 値 | 要る欄 |
| --- | --- | --- |
| `skill` | japanese-writing を起動した応答の割合(%)。題材では絞れない | なし |
| `touten` | 読点の 100 字あたりの数。字数は `prose` の本文から空白を除いて数える | なし |
| `share` | `unit` が `sentence` の型に当たった文が、対象の文に占める割合(%) | `patterns` |
| `ratio` | 1 つ目の型の件数が、1 つ目と 2 つ目の合計に占める割合(%) | `patterns` に 2 つ |
| `mixed` | 1 本の中で 2 つの型が混ざる応答の割合(%)。少ない側の型の件数が、2 つの型の件数の合計に占める割合を出し、`limit`(%)を超える応答を数える。`limit` を省くと 10 | `patterns` に 2 つ |
| `per10k` | 型の件数の、1 万字あたりの数。字数は全文から空白を除いて数える | `patterns` |
| `per100` | 型の件数の、応答 100 本あたりの数 | `patterns` |
| `in_range` | 型の件数の合計が `min` 以上 `max` 以下の応答の割合(%) | `patterns`、`min` か `max` |

- 目安が題材を絞るときは、目安の `prompts` で絞る。型の `prompts` は目安の計算に使われない。

## 採取する

リポジトリのルートで実行する。次は例示であり、値は実際の内容に置き換える。

```bash
python3 tools/native_japanese_ab.py run \
  --before <変更前のコミット> --after <変更後のコミット> \
  --prompts .claude/skills/native-japanese-ab/assets/prompts.json \
  --patterns .claude/skills/native-japanese-ab/assets/patterns.json \
  --targets .claude/skills/native-japanese-ab/assets/targets.json \
  --out <scratchpad のディレクトリ> --models opus,sonnet --runs 3
```

- `--before` には規律を変えた最初のコミットの親を、`--after` には最後のコミットを渡す。
- 変更をまだコミットしていないときは、`--after WORKTREE` を渡す。
- プラグインを読み込まず hook も切った素の出力も並べたいときは、最初の `run` から `--bare` を付ける。表の「改修前」の左に「素」の列が出る。途中から足すときは、新しい `--out` で採り直す。
- 採取は Bash の `run_in_background` で実行し、完了の通知が届いてから結果を読む。本数は題材 × モデル × 回数 × 2(`--bare` を付けると × 3)で、所要時間は 120 本あたり 5 分ほどである。
- 新しい比較は、リポジトリの外の、空かまだ無い `--out` で始める。台帳に題材を足した後の採取も、新しい `--out` にする。`--after WORKTREE` で採った後に作業ツリーを編集したときも、新しい `--out` にする。同じ `--out` では初回の複製が使われる。
- 終了時に `timeout` か `error` が出たら、同じ引数と同じ `--out` でもう一度実行する。保存済みの応答は採り直されない。
- 2 回実行しても「採れなかった本数」が残るときは、その本数を報告に書き、残りで比べる。
- 採取は `--out` の下の空のディレクトリで動き、ユーザーの設定とこのリポジトリの CLAUDE.md を読まない。`--out` は、祖先のディレクトリに CLAUDE.md が無い場所に置く。

## 結果を読む

- `run` の最後に出る表を読む。型ごとに、一致の件数・一致を含む応答の本数・対象の応答の本数が前後で並ぶ。`sentence` の型には、当たった文が対象の文に占める割合も付く。
- 判定には「含む本数」を使う。件数は 1 本の応答に偏るので、判定に使わない。
- 含む本数が前後で違う型は、`report --patterns <型の JSON> --out <dir> --show <型の id>` で一致した行を読む。
- 誤って拾った行があるときは、型の正規表現を直して `report` を実行し直す。正規表現で除けないときは、`--show` の出力から手で数え、除いた件数を控える。
- 型にしなかった項目は、その項目の題材を 1 つ選び、`<out>/text/<before|after>/<モデル>/<題材>-<回>.txt` をモデルごとに前後の全回ぶん読む。変えた項目の文面どおりの形で書かれているかを比べる。
- 含む本数が前後とも 0 本の型は、台帳の題材にその型が当たる場面が無い。判定せず、その型の名前を報告に書く。
- `sentence` の型も、判定は含む本数の割合で行う。文に占める割合は判定に使わず、前後の値を報告に書く。
- 「文の数」は `sentence` と同じ分け方で数えた全応答の文の数である。「読点(100 字あたり)」は、`prose` の本文から空白を除いた字数に対する読点の数である。どちらも前後の値を報告に書く。
- 「Skill を起動した本数」が応答の本数より少ないときは、規律を読まずに書いた応答が混ざっている。比較からは外さず、その本数を報告に書く。

`want` を書いた型の判定は次の表で決める。割合は、誤検出を除いた後の含む本数を、前と後のそれぞれで対象の応答の本数で割って出す。差は、その割合の前後の差とする。この判定は目安であり、報告には前後の本数を添える。

| 判定 | 条件 |
| --- | --- |
| 効いた | 差が `want` の向きで、10 ポイントを超える(前後 60 本ずつなら 7 本以上)。一致した行を読み、狙った形だと確かめている |
| 逆に動いた | 差が `want` と逆の向きで、10 ポイントを超える |
| 差は確かめられなかった | 上のどちらでもない |

表の下に、目安の表が出る。列は、指標・目安・改修前・改修後・判定である。`--bare` で採ったときは「素」の列が加わる。「目安」の列の「無い」は、当たる応答が 0 本であることを求める目安である。値を省いた目安は「目安」が「未定」、判定が「目安が未定」になる。判定は改修後の値で決まり、目安までの差(余裕か不足)が付く。改修前と合否が変わった指標には「後退」か「改善」が付く。

- 今回足した目安は、変えた項目の合否として報告する。
- 以前の改修で足した目安(`since` が今回の値でない目安)は、判定に「後退」が付いたものを、今回の変更による後退として報告する。改修前から届いていない目安は、後退とせず、値を添えて報告する。
- 「測れない」と出た目安は、対象の応答が採れていないか、台帳の題材にその目安の型が当たる場面が無い。「採れなかった本数」を確かめ、目安の名前を報告に書く。
- 目安の無い型は、次の表の判定で読む。

- 今回足した型(`since` が今回の値の型)は、変えた項目が効いたかの判定に使う。1 つの項目に型が複数あるときは、型ごとの判定を並べて報告する。
- 以前の改修で足した型のうち `want` を書いたものは、今回の変更で「逆に動いた」ものが無いかの確認に使う。

## 報告する

報告には次を書く。

- 前後のコミット、モデル、題材の数、回数、採れなかった本数
- 目安の表。ツールが出した表を、列を変えずに載せる
- 以前の目安のうち、今回の変更で届かなくなったもの
- 型ごとの前後の件数の表
- 差が出た型ごとに、一致した行の実例を前後 1〜2 行ずつ
- 除いた誤検出の件数と理由
- 本文を読んで比べた項目の所見
- 今回変えた項目ごとの判定
- 以前の改修で足した型のうち、逆に動いたもの

## 台帳をコミットする

題材・型・目安を足すか直したときは、報告の後に台帳の 3 つのファイルをコミットする。
