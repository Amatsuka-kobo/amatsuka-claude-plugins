## 1. 確認済みの規律と空白

`plugins/agent-policy/references/orchestration-discipline.md` の L74–75 は、文書作成を委譲する依頼文について次を定める。

```
- 文書作成を委譲する依頼文には、事実・決定事項・制約・受け入れ基準・章立て・用語・参照先のパスだけを、箇条書き・表・キーワードの形で書く。
- 文書作成を委譲する依頼文には、対象ファイルの文体で書かれた段落や、そのまま貼り付けられる完成文を載せない。
```

L74 は依頼文に書いてよいものを列挙している。例示は明記されていないが、「事実」または「用語」として読める余地がある。L75 が禁じるのは対象ファイルの文体による段落と、そのまま貼り付けられる完成文であり、単語レベルの例示はどちらにも当たらない。

このため、説明のための例示は許可も禁止もされていない。委譲先が例示を成果物の要件として扱うのか、依頼の説明として扱うのかを判断できない。

---

## 2. 実際に起きたこと

同一セッションで、依頼文の説明用の例示が成果物へ 3 回連続して混入した。いずれも委譲先の不遵守ではなく、依頼の範囲が定まっていなかったことによる。

| 回 | 依頼文に書いた内容 | 成果物への影響 |
| --- | --- | --- |
| 1 | 「`description` が使う語だけで問を作らない」 | 対象を指すパス（`agents/`）まで問から剥がされ、正解ラベルが成立しなくなった |
| 2 | 「行為を指す語を避ける」 | 実際の依頼で最も使われる語が全問から消えた |
| 3 | 「（『レビュー』『監査』『評価』のような）」 | 3 語が本文の列挙として書かれ、閉じた集合として読める文になった |

3 回目では、依頼元が委譲先へ説明するために括弧内へ置いた語が、本文に載せる例として受け取られた。

`GOTCHA-002` には対策として、各例が本文に書くものか説明だけのものかを依頼文で明記し、説明だけの例には「本文には書かない」と添えることを記録している。また、`plugins/*/skills/*/SKILL.md`、`plugins/*/references/`、`.claude/rules/` の項目を書き換える依頼では、語の例ではなく判断の軸を渡すとしている。

## 4. 影響範囲と制約

- 主な変更対象は `plugins/agent-policy/references/orchestration-discipline.md` である。同ディレクトリは AI 向け指示書であり、編集では `prompt-smith:prompt-smith` の規律に従う必要がある。
- `plugins/agent-policy/assets/roles/ja/_common.md` と `plugins/agent-policy/assets/roles/en/_common.md` にも同種の条項がある。両言語を整合させる。`compose.test.ts` は英語側の英語純度を検査する。
- `src/agents/__test__/discipline-role-table.test.ts` は担当表と `roles.ts` の一致を検査する。規律本文だけの変更は同テストの対象ではないが、節見出しを増やすと `extractRoleBandSection` の走査範囲が変わる可能性がある。
- `agent-policy` のバージョンを上げる。`plugin.json` と `package.json` は同じ値にそろえ、現在の値は `0.19.4-dev` である。
- 規律の変更後は `pnpm run test` を実行する。
