# codiel の intent-sync で領域ファイルの古い記述を改訂・削除する

- 対象: Issue #47(親 Story #44)
- 変更するプラグイン: codiel 1.1.3 → 1.1.5(1.1.4 は並行する #46 が使い、この PR は #46 の後にマージする)
- この PR は codiel のソースと hook を変えない

## 領域ファイルが積み上がる一方なので、intent-sync に改訂と削除を加える

持続層の領域ファイル(`docs/intents/domains/<領域>.md`)には、古くなった記述を直す手順が無い。`skills/syncing-intents/references/persistent-layer.md` の取り込み手順は追加だけを定めている。

| 状況 | 今の動作 |
| --- | --- |
| 既存と同じ制約が来た | 制約を増やさず、出典の行を加える |
| 既存と矛盾する制約が来た | 上書きせずユーザーへ確認する。確認後に古い側をどう書き換えるかは定めていない |
| 今回の intent が触れない既存の記述が古くなった | 何もしない |
| `## 目的`・`## 非ゴール` | 「取り込む」とだけあり、置き換えか追記かを定めていない |

設計資料(`docs/intents/design/`)は run のたびに今の姿へ書き直されるが、領域ファイルは積み上がる一方になっている。#45 で失敗の記録が領域ファイルの通常のセクションになり、解決済みの失敗も残り続ける。

この PR で、intent-sync の取り込みの中に、今回の変更で古くなった記述の洗い出しと、承認を得た改訂・削除を加える。

範囲外は次のとおりである。

- 今回の run が触れない領域の古い記述。run の外で棚卸しするコマンドは作らない。
- 改修前の `## GOTCHAS 候補` のセクション。#45 の決定どおり読まず、書き換えない。
- metatron の ADR 候補・GOTCHAS 候補の走査。#46 で消える。

## 決定事項

| 項目 | 決定 | 決めた人 |
| --- | --- | --- |
| 矛盾を確認した後の古い側 | その場で書き換える。古い項目の `constraint`・`reason` を今の姿へ書き換え、`sourceIntent` に今回の intent を加える。`## 由来` の今回の取り込みの行に「改訂: <見出し>」「削除: <見出し>」を添える。古い文面は git の履歴で読む | 利用者 |
| `## 目的`・`## 非ゴール` の取り込み | どちらも既存の記述と今回の intent を統合した今の姿に書き直す。古い部分の改訂・削除は、他の古い記述と同じくユーザーの承認を得る | 利用者 |
| 洗い出しの対象 | `## 目的`・`## 意図的な制約`・`## 非ゴール`・`## 失敗の記録`。今回の run が触れない領域は対象にしない。run の外で棚卸しするコマンドは作らない | 利用者 |
| 承認 | 洗い出した記述ごとに改訂か削除の案を示し、承認を得てから書く。改訂・削除は追加の取り込みと同じコミットに入る | 利用者 |
| 矛盾の確認と古い記述の承認 | 1 回の `mark-ask --kind confirm` の中で、AskUserQuestion で 1 件 1 問にして聞く | 設計者 |
| 見出しを持たない記述の「改訂: <見出し>」 | `## 目的`・`## 非ゴール` はセクション名(`## 目的` など)を書く | 設計者 |
| 同じ intent の `## 由来` の行が既にあるとき | 行を増やさず、既存の行の末尾に添える | 設計者 |
| 失敗の記録の改訂の跡 | `## 由来` の添え書きだけに残す。`date` と `run` は失敗が起きた時点を表すので変えない | 設計者 |
| この intent-sync で写したばかりの失敗の記録 | 洗い出しから除く | 設計者 |
| 改修前の形のエントリ(日本語のキー、`[ADR 候補: <ID>]` の印、`関連 ADR` の行)を改訂するとき | 今の書式(英語のキー、印と `関連 ADR` の行を外す)で書き直す | 設計者 |
| 再開の判定 | `steps/intent-sync/report.md` を書く時点は変えず、領域ファイルを書き終えた後に 1 回で書く。改訂・削除・見送りの行を必ず書き、無ければ「なし」と書く | 設計者 |

## 取り込みの中で洗い出し、同じ確認で承認を得る

洗い出しを置く場所について 3 つの方式を比べ、案 1 を採る。

| 軸 | 案 1: 取り込みの中で洗い出す | 案 2: 取り込みの後に別の確認を置く | 案 3: run の外のコマンドで棚卸しする |
| --- | --- | --- | --- |
| 内容 | 取り込む内容を読んだ後、書く前に古い記述を洗い出し、矛盾の確認と同じ `mark-ask` で承認を得る | 追加を書いてから、もう一度 `mark-ask` で改訂・削除の承認を得る | 利用者が任意の時点で全領域を見直す |
| 人への確認 | 1 回 | 2 回 | run とは別 |
| コミット | 追加と同じ、ゲート通過直後のコミット | 同じ | 別のコミット |
| 判定の材料 | 今回の intent・`design.md`・run の差分 | 同じ | 材料が無い。何が古いかを決める変更が無い |
| 再開の判定 | `report.md` の有無 1 つで済む | 追加だけ済んだ状態を別に区別する必要がある | 対象外 |

案 2 は確認が 2 回になり、途中で止まったときの状態が増える。案 3 は利用者が範囲外とした。

### 「古くなった」の判定

今回の intent(`## 目的`・`## 要求`・`## 意図的な制約`・`## 非スコープ`・`## 合意済み事項`)・`design.md`・run の差分に照らして、事実でなくなった記述を古いとみなす。例を 3 つ挙げる。

- 今回の intent が、領域ファイルの `## 非ゴール` に書かれた機能を実装した。非ゴールの項目を削除する案を出す。
- 今回の差分が、失敗の記録の `cause` にある仕組みを取り除いた。`countermeasure` が要らなくなったので、エントリを削除する案を出す。
- 今回の intent が、ある制約の `reason` の前提(「外部の決済サービスが 1 つだけ」など)を変えた。制約は保ち、`reason` を今の姿へ書き換える案を出す。

今回の変更と関係の無い記述は、内容が古く見えても案にしない。

## 書式の変更

`references/intent-format.md` の「持続層」セクションに次を加える。エントリのキーとセクションの構成は変えない。

- `## 目的` と `## 非ゴール` は、取り込んだ intent を統合した今の姿を書く。intent ごとの記述を積み上げない。
- `## 意図的な制約` の改訂では、`constraint` と `reason` を今の姿に書き換え、`sourceIntent` の行に今回の intent を加える。
- `## 由来` の行に、その取り込みで改訂・削除した記述を添える。値は例であり、実際のパスと見出しに置き換える。

```markdown
## 由来
- docs/intents/2026-10-01-add-oauth-login.md(取り込み日 2026-10-01)
- docs/intents/2026-11-27-drop-legacy-session.md(取り込み日 2026-11-27)改訂: セッションの保存先、## 非ゴール / 削除: ログアウト後にフォームが消える
```

- 添え書きは「改訂: 」「削除: 」の後に見出しを読点で並べ、2 つあるときは ` / ` で区切る。見出しの無い記述はセクション名を書く。
- 古い文面は git の履歴で読み、領域ファイルには残さない。
- 設計資料の `## 由来` には添え書きを付けない。
- 最後のエントリを削除した `## 失敗の記録` は、見出しごと消す。記録の無い領域ファイルには置かない、という今の規則に合わせる。

チェックリスト(`docs/format-change-checklist.md`)の「intent 文書と intent-issue の書式」の項目のうち、`skills/syncing-intents/SKILL.md` の持続層への取り込みを同じコミットで追随させる。ほかの項目(契約凍結文書の §9・§10、`filing-followup-issues`・`preparing-design-agendas`・`capturing-intent`・gh-utility の `issue-craft`)は intent 文書と intent-issue の書式を写すもので、持続層を写さないので追随させない。

## 再開は report.md の有無と行で判定する

`steps/intent-sync/report.md` は、領域ファイルを書き終えた後に 1 回で書く。行の形は次のとおりにする。値は例である。

```markdown
取り込み: docs/intents/domains/auth.md
改訂: docs/intents/domains/auth.md / セッションの保存先
削除: docs/intents/domains/auth.md / ログアウト後にフォームが消える
見送り: docs/intents/domains/auth.md / ## 目的
書かずに終えた矛盾: なし
```

- 再開でこのファイルがあれば、取り込み・改訂・削除は済んでいる。`設計資料:` の行の判定(`orchestrating-runs` の `references/resume.md`)は変えない。
- 改訂・削除・見送りが無いときは「改訂: なし」のように書く。行が揃っていることで、改訂の判定を終えたと読める。
- 見送りは、案を示して人が書き換えないと答えた記述である。次の run では、その run の変更に照らして改めて洗い出す。

## 影響範囲

| 種別 | ファイル | 変更 |
| --- | --- | --- |
| 参照 | `references/intent-format.md` | 持続層のセクションに、今の姿の書き方・改訂の出典・`## 由来` の添え書きを加える。設計資料の `## 由来` に添え書きを付けないと書く |
| 指示 | `skills/syncing-intents/references/persistent-layer.md` | 洗い出し・承認・改訂と削除・`report.md` の行を加える。`## 目的`・`## 非ゴール` を統合に変える |
| 指示 | `skills/syncing-intents/SKILL.md` | 概要と手順 6 の矛盾の確認を、`persistent-layer.md` の承認の流れに寄せる |
| 指示 | `skills/orchestrating-runs/references/resume.md` | intent-sync の再開の判定に、改訂と削除が済んでいることを加える |
| 文書 | `docs/DESIGN.md` | 持続層の表の intent-sync の行 |
| 文書 | `README.md`、ルートの `README.md` | 古い記述の改訂を利用者に見える変化として書く |
| 配布宣言 | `.claude-plugin/plugin.json`、`package.json` | 1.1.5 |

変えないものは次のとおりである。

- `guard-write`。intent-sync の間は `docs/intents/domains/**` への書き込みを通しているので、改訂と削除にも追加の免除は要らない。
- `assets/rules/codiel.md`。持続層を intent-sync の外で書き換えないという文面は、改訂を加えても成り立つ。変えると導入済みのプロジェクトで `/codiel:init` のやり直しが要る。
- `orchestrating-runs` の `references/failure-records.md`。写し済みと判定した記録は、領域ファイルから後で消されていても作り直さない、という今の規則が削除と両立する。
- `orchestrating-runs` の `references/phase-intent-sync.md`。取り込み先の分岐は変えない。

### #46 のマージまで metatron との間に残るずれ

metatron の `scan-adr-candidates` と `shrink-adr-candidate` は、領域ファイルの `[ADR 候補: <ID>]` の印と走査時のハッシュでエントリを特定する。印の付いた改修前のエントリを intent-sync が改訂すると、印が外れて metatron の走査に出なくなる。ADR の記録を環境変数で有効にしたプロジェクトだけに起き、#46 で両コマンドが消える。

## 確かめ方

- `pnpm run lint`・`pnpm run typecheck`・`pnpm run test` を通す。ソースを変えないのでビルドは要らない。
- 変更後の `SKILL.md` と `persistent-layer.md` を通して読み、次の 2 つが途切れずにたどれることを確かめる。
  - 矛盾と古い記述の洗い出しから、承認、領域ファイルへの書き込み、ゲート通過直後のコミットまで。
  - 中断から再開したときに、`report.md` の有無で取り込みと改訂を飛ばすか決まるまで。
- `plugins/codiel/evals/` は無いので、評価ケースは加えない。
