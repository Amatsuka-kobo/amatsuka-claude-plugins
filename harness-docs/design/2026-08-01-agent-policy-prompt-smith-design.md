## 1. 目的と背景

`lean-docs`(0.6.0-dev)は AI 向け指示書の削減基準と工程を定めたが、規律を**示す**だけで、既存の指示書を**評価して正す**手段を持たない。ユーザーの要望は「AI が読む指示書の規律を示すスキル」から「規律を示し、正すスキル」への拡張である。

同時に、旧 07-31 設計書 §3-4 で設計判断としてのみ記録され、SKILL.md 本文には規律として入っていなかった「記述スタイル」の観点を本文へ昇格させる。

拡張の結果、スキルの性質が「削減」から「削減と充足の両面を扱う鍛錬」へ変わるため、名前も `lean-docs` から `prompt-smith` へ改める。

## 3. 設計判断

### 3-1. 「残す基準」は評価軸にそのまま使えない

削る基準と書き方の基準は、文書に書かれているものを見て違反を数えられる。一方で残す基準が問うのは「残すべき文が消えていないか」であり、既存文書を読むだけでは判定できない — 削られた文は文書に存在しないためである。

評価モードにおける残す基準の実際の役割は、削る候補として挙げた文にフィルタを掛けること(07-31 設計書 §3-1 の優先規定)であって、独立した採点軸ではない。

そこで採点軸としては**残す基準の裏返し**を「充足度」として置く: 判断基準・制約・優先順位が要る箇所で、それが書かれていないことを欠落として指摘し、その件数で採点する。

イ案(充足度を置かず 2 行にする)を採らなかった理由は、「短いが何も決めていない指示書」が冗長度 5・スタイル適合 5 の満点になり、評価として機能しないためである。

### 3-2. 評点は指摘から導出する

α(文単位の指摘リスト)を採った以上、指摘件数は評価時に必ず手元にある。評点をそこから導出すれば、表の数字と指摘リストが構造的にずれない。

b 案(段階ごとに定性的な判定文言を定義する)は文書の長短に左右されない利点があるが、指摘リストと独立に採点する分、両者が食い違うリスクが残る。再現性(同じ文書に同じ評点が出ること)も a のほうが高い。

閾値(0% → 5、10% 以下 → 4、25% 以下 → 3、50% 以下 → 2、50% 超 → 1)は恣意的である。ただし本文に公開されているため、読み手が数字を解釈できる。

### 3-3. 指摘は 1 箇所につき 1 軸にのみ計上する

「適宜」のような判断基準のない修飾は、削る基準(冗長度)にも充足の欠落(充足度)にも読める。同じ箇所を 2 軸で数えると評点が二重に下がるため、帰属を固定する。

振り分けは「書かれている不要な内容 → 冗長度」「書かれていない内容 → 充足度」「文の書き方 → スタイル適合」で決まる。

ただしこの 3 分類は互いに排他ではない。「適宜」のような判断基準のない修飾は、削る基準の項目に直接当たる(冗長度)と同時に、「判断基準が書かれていない」(充足度)とも読める。そこで軸の優先順位を明示する: **冗長度 → 充足度 → スタイル適合** の順で、先に当たった軸に計上する。

この順にする理由は、削る基準が具体的な語句を名指しで列挙している(「適宜」「必要に応じて」「できるだけ」)のに対し、充足度は「要る箇所で書かれていない」という判定者の推定を含むためである。具体列挙に当たるものを先に確定させたほうが、判定のばらつきが小さい。

### 3-4. 充足度の分母は近似である(既知の弱点)

冗長度とスタイル適合は「文の何割が違反か」として自然だが、充足度は「無いもの」を数えるため、分母(文の総数)との対応が厳密ではない。短い文書ほど分母が小さく、欠落 1 件が評点に与える影響が大きく出る。

それでも a(機械的な導出)の利点 — 指摘リストと数字が構造的にずれない — が上回ると判断した。この近似は仕様として受容する。

この弱点は本文には書かない。読み手の振る舞いを変えないためである(評点の出し方は本文の手順どおりで変わらず、近似であることを知っても計算は同じになる)。本設計書に記録するに留める。

充足度の欠落は、**書かれていない項目の種類ごとに 1 件**と数える。1 つの箇所で判断基準と優先順位の両方が欠けていれば 2 件である。単一の箇所につき常に 1 件と数えると、欠落の深刻さが評点に反映されない。

### 3-5. 判定は 3 値から 4 値へ拡張する

現行の工程節は各文を保持・削除・退避の 3 値で判定する。スタイル違反への対処は削除でも退避でもなく**書き換え**であるため、書き方の基準を足すと 3 値では判定先がない。工程節と評価節の双方で 4 値(保持・削除・退避・書き換え)を用いる。

### 3-6. 書き方の基準は 3 項目に絞る

P(命令形の禁止のみ)では評価モードが「命令形かどうか」しか見ないスタイル検査になり、規律を正すには弱い。R(区分の明示・表記ゆれの統一まで含む)は、EnhancedClaude5 が**会話の出力**に課した規律であり、指示書というフォーマットに移すと当たり前の話に薄まる、または見た目の問題に留まる。

Q で採った 2 項目(1 文 1 指示 / 禁止に代替行動を併記)は、どちらも別々の失敗モードに対応する:

- 1 文に複数の指示が詰まっていると、読み手が片方を落とす。
- 「〜しない」だけの禁止規定は代替行動が不定になり、読み手が停止するか勝手に補完する。

基準を増やすほど本文が伸び、毎ターン再送されるロードコストに直結する(`docs/cost-discipline.md`)。このスキル自身が削減を説く以上、項目数の抑制は自己適用の要請でもある。

### 3-7. 改名の理由

`lean-docs` が合わない点は 2 つある。

- `lean`(引き締まった)は削減という片側しか指さない。充足度を採点軸に入れたことで、このスキルは「足りない指示書」も低評価にする。
- `docs` は対象を取り違えている。扱うのは文書一般ではなく、AI に読ませて振る舞いを決める指示である。

`prompt-smith`(プロンプト鍛冶)を選んだ理由は 2 つある。

- 鍛冶は「余分を打ち落とす」と「足りない形を叩き出す」の両方を含む比喩であり、削減と充足の両面を持つ本スキルに対応する。切る・削る系の比喩(razor / trim / whetstone)は片側しか表せない。
- 鍛冶は打ち直しを含む。既存の指示書を評価して直す作業は、新品の作成より研ぎ直しに近い。

連結形 `promptsmith` ではなくハイフン区切りを採るのは、既存スキル名(`with-codex` / `claude-only` / `chat-recorder` / `issue-craft`)がすべてハイフン区切りで、連結形だけが規則から外れるためである。

比較検討した他の候補と不採用の理由:

| 候補 | 不採用の理由 |
| --- | --- |
| `prompt-discipline` | 機能的には最適だったが、比喩による訴求力を優先した |
| `prompt-hygiene` / `prompt-lint` | 正す側に偏り、新規作成時の規律が名前から消える |
| `prompt-standard` | 定める側に偏り、照らして正す動作が出ない |
| `disciplined-prompts` | 状態名のため「正す」動作が一段遠い |
| `bonsai` / `high-signal` / `whetstone` | 比喩の質は高いが、対象が名前から消える(bonsai / high-signal)、片側しか表せない(whetstone) |
| `prompt-tuning` | 機械学習の確立した技法名(ソフトプロンプト学習)と衝突する |
| `distill` | `raphael` が infection distillation で使用中 |

### 3-8. 適用範囲の 2 行は改名後も残す

名前に `prompt` が入ったことで「人間向け文書には適用しない」の一部は名前が担うが、07-31 設計書 §3-6 の判断(description はロード判断用、本文 1 行はロード後の誤適用防止用で、届くタイミングが異なる)は改名後も成立する。2 行とも維持する。

### 3-9. 自己適用の継ぎ目(意図的に残す)

本文冒頭の「人間が読み手の文書には適用しない」は、新設する書き方の基準「禁止を書くときは代わりに取る動きを併記する」に、単独では違反する形をとる。

これは評価節末尾の「対象外の文書を渡されたときは、評価せず適用範囲の外であることを伝える」が代替行動を供給する構造で解消する。冒頭の 1 行に代替行動を併記すると、同じ内容が 2 箇所に書かれ、削る基準「重複は削る」に違反するためである。

### 3-10. references/ には分割しない

追加後の本文は約 70 行で自己完結する。参照 1 段を挟む理由がない(07-31 設計書 §3-5 の判断を踏襲)。

````markdown
# AI 向け指示書の鍛錬

対象は CLAUDE.md・SKILL.md・output style・Agents 定義・メモリなど、AI が読み手となる指示書である。
README・設計書・チュートリアルなど、人間が読み手の文書には適用しない。

## 削る基準

- 指示を正当化する根拠・理由は削り、指示だけを残す。
- 出典・引用・経緯は削る。どこから来たか、いつ決まったかは振る舞いを変えない。
- 重複は削る。同じ指示の言い換え、要約と本文の重なりは一方だけを残す。
- 判断基準のない修飾(「適宜」「必要に応じて」「できるだけ」)は、基準に置き換えられるなら置き換え、
  置き換えられないなら修飾ごと削る。
- 文書自身の構成や意図の説明(「この文書は〜を説明する」)は削る。適用範囲の限定は残す基準に従う。
- 例は 1 つで伝わるなら 2 つ目以降を削る。

## 残す基準

- 読んだ後にエージェントの振る舞いが変わる文は残す。
- 誤読を防ぐ制約(順序・範囲・例外・優先順位)は残す。
- 判断基準そのものは残す。
- 同じ文が削る基準と残す基準の両方に当たるときは、残す基準を優先する。

## 書き方の基準

- 命令形(「〜すること」)ではなく、望ましい動きの言い切り(「〜する」「〜しない」)で書く。
- 1 文に 1 指示だけを書く。複数の指示を 1 文に詰めない。
- 禁止を書くときは、代わりに取る動きを併記する。「〜しない」だけで終えない。

## 工程

- 新規に書くときは、素案を書き切ってから別のパスで基準を当てて削る。生成と削減を同じパスで行わない。
- 既存の指示書を見直すときは、文単位で走査し、各文を保持・削除・退避・書き換えのいずれかに判定する。
- 削除と退避の分岐は内容の種別で決める。将来の判断や調査の入力になる種別(根拠・実測値・経緯・
  不採用案)は退避、それ以外(言い換え・修飾・文書自身の説明)は削除。迷った文は退避に倒す。

## 評価

既存の指示書を評価するときは、次の順で出力する。

1. 評点表。冗長度・充足度・スタイル適合の 3 軸と、その評点を並べる。
2. 指摘リスト。番号を振り、1 件ごとに 該当箇所 / 当たった基準 / 判定(削除・退避・書き換え) を書く。
   判定が退避・書き換えのときは置き換え後の文言も書く。判定が削除のときは書かない。
3. 適用の可否を尋ねる。「全件」と「番号指定」の双方を受け付け、承認された項目だけを直す。

指摘は 1 箇所につき 1 軸にのみ計上する。書かれている不要な内容は冗長度、書かれていない内容は
充足度、文の書き方はスタイル適合に振り分ける。1 箇所が複数の軸に読めるときは、この順で
先に当たった軸に計上する: 冗長度 → 充足度 → スタイル適合。

| 軸 | 当てる基準 |
| --- | --- |
| 冗長度 | 削る基準 |
| 充足度 | 残す基準の裏返し(判断基準・制約・優先順位が要る箇所で書かれていない) |
| スタイル適合 | 書き方の基準 |

評点は、その軸の指摘件数を文の総数で割った比率から決める。箇条書きの 1 項目と散文の 1 文を
それぞれ 1 と数える。充足度の欠落は、書かれていない項目の種類ごとに 1 と数える。

| 比率 | 評点 |
| --- | --- |
| 0% | 5 |
| 0% 超 10% 以下 | 4 |
| 10% 超 25% 以下 | 3 |
| 25% 超 50% 以下 | 2 |
| 50% 超 | 1 |

対象外の文書を渡されたときは、評価せず適用範囲の外であることを伝える。

## 退避

- 退避する内容は、references/ や設計書など毎回は読み込まれない置き場へ移し、移動先を報告する。
- 決まった置き場がないリポジトリでは、移動先を提案してから移す。
````
