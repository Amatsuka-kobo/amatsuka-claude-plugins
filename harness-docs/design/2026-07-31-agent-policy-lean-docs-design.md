## 1. 目的と背景

AI に文書を生成させると、根拠・補足・出典・引用・内容の重複が付随する。読み手が人間ならこれらは有用だが、読み手が AI である指示書(CLAUDE.md・SKILL.md・output style・Agents 定義・メモリ)では、余計な文がそのまま指示として文脈に載り、以後の出力品質を下げ、かつ全ターン再送されてトークンコストを増やす(cost-discipline の実測では、巨大スキルのロードで GPT Luna の input が見込み比約 5 倍に増幅した)。

AI は生成が得意な一方で「省く・削る」を自発的に行うことが苦手である。したがって削減は、明示的な基準と工程としてスキル化する必要がある。本設計はこれを agent-policy の新スキル `lean-docs` として定義する。

## 2. 要件(対話で確定済み)

| 論点 | 決定 |
| --- | --- |
| 適用場面 | AI 向け指示書の新規作成・改稿と、既存指示書の削減レビューの両方 |
| 判定基準 | 複数並列の基準リスト(単一の中核基準に集約しない) |
| 削った内容の扱い | 退避先(`references/`・設計書)への移動を案内する |
| 記述スタイル | EnhancedClaude5.md 型(望ましい動きの言い切り箇条書き。命令形「〜すること」を使わない) |
| スキル名 | `lean-docs`(候補 `lean-instructions` / `trim-docs` / `doc-diet` との比較で選定) |

## 3. 設計判断

### 3-1. 基準は「削る」「残す」の対で置く

削る基準だけを並べると削りすぎ(判断基準や誤読防止の制約まで削る)が起き、残す基準だけでは削減が進まない。両側を並列で置く。

基準間の衝突(同じ文が削る基準と残す基準の両方に当たる場合)は、明示の優先規定 1 行で解決する: **残す基準が削る基準に優先する**。削減の失敗(冗長が残る)は次のパスで回収できるが、保持の失敗(制約や基準の消失)は指示書の機能を壊すため、非対称に倒す。Haiku レビュー指摘 B(「根拠」と「判断基準」の境界が曖昧)への対応であり、境界の定義を精緻化するのではなく、境界上の文の落ち先を決めることで解決する。

### 3-2. 生成と削減の工程を分離する

AI が削れない直接原因は、生成と批評を同一パスで行うと批評が甘くなることにある。新規作成時は「素案を書き切る → 別パスで基準を当てて削る」の 2 工程を規定し、生成中の自己抑制(書きながら削る)には期待しない。

### 3-3. 三値判定と退避

レビュー時は文単位で走査し、各文を保持・削除・退避のいずれかに判定する。これは本リポジトリの既存運用(スキル本文は規律のみ、根拠は references と設計書へ)の一般化である。迷った文を削除でなく退避に倒すのは、削除は不可逆で退避は可逆なため、判定精度への要求を下げられるからである。

削除と退避の分岐(Haiku レビュー指摘 F「保存価値の判定基準が不在」への対応): 「保存価値」という抽象語を判定基準にせず、**内容種別の列挙**で分岐を決める。将来の判断・調査の入力になりうる種別(根拠・実測値・経緯・不採用案)は退避、それ以外(言い換え・修飾・メタ言及)は削除。本文にはこの列挙をそのまま書き、「価値」の語は使わない。

### 3-4. 記述スタイル: EnhancedClaude5 型

本文は命令形(「〜すること」)ではなく、望ましい動きの言い切り(「〜する。〜しない。」)で書く。ユーザーは既存の命令形文書群を今後この型へ移行する予定であり、本スキルはその型で書く最初のスキルになる。既存 2 方針スキル(`with-codex` / `claude-only`)の移行は本設計の対象外である。

### 3-5. 自己適用

SKILL.md 本文は自らの削る基準を満たす(根拠・出典・重複を含まない)。本設計の根拠はすべて本設計書に置き、`references/` 配下に運用時参照文書は作らない — 本文が自己完結する分量(約 25 行)であり、参照 1 段を挟む理由がない。

### 3-6. 適用範囲の限定を本文にも書く

frontmatter の description(発動条件)と本文冒頭の両方に「人間向け文書には適用しない」を書く。description はロード判断用、本文の 1 行はロード後の誤適用(README や設計書まで削る)防止用で、読み手に届くタイミングが異なるため重複とみなさない。この判断は本文の削る基準「重複は削る」の例外だが、例外規定を本文へ書き足すことはしない — 本文の重複基準は「同じ読み手に同じタイミングで届く重なり」を対象としており、description と本文は Claude Code の仕組み上、別のタイミングで読まれる(Haiku レビュー指摘 E への対応。例外ではなく基準の適用範囲外と整理する)。

また本文冒頭の対象宣言は「この文書は〜を説明する」型のメタ言及ではなく、適用範囲の限定(誤読を防ぐ制約)であり、残す基準側に該当する(Haiku レビュー指摘 A への対応)。この区別が読み手に自明でないため、本文の削る基準の文言を「文書自身の構成や意図の説明は削る。適用範囲の限定は残す基準に従う」へ精緻化する。

````markdown
# AI 向け指示書の簡潔化

対象は CLAUDE.md・SKILL.md・output style・Agents 定義・メモリなど、AI が読み手となる指示書である。
README・設計書・チュートリアルなど、人間が読み手の文書には適用しない。

## 削る基準

- 指示を正当化する根拠・理由は削り、指示だけを残す。
- 出典・引用・経緯は削る。どこから来たか、いつ決まったかは振る舞いを変えない。
- 重複は削る。同じ指示の言い換え、要約と本文の重なりは一方だけを残す。
- 判断基準のない修飾(「適宜」「必要に応じて」「できるだけ」)は、基準に置き換えられるなら置き換え、
  置き換えられないなら修飾ごと削る。
- 文書自身の構成や意図の説明(「この文書は〜を説明する」)は削る。適用範囲の限定は残す基準に従う。
- 例は 1 つで伝わるなら 2 つ目以降を削る。

## 残す基準

- 読んだ後にエージェントの振る舞いが変わる文は残す。
- 誤読を防ぐ制約(順序・範囲・例外・優先順位)は残す。
- 判断基準そのものは残す。
- 同じ文が削る基準と残す基準の両方に当たるときは、残す基準を優先する。

## 工程

- 新規に書くときは、素案を書き切ってから別のパスで基準を当てて削る。生成と削減を同じパスで行わない。
- 既存の指示書を見直すときは、文単位で走査し、各文を保持・削除・退避のいずれかに判定する。
- 削除と退避の分岐は内容の種別で決める。将来の判断や調査の入力になる種別(根拠・実測値・経緯・
  不採用案)は退避、それ以外(言い換え・修飾・文書自身の説明)は削除。迷った文は退避に倒す。

## 退避

- 退避する内容は、references/ や設計書など毎回は読み込まれない置き場へ移し、移動先を報告する。
- 決まった置き場がないリポジトリでは、移動先を提案してから移す。
````
