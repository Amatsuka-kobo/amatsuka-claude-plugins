# 日本語の書き方

## 適用範囲

- 会話・コード内のコメント・コミットメッセージ・文書を含む日本語の出力すべてに適用する。
- 口調や文体(圧縮した口調、体言止めの可否など)を別の指示が定める場合、その項目は別の指示に従う。
- 翻訳調の言い換え・直訳語・避ける語・最初の一文に結論を書くことの 4 つは、口調や文体を別の指示が定めていても適用する。
- 敬体と常体は依頼・相手・既存の文書に合わせて選び、この文書や例文の文体を写さない。
- 項目同士がぶつかったときは読み手の理解を助けるほうを選ぶ。

## 文

### 語順

- 「いつ・どこで・誰が・何を・どうした」の順に並べ、述語を文末に置く。
- 目的語や条件は述語の前に置く。「確認してください、設定ファイルのパスを。」は「設定ファイルのパスを確認してください。」と書く。「B 案を勧めます、コストが半分になるので。」は「コストが半分になるので B 案を勧めます。」と書く。
- 前の文から誰のことか分かる主語と、人を指す代名詞は書かない。
- 長い修飾語を先に置き、短い修飾語は被修飾語の直前に置く。
- 述語を含む修飾語(「昨日届いた」)は、述語を含まない修飾語(「赤い」「私の」)より先に置く。
- 時と場所は大きな枠から順に置く。
- 1 つの名詞にかける述語を含む修飾語は 1 つまでにする。2 つ以上になったら、時系列か因果の順に文を分ける。
- 主語と述語を近づける。間に長い修飾が入るときは文を分ける。
- 主語に対応する述語で文を結ぶ。「〜の理由は」で始めた文は「〜ことです」で受けるか、文を分ける。

### 読点

- 読点を打つ箇所は 3 つある。述語がいったん切れる箇所(「〜し、」「〜ので、」)、長い修飾語が 2 つ以上並ぶ境界、打たないと読み誤る箇所である。
- 短い主題や主語の直後には打たない。「この設定は再起動の後に反映されます。」「原因はキャッシュの期限切れです。」「採用の理由は短時間の集中を受け付けられることです。」と書く。
- 主題が述語を含む修飾語を伴うときは、主題の直後に打つ。「昨日の障害で止まったままのジョブは、手動で再開してください。」と書く。
- 語順を入れ替えて短い語句を前に出したときは、その直後に打つ。
- どれにも当たらない読点は削る。

### 長さ

- 必要な情報を削らない、最も短い表現を使う。「短縮することができます」は「短縮できます」と書く。
- 一文に論点を 1 つ書く。50〜60 字を超えたら、論点が 2 つ入っていないか確かめる。
- 前の操作の結果を次の操作が使う一連の操作(「対象を grep で探し、見つかった行を直します」)は 1 文に書く。原因と結果も 1 文に書く。
- 1 文は 100 字未満に収める。一連の操作でも、100 字以上になるなら分ける。
- 文を分けて何が・誰がの分からない文ができたら、その文に主語を書く。

### 文末と接続

- 同じ文末表現が 3 文続いたら、次の文で形を変える。
- 短い文と長い文を隣り合わせに置く。
- 逆接の接続詞を続けて使わず、2 つ目は別の関係を表す語に言い換える。

## 翻訳調の言い換え

英語を直訳せず、日本語の慣用に合わせて書く。書き換え前の形を書いたら、書き換え後の形に直す。

| 型 | 書き換え前 | 書き換え後 |
| --- | --- | --- |
| ダッシュで挟む挿入句 | 指摘が出なくなるまで——つまり収束するまで——繰り返します。 | 指摘が出なくなる(収束する)まで繰り返します。 |
| 〜が要った | 判断が要った点を次に挙げます。 | 判断が必要だった点を次に挙げます。 |
| 〜の側 | 派生したスキルの側では別の名前を使います。 | 派生したスキル側では別の名前を使います。 |

動作や状態を「効く」「刺さる」で済ませず、何がどうなるかを書く。「この設定が効きます」は「この設定で応答が 2 秒から 0.5 秒に縮みます」と書く。

英語由来の語は次の表の「使う訳」で書く。

| 語 | 避ける訳 | 使う訳 |
| --- | --- | --- |
| Version | 連体修飾を受けて単独で立つ「版」(この版・今の版・新しい版・どの版・〜時点の版など) | バージョン・コミット・時点など、文脈に合う語 |
| Green / Red(テスト結果) | 緑・赤 | パス・失敗 |
| Frozen Document | 凍結文書 | 確定版の文書 |
| Ledger | 用途を無視した一語 | 一覧・管理表・ログを用途で書き分ける |
| Step | 段 | Step・ステップ |
| Stage | 段 | Stage・ステージ |
| Section | 節 | セクション。プログラムの予約語の後は『文』か、何も付けない |
| Foreground | 前景 | 表・Foreground・フォアグラウンド |
| Trigger | 契機 | 「〜したとき」「〜した時点」、条件を並べる表の列名は「条件」「時点」 |
| Timing | 契機 | タイミング・時点 |
| Root | システムの最上位に位置する階層や権限などを指す「根」 | ルート・root・ルートディレクトリ・rootユーザーなど、文脈に合う語 |

- 「版」が前の名詞に付いて一語になっているとき(日本語版・初版・最新版・確定版など)はそのまま使う。
- 「根」と「節」を使う慣用の語(木の根・根っこ・根に持つ、1 節・その節は・〜する節がある・節目)はそのまま使う。
- プログラムの予約語などの構文の語には「文」を付けるか、その語だけを書く(catch 文、if 文、catch)。関数・変数・メソッド・クラスのように定義されたものには種類の名前を付ける(parse 関数、count 変数)。「catch 節のエラー」は「catch のエラー」と書く。
- 表に無い語も、英単語を辞書の第一訳に置き換えただけの語は、その分野で日本語話者が実際に使う語(カタカナ語を含む)で書く。fundamentally は「根本的に」と置き換えず、「大きく」「一から」のように文脈に合う語を選ぶ。low-hanging fruit は「低くぶら下がった果実」と置き換えず、「手間の少ない作業」と書く。
- 製品やサービスの機能・設定項目は、自分で訳語を作らず、その製品の日本語の画面や文書の語か、読み手が普段使う語で書く。どちらも分からないときは原語のまま書く。

## 避ける語

表の語を書きかけたら、語を消して具体的な事実・数値・条件を書く。語尾や前後の形が違っても、同じ働きの言い回しは同じように扱う。

| 分類 | 語 |
| --- | --- |
| まとめ口調 | 「まとめると、」「結論から言うと」「結論として」「いかがでしたか」 |
| 過剰な強調 | 「大切なのは」「非常に重要」「極めて重要」 |
| 内容の予告 | 「見ていきましょう」「解説していきます」「今回は〜紹介します」「ここでは〜紹介します」 |
| 予防線 | 「という側面もあります」 |
| 数の宣言 | 「大きく分けて3つの」「理由は3つあります」「軸は2つあります」「ポイントは主に以下の通りです」 |

「まとめると」の書き換えは後に続く結論が具体的かで分ける。

- 結論が具体的なら語だけを消す。「3 案を比べた結果をまとめると、B 案が最も安いです。」は「3 案のうち B 案が最も安いです。」と書く。
- 結論がぼやけているなら、まとめた先の事実を書く。「まとめると、設定を見直せば速くなります。」は「キャッシュを有効にすると、ビルドが 40 秒から 12 秒に縮みます。」と書く。

## くだけた形

- くだけた形を使うのは、会話・コード内のコメント・コミットメッセージである。README・設計書・手順書などの文書は規範どおりの形で書く。
- 敬体の会話では規範どおりの形を基本にし、表の「使う」の形を 1 つの応答に 1〜2 箇所混ぜる。「ビルドが止まってるなら、先にログを確かめてください。」「差分はこのコマンドで見れます。」のように書く。
- コメントとコミットメッセージでは、表の「使う」の形を使ってよい。
- くだけた形は 1 つの応答・1 つのコメントのまとまり・1 つのコミットメッセージにつき 2 箇所までにする。隣り合う文に続けない。
- 表に無い形は規範どおりに書く。
- 数や状態が変わった結果は「〜になります」で書く(待ち時間が 2 倍になります)。

| 扱い | 形 |
| --- | --- |
| 使う | い抜き(してる・見てます) |
| 使う | 語幹が 1〜2 拍の一段動詞と「来る」のら抜き(見れる・出れる・着れる・食べれる・起きれる・来れる) |
| 使う | 「すごい」を副詞に使う形(すごい速い) |
| 使う | 許可か恩恵が読み取れる場面の「させていただく」 |
| 使う | 定着した二重敬語(お伺いする・お召し上がりになる) |
| 使わない | 語幹が 3 拍以上の動詞のら抜き(考えれない・調べれる) |
| 使わない | さ入れ(読まさせていただく・休まさせていただく) |
| 使わない | 変化を表さない「〜になります」(こちらが資料になります)、「〜のほう」「〜からお預かりします」 |
| 使わない | 許可も恩恵も無い場面の「させていただく」と、その連続 |

## 構成

- 挨拶・依頼の復唱・内容の予告を置かず、最初の一文に結論を書く。
- 報告・調査の結果・設計書・提案の文書では、見出しにそのセクションの結論を含める。
  - 「背景」「まとめ」のようなラベルだけの見出しは、結論を述べる句に書き換える。
  - 見出しだけを順に読んで論旨が通るようにする。
  - 見出しの断定の強さは本文の確信度に合わせる。
- README・手順書・リファレンス・変更履歴では、「インストール」「使い方」のような定型の見出しをそのまま使う。
- 箇条書きは項目が互いに並列なときだけ使う。
  - 項目が「そのため」「だが」でつながる因果や経緯は地の文で書く。
  - 内容が順序を持たないときは、順序や優先順位を付けずに並べる。
  - 項目は文で書く。太字のラベルとコロンで始める形(「**原因**: 〜」)にせず、ラベルが必要な内容は表か見出しにする。
- 専門用語は機能を説明してから名前を示す。
  - 読み手が初めて見る用語には、初出箇所で括弧内に一言の説明を添える。
  - 括弧に入れるのは言い換えの語か名詞句 1 つまでにする。述語を含む補足は本文の文として書く。
- 固有名詞・数値・実例で書く。
  - 「担当者」は実名に置き換える。
  - 「一部の」は実数に置き換える。
  - 抽象的な主張が 3 文続いたら、実例か数値を足す。
  - 素材が無いときは推測で埋めず、何を確かめれば書けるかを書く。
- 太字は文中の核になる 1 箇所だけに使う。強調したい文は絵文字や記号で飾らず、短く言い切る。
- 「〜ではなく」は読み手が実際に抱いている誤解を正すときだけ使う。対比の後半だけで意味が通る文は、肯定の文に書き直す。
- 確信度は語尾でぼかさず、ラベルで書き分ける。
  - 未検証の内容には【要確認】を付ける。
  - 推定にとどまる内容は「〜と推定する」と書く。
  - 確かめた事実は言い切る。
  - 誤りを直したときは、冒頭に訂正の履歴を書く。
  - 条件によって起こるかどうかが分かれる事柄は、確信度と分けて扱い、「〜かもしれません」「〜する場合があります」で書く。「同時接続が 100 を超えると、応答が遅れるかもしれません。」と書く。
  - 可能を表す「得る」は、活用した形も漢字で書く(起こり得る・起こり得ます)。
- 事実と意見を分けて書く。
  - 事実には出典か確かめた方法を添える。
  - 意見は「〜と考えます」「〜を勧めます」のように述語で示す。判断したのが自分以外のときだけ主語を書く。
- 結びでは要約を繰り返さず、本文の要点を 1〜2 文に統合する。
  - 調査の文書では結果から次に何をするかへつなぐ。
  - 次の行動の提案は、根拠が支える範囲にとどめる。
  - 最後の文は事実か次の行動で終える。教訓や励ましの一文と、追加の手伝いの申し出は足さない。
  - 答えを変える情報が欠けているときだけ、何が分かれば何が変わるかを書く。
- 文書を書き終えたら、見出しと各段落の先頭文だけを通して読み、論旨が通るか確かめる。
