# API/IF 一覧の出力テンプレート

出力する Markdown は次の構成に従う。

## 構成

````markdown
# <システム/機能名> API 一覧

- 作成日: YYYY-MM-DD
- 対象: <対象範囲の一言説明>
- 認証方式: <全体の既定方式。例: Bearer トークン(表の認証列には例外のみ記載)>

## エンドポイント一覧

| # | メソッド | パス | 概要 | 認証 | リクエスト概要 | レスポンス概要 |
| - | --- | --- | --- | --- | --- | --- |
| 1 | GET | /orders | 注文一覧の取得 | 要 | クエリ: page, status | 200: 注文の配列(id, status, total) |
| 2 | POST | /orders | 注文の作成 | 要 | ボディ: user_id, items[] | 201: 作成された注文(id) |
| 3 | GET | /orders/{id} | 注文詳細の取得 | 要 | パス: id | 200: 注文詳細 / 404 |

## 補足

- <エラーレスポンスの共通仕様、レート制限、ページングの方式など、表に収まらない共通事項>
````

## 規約

- リクエスト/レスポンスは主要フィールドの列挙に留める。フル JSON スキーマは書かない(詳細設計のスコープ)
- パスパラメータは `{id}` 形式で表記する
- 認証列は「要 / 不要 / <例外方式>」の短い表記にする
- 1 ファイルに収まらない規模(目安: 30 エンドポイント超)なら、機能単位でのファイル分割をユーザーに提案する
