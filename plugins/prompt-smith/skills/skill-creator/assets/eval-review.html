Eval Set Review: __SKILL_NAME_PLACEHOLDER__

Current description: __SKILL_DESCRIPTION_PLACEHOLDER__

Eval Set Creation Criteria

  1. eval セットは 20 問にする。
  2. should_trigger: true は 8〜10 問にする。
  3. should_trigger: false は 8〜10 問にする。
  4. クエリは具体的で現実的にする。
  5. クエリにはファイルパス・仕事や状況の背景・列名と値・会社名・URL・短い前置きのような手がかりを混ぜる。
  6. 小文字・略語・タイプミス・口語を混ぜる。
  7. クエリの長さを混ぜる。
  8. 明快な例ではなく境界事例を選ぶ。
  9. 1 手で終わる作業を求める問は作らない。多段の作業や専門的な判断を要する問を作る。問の短さで作業量を判断しない。
  10. should_trigger: false は語や概念を共有する near-miss で埋める。
  11. 明らかに無関係な問は入れない。別の対応が要る問を入れる。
  12. should_trigger: true には別のスキルが担当しそうに見えて、実はこのスキルが担当する依頼を入れる。
  13. eval セットを作る前に、そのスキルの主な起動経路をユーザーに聞く。起動経路は「ユーザーが目的を明示して依頼する」と「AI が提案し、ユーザーがそれに答える」の 2 通りがある。
  14. 主な起動経路が AI の提案に対するユーザーの回答であるときは、その回答の形を should_trigger: true の問に入れる。
  15. 提案への回答を should_trigger: true の問に入れるときは、AI の発言をなぞらない。Input: 「AI: リリースノートの下書きを作りましょうか。」 Output: 「リリースノートの下書きを作ってください。」
  16. 短い問を作るときは、対象を指す語を 1 つ残す。測定は会話履歴を持たない単発実行であり、「お願いします」だけの返答ではどのスキルへの依頼かを判定できない。Input: 「このスキルを直してください。」 Output: 「スキルを直してください。」
  17. description が使う語だけで should_trigger: true の問を作らない。同じ行為を指す別の語を混ぜる。
