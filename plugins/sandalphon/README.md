# Sandalphon

ユーザーの「やりたいこと」を聞き取り、ソフトウェアの現状(ASIS)と突き合わせて intent 文書に固定し、
GitHub issue という形で実行系へ届けるオーケストレーターです。

## 名前の由来

人間の祈り・願いを束ねて天へ届ける天使 Sandalphon に由来します。ユーザーの願い(TOBE)を束ね、
実行系(Codiel)へ届けるという役割そのものを表します。

## 何をするか

Codiel は「GitHub Issue #N がある」ところから始まります。しかし実際の開発で最も欠落しやすく、
手戻りコストが最も高いのは、**その Issue が生まれる前の区間**です。

- 断片的な要望が ASIS と接続されないまま Issue になる。
- ASIS を知らずに書かれた Issue は、実現不能な要求や既に満たされている要求を含む。
- 「なぜその方針にしたか」の合意が Issue に残らず、設計フェーズで同じ分岐がもう一度議論される。
- GitHub リポジトリを持たない小さな作業では、そもそも Issue 起点のツールが届かない。

Sandalphon はこの上流区間を担当します。成果物は `docs/intents/YYYY-MM-DD-<slug>.md` に保存される
intent 文書(ASIS / TOBE / 受け入れ基準 / 実装方針 / 合意済み事項 / 非スコープ / 未確定事項)であり、
issue はその派生物です。intent 文書はコミットせず作業ツリーに残します。

## 動作要件

スクリプトは Node.js で動作します。`node` が PATH 上にあり、バージョンが 22 以上である必要があります。

Claude Code 本体はネイティブバイナリで配布され Node.js を同梱しないため、未導入の場合は別途インストールしてください。

| やりたいこと | 必要なもの |
| --- | --- |
| intent 文書の作成 | なし(git リポジトリでなくても動きます。保存先の絶対パスを提示して確認します) |
| issue の起票 | GitHub CLI(`gh`)のインストールと認証、`origin` に `github.com` のリモート |
| Codiel への委譲 | 下記のとおり Codiel 側の条件を満たしていること |

**Codiel 委譲の前提**: `/codiel:run` は **Raguel MCP への接続**と、**`/codiel:init` 済みのハーネス**
(`.codiel/` ディレクトリと、ドメイン定義が読める `ARCHITECTURE`)を必要とします。これは Sandalphon 単体では
満たせない外部条件です。ハーネスが未初期化の場合、Sandalphon は委譲を選択肢に出さず、初期化コマンドを 1 行案内します。
Raguel MCP の接続が確認できない場合は、選択肢は出したうえで注記を添えます(引き渡し先は新しいセッションであり、
そちらで接続済みの可能性があるためです)。`/codiel:run` は issue 番号を引数に取るため、**委譲を選ぶ場合は起票が必須**です。

## コマンド

### `/sandalphon:run [やりたいこと]`

intent の聞き取りから実行系への引き渡しまでを進めます。

- 引数は省略できます。省略した場合は「何をしたいか」から聞きます。
- 引数に既存の intent 文書のパスを渡すと、その内容を読み込んだ状態から再開します。
  中断した作業の再開はこの形で行います(Sandalphon は状態ファイルを持ちません)。

## フェーズと承認ゲート

```
Phase 1  capturing-intent    TOBE のヒアリング → ASIS 探索 → 分岐の合意 → intent 文書のドラフト
                             ★ ゲート 1: intent 文書の承認 → docs/intents/ へ保存
Phase 2  bridging-execution  起票可否の判定 → 実行経路の質問(1 回) → issue 起票 → 引き渡し
Phase 3  executing-intent    テスト仕様(基盤が無ければ手動検証手順)の作成
                             ★ ゲート 2: ケース一覧・実行コマンド・作業ブランチの承認
                             → TDD 実装 → ドキュメント更新 → 報告
```

承認ゲートは 2 点だけです。「取り消しコストが跳ね上がる直前」にのみ置いています。
ゲート 2 を過ぎた後は自律実行しますが、secrets への接触・DB マイグレーション・破壊的操作・
依存パッケージの追加は、承認後であっても都度確認します。

**issue の起票は外部公開行為であり、ゲートとは別に必ず承認を取ります。** 本文を全文提示し、
明示的な承認を得るまで起票しません。この承認は環境がどれだけ縮退しても省略されません。

## 他プラグインとの関係

| プラグイン | 担当区間 |
| --- | --- |
| **sandalphon** | 願い → intent 確定 → issue 起票 → 実行系への引き渡し(または軽量実行) |
| codiel | Issue #N → 設計 → 実装 → テスト → PR → レビュー |
| gh-utility | Issue の起票・分割・棚卸しという単機能ユーティリティ |
| metatron | ARCHITECTURE / GOTCHAS の生成と維持 |

- Sandalphon は Codiel の**前段**であり、置き換えではありません。Codiel へは
  `/codiel:run <番号>` を提示する形で引き渡し、Sandalphon のセッションはそこで終えます
  (引き渡しは新しいセッションで実行することを推奨します。文脈は issue に外部化済みです)。
- 起票は gh-utility の `issue-craft` を**持ち込みモード**で呼びます。本文は Sandalphon が組み立て、
  `issue-craft` はそれを改変せずに起票します。
- metatron が管理する ARCHITECTURE / GOTCHAS は ASIS 探索の材料として使いますが、必須ではありません。

## 環境が揃っていない場合

使えない経路は選択肢に出さず、**理由を 1 行報告して静かに畳みます**。エラーで止まりません。

| 状況 | 畳まれるもの | 残るもの |
| --- | --- | --- |
| git リポジトリでない / GitHub の `origin` が無い | issue 起票、Codiel 委譲 | intent 文書、自前実行(作業ブランチは作りません) |
| `gh` が未導入 / 未認証 | issue 起票、Codiel 委譲 | intent 文書、自前実行 |
| gh-utility が無い | `issue-craft` への委譲 | 起票そのもの(Sandalphon が `gh issue create` を直接実行。全文提示と承認は同じく行います) |
| Codiel が無い | Codiel 委譲(言及もしません) | intent 文書、issue 起票、自前実行 |
| Codiel はあるがハーネス未初期化 | Codiel 委譲 | 同上(初期化コマンドを 1 行案内します) |
| テスト基盤が無い | 自動テスト | 手動検証手順による Phase 3(検証強度が下がる旨を報告に明記します) |
| metatron が無い | なし | すべて(ARCHITECTURE / GOTCHAS は存在すれば読みます) |

## 文書の置き場

- `README.md`(このファイル): 利用者が読まなければこのプラグインを使えない情報
- `docs/rationale.md`: 設計根拠(なぜその設計なのか、不採用にした案は何か)
- `references/`: 3 つのスキルが実行時に共有する規律と書式の正本(AI が読む)
