# intent 文書と intent-issue の書式

この仕様を変更したら、同じコミットで次も更新する。

- [ ] 契約凍結文書 `harness-docs/design/2026-08-16-file-contract-freeze.md` の §8・§9
- [ ] codiel: `skills/analyzing-issues/SKILL.md` の `## intent issue の写像`
- [ ] codiel: `skills/preparing-design-agendas/SKILL.md` の `## 合意済み事項の継承`
- [ ] gh-utility: `skills/issue-craft/SKILL.md` の `## 持ち込みモード`

写しにはマーカーと見出し名の認識に要る最小限だけを持たせる。書き方の規律・理由・例はこの文書にだけ置く。

## 保存先と命名

- `docs/intents/YYYY-MM-DD-<slug>.md` に保存する。基準は対象リポジトリのルートで固定し、設定による変更を持たない。
- `<slug>` は TOBE を表す英小文字ケバブケースにする。日本語プロジェクトでも slug は英字にする。
- 同日に同じ slug が既にあるときは `-2` を付す。既存ファイルを上書きしない。
- `docs/intents/` が無ければ作る。作成はゲート 1 通過後の保存時に行い、ゲート前にディレクトリを作らない。
- git リポジトリでないときは、カレントディレクトリ基準の `docs/intents/` を提案する。保存前に絶対パスを提示してユーザーの確認を取る。

## frontmatter

| キー | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `intent` | string | 必須 | フォーマットバージョン。v1 では `v1` 固定 |
| `slug` | string | 必須 | ファイル名の `<slug>` と同じ英小文字ケバブケース |
| `created` | string | 必須 | 作成日 `YYYY-MM-DD` |
| `status` | string | 必須 | `approved` / `issued` / `done` のいずれか |
| `issue` | string | 必須(値は空でよい) | issue の番号または URL。`issued` になるまでは空 |

- 5 キー平坦とする。ネスト・複数行文字列・リストは解釈しない。
- YAML パーサを使わない。`---` で挟まれた先頭ブロックのトップレベル行だけを `キー: 値` として行単位で抽出する。
- 値は前後の空白を除いた文字列として扱う。空値は空文字列とする。引用符は剥がさない。
- 未知キーは無視し、欠けているキーは未設定として扱う。どちらも例外を投げない。
- frontmatter を issue 本文へ転記しない。
- `status` と `issue` の更新は各フェーズのスキルが Edit ツールで行う。`check-intent-env` は intent 文書を読み取るだけで、一切書き込まない。

## セクション構成

```markdown
---
intent: v1
slug: add-oauth-login
created: 2026-08-16
status: approved
issue:
---

# intent: <一行で表した TOBE>

## ASIS

- <intent に関係する範囲の現状。関連ファイル・モジュールを添える>

## TOBE

- <達成したいこと 1(要求 1 件 = 1 行)>
- <達成したいこと 2>

## 受け入れ基準

- <機械的に YES/NO を判定できる基準 1>

## 実装方針

- <どの層をどう変えるか。影響範囲。想定手順>

## 合意済み事項

- <論点>: <採用した選択肢>(理由: <...>)

## 非スコープ

- <今回扱わない範囲>

## 未確定事項

- <推測で埋めずに残した疑問。無ければ「なし」>
```

- 見出しは `##` レベルとする。名称と順序を intent-issue と完全に一致させる。
- `##` の 7 セクションをすべて置く。内容が無いセクションにも見出しを残す。
- `## ASIS` はプロジェクト全体の現状を書かず、intent に関係する範囲に絞る。
- `## 受け入れ基準` には機械的に YES/NO を判定できる基準だけを書く。判定できない項目は `## 未確定事項` へ回す。
- `## 実装方針` には方針を書く。設計書を書かない。
- `## 合意済み事項` にはヒアリングで決着した分岐を書く。
- `## 未確定事項` を推測で埋めない。

## status のライフサイクル

| status | 意味 | 遷移させる主体 |
| --- | --- | --- |
| `draft` | ドラフト提示中。ファイルとしては未保存 | (ファイルに現れない概念上の状態) |
| `approved` | ゲート 1 を通過し保存された | sandalphon `capturing-intent` |
| `issued` | issue 化された(`issue:` に番号または URL が入る) | sandalphon `bridging-execution` |
| `done` | 自前実行が完了した | sandalphon `executing-intent` |

- 値域は `approved` / `issued` / `done` とする。`draft` はファイルに現れない。
- **status の遷移をスクリプトで検証しない。契約が定めるのは値域だけである。** `check-intent-env` は読み取った値をそのまま返す。
- 後戻り(`issued` → `approved` 等)を禁止しない。既存 intent 文書を `/sandalphon:run` に渡してやり直す経路で status が巻き戻るためである。遷移が妥当かどうかはスキルが文脈と併せて判断する。
- Codiel へ委譲したときは `issued` のまま残す。以降の状態は issue と PR が持ち、sandalphon は追跡しない。

## intent-issue の本文

```markdown
<!-- intent:v1 -->

## ASIS
## TOBE
## 受け入れ基準
## 実装方針
## 合意済み事項
## 非スコープ
## 未確定事項

<!-- intent-source: docs/intents/2026-08-16-add-oauth-login.md -->
```

- マーカー `<!-- intent:v1 -->` を含める。書き出す位置は 1 行目にする。
- **検知は本文全体を対象にし、位置の制約を課さない。** Issue テンプレートのヘッダが前置されてマーカーが本文の中ほどに来ることがあり、「先頭 N 行以内」のような位置条件は intent issue を取りこぼす。
- **フェンスの中に例示として現れたマーカーも intent issue として検知する。** 取りこぼしの損失(写像が効かず精度が落ちる)は誤検知の損失より確実に大きい。ARCHITECTURE 側のフェンス除外と規律が異なるのは意図した非対称であり、揃えない。
- 検知はマーカー文字列の完全一致で行う。`<!--intent:v1-->` のように空白が異なる形は検知しない。書き出し側は必ず `<!-- intent:v1 -->` の形で出す。
- 見出しは `##` レベルとする。名称と順序を intent 文書と完全に一致させる。
- 転記は frontmatter を落として見出し以下をそのまま貼る。要約・整形・見出しの並べ替えをしない。
- 末尾に `<!-- intent-source: <リポジトリルートからの相対パス> -->` を置く。
- タイトルは intent 文書の `# intent: <...>` の内容から `intent:` の接頭辞を外したものにする。

## バージョニング

- `v1` はフォーマットのバージョンである。見出しの追加・削除・改名を行うときは `v2` に上げる。
- 知らないバージョンを見たときは機械的写像をしない。本文全文を原文として扱う既定動作に落とす。

## issue.md への写像表(codiel `analyzing-issues` 用)

| issue 本文のセクション | issue.md の写像先 | 扱い |
| --- | --- | --- |
| `## TOBE` | `## 要件` | 1 行 1 要求のまま**そのまま転記** |
| `## 受け入れ基準` | `## 受け入れ基準` | そのまま転記。機械的に YES/NO を判定できない行だけ `## 不明点` へ格下げ |
| `## 非スコープ` | `## 非スコープ` | そのまま転記 |
| `## 未確定事項` | `## 不明点` | そのまま転記。「なし」だけなら何も写さない |
| `## ASIS` | (写像先なし) | `## 原文` に含まれるため十分 |
| `## 実装方針` | (写像先なし) | **`## スコープ` へ要約して落とさない**。`## 原文` に残す |
| `## 合意済み事項` | 条件付き | スコープの合意が含まれる場合のみ、その行を `## スコープ` / `## 非スコープ` へ**そのまま転記** |

- **要約を伴う抽出をしない。** 写像はすべて転記で行う。要約は原文にない語を持ち込む。
- `## スコープ` が結果として薄くなることは許容する。スコープの境界は通常の手順で引く。
