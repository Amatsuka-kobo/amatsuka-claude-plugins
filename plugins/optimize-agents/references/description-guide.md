# description の書き方

SKILL.md・コマンド定義(`commands/*.md`)・Agents 定義の frontmatter にある description の基準である。
`prompt-smith` の削る基準・書き方の基準は、description には当てない。

## 書く内容

- 何をするスキルかと、どんなときに使うかの両方を書く。
- 発動する場面を、ユーザーが実際に使う言い回しで例示する。「〜しといて」のような口語・省略形も含める。
- 「必ず使用する」と書く。「〜に役立つ」「〜のときに参照できる」のような控えめな表現にしない。
- 三人称で書く。「〜をお手伝いします」「あなたは〜できます」のような一人称・二人称にしない。
- 実装の仕組みではなく、ユーザーが何を達成しようとしているかを書く。
- 担当が近いスキルがあるときは、そちらが担当する場面を書いて境界を示す。
- 隣接するスキルと並べたとき、どちらを選ぶかが 1 読で決まる語を選ぶ。
- 発動してほしくない場面があるときは、除外する記述と、発動する場面の例示を同じ改稿で入れる。除外だけを足さない。
- 自律的に発動させないスキルは、明示的な依頼があったときだけ使う旨を末尾に置く。
- 「いつ使うか」は description にだけ書く。本文へ分散させない。

## 配布するスキルの例示

配布するスキルでは、例示に開発リポジトリのファイル名・プラグイン名・エージェント名を書かない。

例示する対象は、置き場所と種別で示す。`references/` 配下の文書・`commands/` 配下のコマンド定義・SKILL.md のように、どのリポジトリにもある形で書く。

固有名を書いてよいのは、そのリポジトリでしか使わないスキルに限る。

## 長さの上限

- SKILL.md とコマンド定義では、`description` と `when_to_use` の合計を 1536 字以内にする。
- 上限に触れたときは削らず、`when_to_use` へ分ける。それでも超えるときだけ例示を統合する。

## 削らない

- 同じ意図の言い換えは残す。
- 例示は 2 つ目以降も残す。
- 長さを理由に削らない。

## 対象を広げるとき

- 既に書いてある対象と別の種類の対象を足すときは、対象の列挙にだけ足す。依頼文の例示は同じ改稿で足さない。
- §削らない の「例示は残す」は、同じ対象を指す言い換えに当てる。別種の対象を指す例示には当てない。
