# description の書き方

SKILL.md・Agents 定義の frontmatter にある description の基準である。
`prompt-smith` の削る基準・書き方の基準は、description には当てない。

## 書く内容

- 何をするスキルかと、どんなときに使うかの両方を書く。
- 発動する場面を、ユーザーが実際に使う言い回しで例示する。「〜しといて」のような口語・省略形も含める。
- 「必ず使用する」と書く。「〜に役立つ」「〜のときに参照できる」のような控えめな表現にしない。
- 担当が近いスキルがあるときは、そちらが担当する場面を書いて境界を示す。
- 発動してほしくない場面があるときは、除外する記述と、発動する場面の例示を同じ改稿で入れる。除外だけを足さない。
- 自律的に発動させないスキルは、明示的な依頼があったときだけ使う旨を末尾に置く。
- 「いつ使うか」は description にだけ書く。本文へ分散させない。

## 削らない

- 同じ意図の言い換えは残す。一致する依頼文の幅が広がる。
- 例示は 2 つ目以降も残す。description の例示は理解のためではなく一致のためにある。
- 長さを理由に削らない。description の長さは発火の判断にしか影響しない。

## 直したときの確かめ方

description を直したら、次の 3 種の依頼で発火を確かめる。1 種だけで判断しない。

| 種別 | 依頼の例 | 期待 |
| --- | --- | --- |
| 文脈のある依頼 | 固有名・パス・背景を含む長い依頼 | 発火する |
| 短い依頼 | 実運用に多い一言の依頼 | 発火する |
| 近接した依頼 | 担当が近い別スキルが正解の依頼 | 発火しない |

除外の記述を足すと 3 種目は改善するが 1・2 種目が落ちうる。例示を足すとその逆になる。両方を同じ改稿で行い、3 種すべてを測り直す。

測定の手順は `optimize-agents:skill-eval` が持つ。

## Agents 定義での違い

ここまでの基準は skill の発火精度を 168 問で測って導いたものである。**Agents 定義については同じ測定を行っていない。**

以下は Anthropic 公式ドキュメントの記述に基づく準用であり、このリポジトリでの実測はない。

- skill 向けの基準を準用する。方向は一致する(公式も発火を強める句を推奨している)
- `<example>` ブロックは使わない。公式ドキュメントに記述がない
- Agent はオーケストレーターが担当表を見て選ぶ経路が主である。作業種別と、隣接する Agent との境界を書く

Agent 定義を作るときは `optimize-agents:agent-creator` を使う。
