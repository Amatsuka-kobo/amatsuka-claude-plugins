# Agent 定義のセットアップ

生成するのは、プロジェクトの `.claude/agents/` に置く Markdown の Agent 定義だけである。MCP サーバーの設定そのものと秘密値は管理しない。

定義の `better-agentics-role` は、その定義が委譲先の候補になる役割を表す。定義は 1 つにつき 1 役割だけを持つ。

## 書き込みと対話の規律

- `.claude/agents/` のファイルを `Write` / `Edit` で直接編集しない。点検・差分確認・生成は、対象プロジェクトのルートから次の CLI で行い、`--dir "$PWD"` を渡す。

  ```bash
  node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" ... --dir "$PWD"
  ```

- `Edit` を使ってよいのは、CLI が作った `.claude/better-agentics/roles/<lang>/` 配下の翻訳断片だけである。
- CLI の応答の `ok` が `false` なら、`error` を報告してその処理を止める。
- 例外は次の 2 つだけである。どちらも `ok: false` を返したら、定義名と `error` を控えてウィザードを続け、ステップ 8 で報告する。
  - ステップ 2 の `--prune-tools` / `--rewrite-roles`
  - ステップ 6 と 7 の 1 定義ごとの `--write`(失敗した定義を飛ばし、残りの定義を続ける)
- `AskUserQuestion` は 1 回ずつ呼び、前の回答を受け取ってから次を呼ぶ。1 つのメッセージで複数回呼ばない。
- `AskUserQuestion` は 1 問につき選択肢を 2〜4 個しか受け付けない。すべての選択で次を守る。

  | 候補数 | 扱い |
  | --- | --- |
  | 0 件 | 質問せず、候補がないことを報告して次へ進む。 |
  | 1 件 | `AskUserQuestion` を使わず、「これを使うか」を通常の確認文で尋ねる。 |
  | 2〜4 件 | 1 回の `AskUserQuestion` で尋ねる。 |
  | 5 件以上(複数選択) | 配列の並び順のままページに分け、各ページを候補 1〜3 件にする(5 件なら 3 件と 2 件)。各ページの末尾に「このページでは選ばない」を置く。各質問に `(1/2)` のような通し番号を付ける。 |
  | 5 件以上(単一選択) | ページに分けない。各ステップに書いた 2 問の手順で絞る。 |

単一選択の `AskUserQuestion` は 1 ページ目で選んだ時点で終わり、次のページへ進めないため、ページ分けは複数選択にだけ当てる。

- 表の候補数は、ページに分ける前の数で引く。分けた後のページは 1 件の行に当てず、どのページも `AskUserQuestion` で出す。
- ページに分けたときは、すべてのページを順に出す。Other で残りを選ばせない。
- 質問文で次のページを案内するときは、実際の分け方(ページ数と各ページの件数)と一致させる。

- ツール呼び出しより前に書いた本文は、利用者に表示されないことがある。質問の前提になる表は `AskUserQuestion` の中に入れる。
  - 短い表は `question` 本文に、長い表は各選択肢の `preview` に、Markdown の表で入れる。`preview` に入れるときは、全選択肢に同じ表を入れる。
  - 質問文は、質問の中だけで読めるように書き、「上の表」「上の案」のように質問の外の本文を指さない。
  - 質問をせずに表だけ示す報告は、ターン末尾の本文に置く。

- 選択の結果が空になりうるときは、「付与しない」「作らない」「再生成しない」に相当する選択肢を明示して置く。`AskUserQuestion` は空の選択を受け付けないため、この選択肢が無いと、何も選ばないという意思を利用者が表せない。
  - 推奨や既定の候補を先頭に置く。
  - 空の選択に当たる選択肢は、候補の最後に必ず置く。
  - 候補数には、空の選択肢も含めて数える。
  - 複数選択の前に単一選択で空の選択を聞けるときは、複数選択に空の選択肢を置かない。
- 複数選択をページに分けるときは、全体を空にする選択肢を置かず、各ページの末尾に「このページでは選ばない」を置く。
  - 「このページでは選ばない」はそのページだけに効き、前のページの選択を取り消さない。質問文にもそう書く。
  - すべてのページで「このページでは選ばない」が選ばれたら、その質問の回答は空とする。空の回答の扱いは各ステップに従う。

## ステップ 1: 言語の判定

会話でユーザーが使っている言語から `lang` を決める。複数の言語が混ざるときは、直近のユーザー発話の言語を採る。以降のコマンドの `--lang` にはこの値を渡す。

## ステップ 2: 既存定義の点検

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --list-coverage --lang <lang> --dir "$PWD"
```

応答の `definitions` は `better-agentics-role` を持つ全定義、`duplicates` は同じ役割を 2 件以上の定義が持つ役割、`unknownRoles` は役割表に無い role-id を持つ定義である。どれも空なら、ステップ 3 へ進む。

1. 許可されていないツール。`disallowedTools` が空でない定義を `file` の昇順に並べ、ツールごとに 1 問、「削除する(推奨)」「残す」の 2 択で聞く。
   - 各質問には「定義 / 許可されていないツール」の表を入れる。1 回の `AskUserQuestion` には 4 問まで入る。
   - `toolsFormat` が `csv` でない定義には質問を出さない。`disallowedTools` が `*`(tools 行が無く、全ツールを継承する)の定義も同じである。どちらもステップ 8 で、手で直すツールとして報告する。
   - 削除を選んだツールは、定義ごとにまとめて外す。

     ```bash
     node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --prune-tools --name <file> --tools <tool,...> --dir "$PWD"
     ```

2. 同じ役割の重複。`duplicates` の役割ごとに、残す定義を単一選択で聞く。選択肢は `files` の定義とし、質問文に役割名を書く。残さない定義は、マーカー行を消す。

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --rewrite-roles --name <file> --roles "" --dir "$PWD"
   ```

   マーカー行を消した定義は委譲先の候補から外れる。ファイルを消すかは利用者に委ね、ステップ 8 でパスを示す。

3. 役割表に無い role-id。`unknownRoles` は質問せず、ステップ 8 で報告する。

操作を 1 つでも実行したときは、`--list-coverage` を取り直してからステップ 3 へ進む。

## ステップ 3: 被覆の確認

すべての役割の `coveredBy` が空なら、何も聞かずに全役割を新規生成の対象にしてステップ 4 へ進む。

1 つでも `coveredBy` が空でないときは、「役割 / 推奨モデル / 既存定義」の表を入れた質問で次を聞く。

- `uncovered` が空でないときは、「未カバーの役割だけ作る(推奨)」「すべての役割を確認し直す」「中止する」の 3 択とする。
- `uncovered` が空のときは、「すべての役割を確認し直す」「中止する」の 2 択とする。

| 回答 | 新規生成(ステップ 6)の対象 | 再生成(ステップ 7)の対象 |
| --- | --- | --- |
| 未カバーの役割だけ作る | `uncovered` の役割 | なし |
| すべての役割を確認し直す | `uncovered` の役割 | `coveredBy` のある役割の定義 |
| 中止する | なし | なし |

「中止する」が選ばれたら生成せずに終え、ステップ 2 で操作を実行していれば、その結果だけをステップ 8 の形で報告する。

## ステップ 4: 翻訳断片の準備

`lang` が `ja` か `en` なら、このステップを飛ばす。

1. 翻訳断片の状態を取得する。

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --check-fragments --lang <lang> --dir "$PWD"
   ```

2. `missing` と `stale` がともに空なら、ステップ 5 へ進む。どちらかがあれば、`stale` の既存訳を退避するよう利用者に促してから scaffold する。scaffold は `stale` のファイルを英語で上書きするため、既存の訳は失われる。

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --scaffold-fragments --lang <lang> --dir "$PWD"
   ```

3. 応答の `written` の各ファイルを `Edit` で翻訳する。
   - 翻訳するのは、本文と frontmatter の `label` / `description` だけである。
   - `## When to invoke` の本文は翻訳せず、英語のまま残す。
   - `id` / `kind` / `tools` / `default-name` / `source-lang` / `source-hash` と、セクションの見出しは変えない。
4. 状態確認を再実行し、`missing` と `stale` が空になったことを確かめる。空でなければ生成へ進まない。

## ステップ 5: MCP サーバーの選択

新規生成の対象が 0 件なら、このステップを飛ばす。

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --list-mcp --dir "$PWD"
```

失敗したとき、または `servers` が 0 件なら、何も質問せず、ステップ 6 の MCP の質問を省く。成功したときは、`usable: true` のサーバーだけを、名前と `status` を添えて選択肢にする。候補数の共通規則を当て、「どのサーバーも使わない」を最後の選択肢に置く。ページに分けるときは「どのサーバーも使わない」を置かず、回答が空になったときを「どのサーバーも使わない」として扱う。「どのサーバーも使わない」が選ばれたら、ステップ 6 の MCP の質問を省く。

## ステップ 6: 新規生成

対象の役割を、`--list-coverage` の `roles` の順に 1 つずつ扱う。1 つの役割の 1〜6 を終えてから次の役割へ進む。各質問は別の `AskUserQuestion` 呼び出しにし、この役割だけを対象にする。複数の役割をまとめて決める選択肢(「推奨をそのまま使う」「全部作る」など)は出さない。

1. モデルを聞く。候補は推奨のモデル(`roles[].model`)と残りの Claude の 3 モデル(`sonnet` / `opus` / `haiku` / `fable` のうち推奨以外)、「この役割は作らない」の 5 件になる。単一選択で 4 件を超えるので、2 問に分ける。
   - 1 問目: 「<推奨のモデル>(推奨)」「その他のモデル」「この役割は作らない」の 3 択。<> の中は実際の値に置き換える。
   - 2 問目: 1 問目で「その他のモデル」が選ばれたときだけ、残りの 3 モデルから選ばせる。
   - 「この役割は作らない」が選ばれたら、2〜6 を聞かずに次の役割へ進み、ステップ 8 で報告する。
2. effort を聞く。1 で推奨と違うモデルを選んだときだけ聞く。推奨のモデルのときは聞かず、`--effort` を渡さない(CLI が役割の推奨値を書く)。候補は `low` / `medium` / `high` / `xhigh` / `max` と「書かない」の 6 件なので、2 問に分ける。
   - 1 問目: 「<推奨の effort>(推奨)」「その他の値」「書かない(モデルの既定に任せる)」の 3 択。推奨の effort は `roles[].effort` である。
   - 2 問目: 1 問目で「その他の値」が選ばれたときだけ、残りの 4 値から選ばせる。
   - 選んだ値を `--effort` に渡す。「書かない」は `--effort none` にする。
3. 定義名を「既定名を使う」「別の名前を指定する」の 2 択で必ず聞く。既定名は `roles[].defaultName` で、前にモデル名を付けない。後者は自由入力で受け、`^[a-z0-9]+(?:-[a-z0-9]+)*$` に合わなければ聞き直す。
4. MCP サーバーを聞く。ステップ 5 でサーバーを 1 つ以上選んだときだけ行う。
   - 先に単一選択で「既定のサーバーを付ける(推奨)」「選ぶ」「付与しない」の 3 択を聞く。既定のサーバーは、ステップ 5 で選んだ全サーバーである。質問文に既定のサーバー名を書く。
   - 「選ぶ」が選ばれたときだけ、続けて別の呼び出しで、付与するサーバーを複数選択で聞く。選択肢はステップ 5 で選んだサーバーに限り、候補数の共通規則に従う。空の選択肢は置かない。ページ分けで回答が空になったら「付与しない」と同じに扱う。
   - readonly の役割(`roles[].kind` が `readonly`)にサーバーが付くときは、書き込み系ツールの denylist を確定させる。書き込み系ツールは、ファイル・リポジトリ・外部サービスの状態を変えるツールを指す。実行中の Agent 自身のツール一覧から、付与するサーバーの書き込み系ツールを列挙する。読み取り・検索・解析のツールは含めない。サーバーの選択の回答を受け取った後に、`disallowedTools` に入れる案を別の `AskUserQuestion` 呼び出しで確認する。同じサーバー集合で確定済みの denylist があれば、聞き直さずに使う。
   - denylist は列挙漏れを許可する方式である。確認の質問文には、次の文をそのまま入れる。

     > 一覧に無い書き込み系ツールは、読み取り専用の役割からも使えます。

   - 利用者が denylist の確定を拒んだ readonly の役割には、サーバーを付けない。
5. 差分を確かめる。

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --check --role <RoleId> --model <model> [--effort <effort|none>] --name <name> --lang <lang> --dir "$PWD"
   ```

   - `exists` が `false` なら、6 へ進む。
   - `adopt` が `true`(同じ名前のファイルがあり、`better-agentics-role` を持たない)なら、ファイルごとに 1 回、「本文をまとめてテンプレートに置き換える(推奨)」「セクションごとに選ぶ」の 2 択で聞く。質問文に、既存のファイルの frontmatter(MCP・`disallowedTools`・その他のキー)は引き継がれることを書く。「セクションごとに選ぶ」のときだけ、`sections` のうち `state` が `unknown` のセクションごとに、既存(`existing`)とテンプレート(`template`)を選択肢の `preview` に入れて、「保持する」「テンプレートに置き換える」を聞く。推奨は付けない。
   - `adopt` が `false` で `exists` が `true` のときは、ステップ 7 の 4 と同じ規則でセクションを扱う。
   - 保持すると決めたセクションを、6 の `--keep` に渡す。
6. 生成する。MCP の引数は、impl の役割にサーバーが付くときは `--mcp-servers` だけを渡す。readonly の役割にサーバーが付くときは `--mcp-servers` と `--mcp-deny` の両方を渡す。サーバーを付けないときは `--mcp-servers ""` を渡す。

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --write --role <RoleId> --model <model> [--effort <effort|none>] --name <name> [--mcp-servers "<server,...>"] [--mcp-deny <tool,...>] [--keep <section,...>] --lang <lang> --dir "$PWD"
   ```

   `--keep` の値は、`description`・`preamble`・見出しから `## ` を除いた名前(例: `When to invoke`)をカンマで区切ったものである。

## ステップ 7: 再生成

対象は、ステップ 3 で「すべての役割を確認し直す」が選ばれたときの、`coveredBy` のある役割の定義である。0 件なら飛ばす。定義を 1 つずつ、1〜5 の順に扱う。`--name` には定義の `file` を渡し、ファイル名を変えない。

1. モデル。定義の `model` が `sonnet` / `opus` / `haiku` / `fable` のどれかなら、その値を使い、質問しない。それ以外(`inherit`・外部のモデル・未設定)なら、ステップ 6 の 1 の 2 問で聞く。「この役割は作らない」の位置には「再生成しない」を置く。質問文には、「この定義の model は <元の値、または未設定> から <選んだモデル> に変わる」と書く。<> の中は実際の値に置き換える。
2. effort。モデルが役割の推奨と同じなら `--effort` を渡さない。違うなら、定義の `effort` があればその値を渡し、無ければ `--effort none` を渡す。1 でモデルを選び直したときは、ステップ 6 の 2 で聞く。
3. MCP。定義ごとに 1 回、単一選択の「既存のまま(推奨)」「変更する」「付与しない」の 3 択を聞く。質問文に、ステップ 4 の `--check` の `mcpCurrent` のサーバー名(無ければ「MCP なし」)を書く。
   - 「既存のまま」: `--mcp-servers` と `--mcp-deny` を渡さない(CLI が既存の値を引き継ぐ)。
   - 「付与しない」: `--mcp-servers ""` と `--mcp-deny ""` を渡す。
   - 「変更する」: 続けて別の呼び出しで、付与するサーバーを複数選択で聞く。選択肢は `--list-mcp` の `usable: true` のサーバーとし、候補数の共通規則に従う。空の選択肢は置かない。readonly の役割なら、ステップ 6 の 4 の手順で denylist を確定させる。
4. セクション。`--check` を実行し、`sections` を `state` で扱う。

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.mjs" --check --role <RoleId> --model <model> [--effort <effort|none>] --name <file> --lang <lang> --dir "$PWD"
   ```

   | `state` | 扱い |
   | --- | --- |
   | `same`・`new`・`extra` | 質問しない。`extra`(既存だけにあるセクション)は CLI が残す |
   | `templateChanged` | 「テンプレートに置き換える(推奨)」「保持する」 |
   | `userEdited` | 「保持する(推奨)」「テンプレートに置き換える」 |
   | `unknown` | 「保持する」「テンプレートに置き換える」。推奨は付けない |

   質問するときは、既存(`existing`)とテンプレート(`template`)を選択肢の `preview` に入れる。1 回の `AskUserQuestion` には 4 問まで入る。
5. 保持すると決めたものを `--keep` に渡し、ステップ 6 の 6 のコマンドで生成する。

## ステップ 8: 報告

すべての応答から、次を報告する。

- 生成・再生成・取り込みした定義の `target` と `action`、`kept`(保持したセクション)、`replaced`(置き換えたセクション)
- `keysKept`(CLI が生成しないキーのうち残したもの)
  - 取り込んだ定義の `keysKept` に、キー名が `-role` で終わる他の役割マーカーが残ることがある。
  - その定義は本文を書き換えた後も、そのマーカーを読む仕組みから委譲先として使われうる。このことを伝え、マーカーを残すかを利用者に委ねる。
