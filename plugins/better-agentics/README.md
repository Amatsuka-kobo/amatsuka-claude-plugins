# better-agentics

オーケストレーター(メインのセッション)が調査・設計・実装を自分で進め、次の 3 つの場面でだけサブエージェントへ委譲するプラグインです。

| 場面 | 内容 |
| --- | --- |
| レビュー | 自分の成果物を、自分以外の目で確かめる |
| 分担 | 作業の一部を、委譲先に進めてもらう |
| 行き詰まり | 自分で原因を追っても解決しない |

委譲先は、TypeSafe AI の判断モデル Jev が、13 の役割から選びます。選択基準(英語の `## When to invoke`)は委譲先決定スクリプトだけが読んで Jev に渡し、オーケストレーターは「いつ委譲するか」だけを判断します。

## 使い方

1. 次の 2 つの環境変数を設定し、新しいセッションを起動します。

   ```bash
   export AMATSUKA_AGENT_ENABLE_ORCHESTRATION=1
   export TYPESAFE_API_KEY=<TypeSafe AI の API キー>
   ```

2. セッションの開始時に、オーケストレーターの規律(`better-agentics:orchestration`)の使用指示が注入されます。これだけで、13 の役割すべてに、役割ごとのモデルと effort で委譲できます。
3. 役割の定義を調整したいときや、使わない役割を外したいときは、`/better-agentics:setup` を実行します。setup は必須ではありません。

## 委譲の 2 つのモード

役割ごとに、プロジェクトに定義があるかで起動の仕方が決まります。

| モード | 条件 | 起動の仕方 |
| --- | --- | --- |
| Custom Agent モード | `.claude/agents/` に、その役割の `better-agentics-role` を持つ定義がある | 定義の名前で起動します。モデル・effort・ツールは定義の frontmatter に従います |
| Standard Agent モード | 定義が無い | 組み込みの `general-purpose` に、役割の推奨のモデルと effort を付けて起動します。役割の指示とサブエージェントの規律は、依頼文の冒頭の前置きで渡します |

分担の作業のうち、会話の文脈が無いと仕様を書き切れないものは、fork(会話の履歴を引き継ぐサブエージェント)に委譲します。fork を使うのは、複雑な実装・通常の実装・その他のタスクの 3 役割で、役割のモデルが親のモデルと同じときだけです。fork は親のモデルと effort で動き、役割の推奨 effort は使いません。条件に合わない作業は、オーケストレーターが自分で行います。

定義を作った役割では、利用者が定義を編集して振る舞いを調整できます。setup が作る定義には次のキーも入ります。

- レビューの 5 役割には `experimental.cacheTtl: 1h` を書き、再レビューで再開するまでのプロンプトキャッシュを 1 時間にします。
- 役割ごとに `omitClaudeMd: true` を付けるかを選べます。付けると、CLAUDE.md・規約・保護パス・ユーザーの rules が委譲先に届かなくなります。推奨は、暗黙知の抽出の役割だけに付けることです。

`.claude/agents/` を新しく作ったときは、Claude Code を再起動するまで定義が読み込まれません。

## 役割の外し方

setup の「外す役割の見直し」で選んだ役割は、委譲先の候補から外れます。外した役割は `.claude/better-agentics/config.json` の `disabledRoles` に記録され、定義があっても委譲しません。

- レビューの役割をすべて外すと、必須のレビューが止まります。分担の役割をすべて外すと、探索などの委譲が止まります。
- 行き詰まりの役割(escalation)を外すと、行き詰まったときもオーケストレーターが自分で続けます。
- fable を使えない環境では、escalation と complex-review を外すか、別のモデルで定義を作ってください。使えないモデルはエラーにならず、別のモデルに置き換わります。
- `config.json` を git で追跡するかはプロジェクトの判断です。追跡しないと、git worktree では外した役割が戻ります。

## 環境変数

`AMATSUKA_AGENT_ENABLE_ORCHESTRATION` は前後の空白を除き、小文字にしてから判定します。上の行から順に評価し、最初に当たった行の動作になります。

| 状態 | セッション開始時の動作 |
| --- | --- |
| 未設定・空・`0`・`false`・`off` | 何もしない |
| `1`・`true`・`on` 以外の値 | 未知の値だという警告だけを出す |
| `AMATSUKA_AGENT_AUTO_INJECTION` が空でも `none` でもない | 規律を注入せず、2 つの環境変数が同時に有効だという警告を出す |
| `AMATSUKA_AGENT_DELEGATION_GATE` が `1`・`true`・`on` | 規律を注入せず、直接編集を差し止める gate が有効だという警告を出す |
| `TYPESAFE_API_KEY` が無い | 規律を注入せず、キーが無いという警告を出す |
| 上記以外 | オーケストレーターの規律の使用指示を注入する |

`AMATSUKA_AGENT_AUTO_INJECTION` と `AMATSUKA_AGENT_DELEGATION_GATE` は、エージェント運用方針を注入する別のプラグインの環境変数です。better-agentics と同時には使えません。

サブエージェントの規律は、Custom Agent モードの定義で起動したサブエージェントに対し、上の表の最後の行か「`TYPESAFE_API_KEY` が無い」の行に当たるときだけ注入します。注入の先頭には、その定義の役割 ID を添えます。

### 役割の設定を上書きする環境変数の警告

規律を注入するとき、次の環境変数が設定されていれば警告を添えます。注入は止めません。設定ファイルの `env` で設定した値も対象です。

| 環境変数 | 起きること |
| --- | --- |
| `CLAUDE_CODE_EFFORT_LEVEL` が空でない(`auto`・`unset` を含む) | 役割ごとの effort が使われません |
| `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` が空・`0`・`false` 以外 | 委譲先のモデルが一律になります。渡したモデルは黙って置き換わります |
| `FORCE_PROMPT_CACHING_5M` が設定されていて、レビューの役割の定義がある | レビュアーの 1 時間のキャッシュが効きません |
| `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` が `5m` で、レビューの役割の定義がある | 同上 |

次の設定は検出しません。設定の `maxEffortLevel` と組織の effort の上限は、役割の effort を抑えます。設定の `subagentPromptCacheTtl` は、定義の 1 時間のキャッシュより優先されます。`availableModels` が塞ぐモデルは、エラーにならず別のモデルに置き換わります。`claude -p` では、置き換えの警告も出ません。

## TypeSafe AI へ送る内容

委譲のたびに、次の内容が TypeSafe AI へ送られます。

- オーケストレーターが書いた作業の要約(英語)
- レビューを依頼するときは、成果物のパス
- 候補の役割 ID と選択基準。定義のある役割は定義の `## When to invoke`、定義の無い役割は同梱の役割断片の `## When to invoke` を送ります

成果物の中身は送りません。文脈が要る作業のうち、Jev に問う前に自分で行うと決まったもの(親のモデルの申告が無い、または fork が無効)は送りません。fork になりうる作業の要約は送ります。

## 選ばれ方の調整

定義のある役割の選ばれ方は、定義の `## When to invoke` を編集すると変えられます。`/better-agentics:setup` で定義を作り直すときは、利用者が編集したセクションを見分けて、保持するかを尋ねます。

## 更新で変わる挙動(0.0.2-dev の起動モード改修)

- 定義の無い役割も、Standard Agent モードで委譲先の候補になります。改修の前に setup で「作らない」を選んだ役割も候補に戻ります。SessionStart がそうした役割を知らせるので、使わない役割は setup で外してください。
- 理由に当たる定義が 1 つだけでも、外していない役割が 2 つ以上あれば Jev を呼びます。
- 委譲先決定スクリプトの出力のキー `agent` が `agentType` に変わり、`mode` などの項目が増えました。
- 役割断片と `_common.md` が変わりました。ja・en 以外の翻訳断片は訳し直すまで setup が止まります。
- 作り直していない定義には、次の変更が入りません。役割 ID、Output Format の結果が無いときの書き方、light-impl の制約の変更(全セッションに効く設定の変更を断らない)、general・light-impl・adversarial-review の `## When to invoke` に足した 1 行です。setup での作り直しを勧めます。作り直さなくても、役割 ID は SubagentStart の注入が補います。
- 実装のレビューは、コミットの前から後へ移りました。
- レビューと修正は、critical・high の指摘が出なくなるまで上限なく回します。critical・high が出なかった巡の medium 以下は、直さずに判断を仰ぎます。
- 実装・設定・データ移行の修正は、4 ラウンド目から行き詰まりの役割に直させ、2 ラウンドごとに新しく起動し直します。文書の修正は、4 ラウンド目からオーケストレーターが自分で直します。行き詰まりの役割を外しているときは自分で直し、2 ラウンドごとに原因の調べ直しから始めます。
- 委譲先にスキルを使わせるときは、名前と SKILL.md のパスで渡し、要る部分を書き写さなくなりました。

## 動作の前提と限界

- Claude Code 2.1.302 以上(fork の既定)。呼び出しごとの `effort` は 2.1.292、`omitClaudeMd` は 2.1.271、`experimental.cacheTtl` は 2.1.248 から使えます。
- Node.js 22 以上
- TypeSafe AI の API キー。キーが無いと委譲先を決められず、オーケストレーターはユーザーの指示を待ちます。TypeSafe AI は 2026-09-22 から新規サインアップを停止しています。
- Standard Agent モードでは、委譲先のツールを絞れません。読み取りの役割が書き込まないことは、規律でしか担保できません。
- `omitClaudeMd` と 1 時間のキャッシュは、Custom Agent モードの定義にしか効きません。
- 1 時間のキャッシュは、サブスクリプションの使用クレジットを消費している間は効きません。
- 委譲先が、スキルの SKILL.md をプラグインのキャッシュ(プロジェクトの外)からパスで読むと、許可の確認が出ます。
- `claude -p` の `default` の許可モードでは、委譲先決定スクリプトへ JSON を heredoc で渡す呼び出しが、Bash の安全検査で拒否されます。`-p` で使うときは、`Skill` と委譲先決定スクリプトの実行を許可したうえで、入力をファイルからリダイレクトで渡せる許可モードで動かしてください。
