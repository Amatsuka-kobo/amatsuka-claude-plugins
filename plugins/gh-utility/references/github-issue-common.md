# GitHub Issue 操作の共通規律

`issue-craft` / `issue-split` / `issue-triage` のいずれかを読むときは、併せてこの文書も読む。

## 大原則

- ディスカッションはユーザーが使用する言語を厳守する。Issue 本文の言語は各スキルの手順で別に確認する。
- ユーザーの明示的な承認を得るまで、外部から見える操作(起票・ラベル付与・コメント・クローズ)をしない。起票とクローズは取り消しの効きにくい外部公開行為である。
- STOP するときは「理由」と「次にユーザーがすべきこと」を伝えて終了する。

## 環境チェック

各スキルの最初の手順で 1 回実行する。

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/check-issue-env.mjs"
```

出力 JSON の事実に基づいて判断する。

- `isGitRepo: false` → git リポジトリ化(`git init` とリモート設定)を推奨して STOP。
- `repoSlug: null`(リモート未設定、または GitHub 以外のリモート)→ 状況を説明し、GitHub リポジトリの作成・リモート設定(`gh repo create` 等)を案内して STOP。

## 操作手段の決定

自分の利用可能ツール一覧を確認し、次の優先順で決める。必要な操作の範囲は各スキルの手順に書かれたものを用いる。

1. 必要な操作ができる GitHub 操作系の MCP Tool があればそれを使う。
2. なければ `gh` コマンドを使う。`ghInstalled: false` なら導入手順を案内して STOP。`ghAuthenticated: false` なら `gh auth login` の実行を案内して STOP。

## コマンドの実行

Issue 本文・コメント本文は一時ファイルに書き、`--body-file` で渡す。

## ラベル・アサイン

- ラベルはリポジトリの既存ラベル(`gh label list` または MCP Tool)から提案する。存在しないラベルを勝手に作らない。
- 既存ラベルが 0 件のときはラベルなしで進め、ラベル体系の整備が必要な旨を報告に添える。
- アサイン・マイルストーンはユーザーから明示的に指示されたときだけ設定する。

## 執筆規則

適用範囲は、起票する Issue 本文、PR 本文、Issue と PR へのコメント、レビュー本文である。

- 必要な情報を 100% 落とさずに、人が読みやすくなるよう可能な限り簡潔に書く。
- テストの結果得たスクショなど、関連する画像を本文に載せる。
- 引用・出典は削らず末尾にまとめる。

文の組み立ては次に従う。

- 言い切りで書き、命令形にしない。
- 1 文に 1 つの情報だけを書く。
- 項目が並列なときだけ箇条書きにし、経緯や理由が続く内容は地の文で書く。
- 太字や強調語で強めず、条件と範囲を書いて重さを伝える。
- 例を示すときは、それが例示であることと、値を実際の内容に置き換えることを明記する。
- 上の基準を保てる範囲で、最も短い文で書く。

## 画像の載せ方

`--attach` は `gh` 2.99.0 以降で、`issue create`・`issue edit`・`issue comment`・`pr create`・`pr edit`・`pr comment` の 6 コマンドに使える。`gh pr review` には無い。

画像を載せる手段は、実行のたびに `gh --version` と、環境チェックが返す `remoteHost`、そのセッションで claude-in-chrome の MCP ツール(`mcp__claude-in-chrome__*`)が使えるかを確かめて決める。縮退の順序は、文書の種類で 2 系統に分かれる。

Issue・PR・コメント全般:

| 順 | 手段 |
| --- | --- |
| 1 | `gh` が 2.99.0 以上で、リモートのホストが `github.com` か `*.ghe.com` なら `--attach` で載せる |
| 2 | claude-in-chrome の MCP ツールが使えれば、ブラウザから GitHub に画像をアップロードし、得た URL を本文に書く |
| 3 | どちらも使えなければ、画像をローカルに保存し、本文に添付できなかった理由と保存パスを書く |

レビュー本文(`gh pr review`):

| 順 | 手段 |
| --- | --- |
| 1 | claude-in-chrome の MCP ツールが使えれば、ブラウザから GitHub に画像をアップロードし、得た URL をレビュー本文に書く |
| 2 | `gh` が 2.99.0 以上で、リモートのホストが `github.com` か `*.ghe.com` なら、画像付きの本文を `gh pr comment --attach` で投稿し、承認・変更要求の判定だけを `gh pr review` で行う |
| 3 | どちらも使えなければ、画像をローカルに保存し、本文に添付できなかった理由と保存パスを書く |

- `--attach` を使うのは、`gh` が 2.99.0 以上で、かつリモートのホストが `github.com` か `*.ghe.com` のときだけである。GHES のホストでは使わず、次の順へ縮退する。
- ローカルに保存したときは、保存したパスを利用者に示す。
- 画像のアップロードは取り消せない外部公開行為である。画像の可視性はリポジトリの可視性に従い、private リポジトリの画像は閲覧権限のある人にだけ見える。載せる前に、公開してよい画像かを確かめる。
- claude-in-chrome を使う操作は、ブラウザが使えてログイン済みであることを前提とする。操作に失敗したら、次の順の手段へ縮退する。

## 失敗時

- 生のエラーをそのままユーザーに報告して停止する。
- 勝手なリトライをしない。代替手段へ切り替えない。
- 作成済み・適用済みの Issue をロールバックしない。どこまで処理済みかを報告に含める。
