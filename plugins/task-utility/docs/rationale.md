# task-utility の設計根拠

各スキルの指示から退避した根拠・背景をまとめる。スキル本文には指示だけを置き、判断の由来はここに残す。

## description を skill-creator 基準で書く理由

description と本文では最適化の目標が違う。本文は読んだ AI の振る舞いを決めるので簡潔さが効くが、description は発火するかどうかだけを決めるので、簡潔さより発火の確実性が優先される。

2026-08-01 の実測で、この 2 つが衝突する場面が確認できた。prompt-smith 基準で足した負の境界(「明示的な依頼があったときのみ使い、自律的には発動しない」)は、隣接スキルへの誤発火を防ぐ一方、正当な依頼への発火も抑える方向に働く。resume / issue-craft の description を直したときも、口語への対応(pushy 化)と範囲の限定を同じ改稿で行うことで、片方の副作用をもう片方が打ち消す形になった。

## trigger eval に自前ランナーを使う理由

skill-creator の `run_eval.py` は測定対象を `.claude/commands/` にスラッシュコマンドとして登録する。Claude Code の現行版ではコマンドと skills が別系統で、コマンドは `/名前` で明示呼び出しするものであり、自然文の依頼からは選ばれない。検出側は `Skill` ツールの呼び出しを見ているため、結果が常に「発火せず」になる。

2026-08-01 の実測: skill-creator 公式の description を、その想定用途どおりの英語クエリで測っても発火率 0 だった。同じ description・同じクエリで登録先を `.claude/skills/` に変えると発火する。resume の substantive クエリ 8 問は、登録方法を変えるだけで 1/8 から 8/8 になった。

この故障に気づかないまま description を書き換えると、壊れた測定に合わせて本番を改悪する。対照実験(実績のある description で測って発火するか)を先に行う。

## 誤発火 3 件を残した理由

2026-08-01 時点で次の 3 件が誤発火する。

- resume: 「この PR のレビューを再開したい。差分を見せて」
- resume: 「さっきの続きだけど、あの関数のリファクタ続けて」
- issue-craft: 「gh コマンドで Issue 一覧を取得する方法を教えて」

3 件とも description の否定条項に直接該当する語を含みながら発火しており、文面では抑えきれない。否定を重ねると正当な発火まで抑える副作用が出る。誤起動しても各スキルは手順の最初でユーザーに確認を入れるため、実害は限定的である。

## chat: ユーザー発言を原文で残す理由

ユーザーの発言は要件の一次資料である。AI の解釈で置き換えて記録すると、AI が要件を誤解していた場合に「AI の誤解」が「ユーザーの要求」として歴史に残り、後から検証する手段が失われる。発言は会話全体のごく一部であり、原文保存のコストはほぼゼロで済む。

## chat: 引用ブロックと地の文を対応させる理由

引用ブロック(`>`)を発言の原文、地の文を要約・言い換えに固定するのは、読み手が「これは本人の言葉か、AI の解釈か」を常に判別できるようにするためである。この対応が崩れると、記録全体の一次資料としての価値が失われる。

## chat-recall: 既定で全ユーザーの記録を検索する理由

過去の決定は誰のセッション由来でも価値がある。作業者で絞ると、他者が決めた前提を見落としたまま同じ議論を繰り返すことになる。

## issue 系: 本文を `--body-file` で渡す理由

Issue 本文・コメント本文には改行・バッククォート・引用符が含まれる。コマンドライン引数として渡すとシェルのクォート解釈で本文が壊れる、あるいはコマンドが意図せず分割される。一時ファイル経由であればシェルの解釈を通らない。

## issue-triage: 新しいラベルの作成を提案しない理由

ラベル体系の設計はユーザーの仕事である。棚卸しの過程で AI が体系を拡張すると、リポジトリの分類方針がユーザーの手を離れて増殖する。

## issue-triage: クローズ提案を決定的ルールに限る理由

クローズは取り消しの効きにくい外部公開行為である。LLM の裁量で「もう不要そう」と判断させると、他者が待っている Issue を閉じる事故が起きる。「自分が作者・アサインなし・コメントなし」という機械的条件は、誰も関心を持っていないことが客観的に確認できる範囲に提案を閉じ込める。
