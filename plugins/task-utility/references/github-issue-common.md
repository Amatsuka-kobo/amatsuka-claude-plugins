# GitHub Issue 操作の共通規律

`issue-craft` / `issue-split` / `issue-triage` のいずれかを読むときは、併せてこの文書も読む。

## 大原則

- ディスカッションはユーザーが使用する言語を厳守する。Issue 本文の言語は各スキルの手順で別に確認する。
- ユーザーの明示的な承認を得るまで、外部から見える操作(起票・ラベル付与・コメント・クローズ)をしない。起票とクローズは取り消しの効きにくい外部公開行為である。
- STOP するときは「理由」と「次にユーザーがすべきこと」を伝えて終了する。

## 環境チェック

各スキルの最初の手順で 1 回実行する。

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/check-issue-env.mjs"
```

出力 JSON の事実に基づいて判断する。

- `isGitRepo: false` → git リポジトリ化(`git init` とリモート設定)を推奨して STOP。
- `repoSlug: null`(リモート未設定、または GitHub 以外のリモート)→ 状況を説明し、GitHub リポジトリの作成・リモート設定(`gh repo create` 等)を案内して STOP。

## 操作手段の決定

自分の利用可能ツール一覧を確認し、次の優先順で決める。必要な操作の範囲は各スキルの手順に書かれたものを用いる。

1. 必要な操作ができる GitHub 操作系の MCP Tool があればそれを使う。
2. なければ `gh` コマンドを使う。`ghInstalled: false` なら導入手順を案内して STOP。`ghAuthenticated: false` なら `gh auth login` の実行を案内して STOP。

## コマンドの実行

Issue 本文・コメント本文は一時ファイルに書き、`--body-file` で渡す。

## ラベル・アサイン

- ラベルはリポジトリの既存ラベル(`gh label list` または MCP Tool)から提案する。存在しないラベルを勝手に作らない。
- 既存ラベルが 0 件のときはラベルなしで進め、ラベル体系の整備が必要な旨を報告に添える。
- アサイン・マイルストーンはユーザーから明示的に指示されたときだけ設定する。

## 失敗時

- 生のエラーをそのままユーザーに報告して停止する。
- 勝手なリトライをしない。代替手段へ切り替えない。
- 作成済み・適用済みの Issue をロールバックしない。どこまで処理済みかを報告に含める。
