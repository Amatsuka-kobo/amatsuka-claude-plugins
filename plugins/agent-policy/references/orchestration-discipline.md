# オーケストレーション共通規律

以下で「担当表」とは、読み込んだ方針の §モデル別役割 の表を指す。帯の名前は担当表の行名で参照する。

## モデル別役割の運用

- 各モデルは担当表に従い、その役割タスクのみを担当する。
- 複数コンポーネントにまたがる実装、または非自明な設計判断を含む実装は「複雑または重要な実装」とする。
- 単一コンポーネントに閉じ、設計判断を伴わない実装は「通常の実装」とする。
- 既存パターンの機械的な反復・一括適用は「軽量な実装」とする。
- サブエージェントを起動するとき、対象に「あなたはサブエージェントである」ことを明示する。
- オーケストレーターは、複数の context-map・設計書・実装差分・並列サブエージェントの全レポートを分割せず一度に読んで突き合わせる。要約の要約では判断しない。
- オーケストレーターは、独立したタスクが複数あるとき、それらを 1 メッセージ内で同時に dispatch する。
- オーケストレーターは、担当表の「軽量な実装」の帯以外のサブエージェントに Agent Tool を許可する。
- サブエージェントは、アドバイザーとして相談する相手を `Fable` にする。`Fable` が利用できないときは `Opus` にする。
- サブエージェントは、Agent Tool が許可されていないときの迷いを、相談ではなく差し戻しで解決する。
- サブエージェントは、自身が起動したアドバイザーサブエージェントに Agent Tool を許可せず、依頼文に「助言のみを返し、作業はしない」と明記する。
- サブエージェントは、依頼文で指定されたスキルだけをロードする。指定がなければどのスキルもロードせず、依頼文の記述だけで作業する。

## 委譲先の実行モデルの確定

すべての dispatch の前に、委譲先の実行モデルを確定させる。

- セッションで初めて委譲する Agents は、定義ファイルの frontmatter `model` を確認する。
- 確認は原本に対して行い、複製・改変版は作らない。
- ビルトイン Agents(`Explore` / `Plan` / `general-purpose` 等)は `inherit` として扱う。
- `model` が具体的なモデルに指定されている Agents は、そのまま起動する。担当表では上書きしない。
- `model` 未指定・`inherit` の Agents は、作業種別を担当表に照らして実行帯を決める。
- 実行帯が Claude モデルのときは、dispatch 時の `model` 上書きで実行帯を明示する。委譲元と同じ帯でも明示する。
- 実行帯が Claude モデル以外のときは、読み込んだ方針の該当節に従う。該当節がない方針では、その帯を担当表の Claude モデルへ読み替える。

## コードベース探索

- ファイル探索・コードベース探索が必要なときだけ、この文書と同じディレクトリの `context-map-guide.md` を読み、これに従う。
- コードベース探索は担当表の「コードベース探索統括」の帯が統括する。grep/read の反復など短命な探索実働は、担当表の「コードベース探索実働」の帯へバッチ委譲する。
- context-map の執筆・§未解決事項の判断・要件確定への接続は、担当表の「コードベース探索統括」の帯が行う。
- 作成した context-map の所在(パス)は、次の dispatch または上流報告で必ず通知する。

## コスト規律

- 委譲先にロードさせるスキルは、`wc -c` で本文と参照文書の合計を測る。30KB を超えるものは、指定があってもロードさせず、必要な節・手順・制約だけを参照断片として依頼文へ転記する。
- サブ側で 3 ターン以上の自律作業が見込める探索・反復作業は、N 件を 1 dispatch に束ねてバッチ委譲する。2 ターン以下で終わる転記級の作業はオーケストレーターが直接 Write する。
- サブエージェントに毎タスクの git commit・広域 grep 検証はさせない。バッチの最後にオーケストレーター側で行うか、1 回の検証専用 dispatch へ寄せる。

## 設計・実装計画の規律

- コードベース探索を伴う設計・実装は、context-map の作成後に着手する。
- 出力した設計書・実装計画書は、まず担当表の「設計書・実装計画書のレビュー」の帯にレビュー(理解+暗黙知・矛盾抽出)させ、オーケストレーターが補足修正を加える。
- 補足修正を終えた設計書・実装計画書は、ユーザーへ提示して承認を得る。
- オーケストレーターの Approve(計画が全体要件を満たすことの確認)はユーザー承認の後に置く。Approve を経てから実装へ移行する。
