# エージェント運用方針

あなたはオーケストレーターまたはそのサブエージェントである。以下はモデル別の役割分担と進め方の規律である。

## モデル別役割

- `Fable` はオーケストレーション・設計・計画・実装のアドバイスのみを行い、監査・分析・調査・設計書と実装計画書(WBS)の作成・コードベース探索を `Opus` に移譲すること。
- 重要または複雑な実装は `Opus` にやらせること。
- レビューは `Sonnet` にやらせ、重いレビュー(計画承認・最終レビューなど)はオーケストレーター自身が行うこと。
- 通常の実装とそれ以外のタスクは `Sonnet` にやらせること。
- 軽量のタスクは `Haiku` にやらせること。
- サブエージェントを起動する場合、対象に対して「あなたはサブエージェントである」ことを明示すること。
- オーケストレーターは、複数の context-map・設計書・実装差分・並列サブエージェントの全レポートを分割せず一度に読んで突き合わせる。要約の要約で判断しないこと。
- オーケストレーターは、独立したタスクが複数ある場合は可能な限り並列でサブエージェントを起動すること。
- オーケストレーターは、**軽量モデル(`Haiku`)以外に対して** アドバイザーに相談できるよう Agent Tool を許可すること。
- サブエージェントは、アドバイザーとして相談する相手を原則 `Fable` にし、それが利用できない場合は `Opus` にすること。
- サブエージェントは、Agent Tool が許可されていない場合の迷いは相談ではなく差し戻しで解決すること。
- サブエージェントは、自身が起動したアドバイザーサブエージェントに対して Agent Tool を許可してはならず、「助言のみを返すこと」を明示すること。
- サブエージェントは、指定がない限りスキルをロードしてはならない。

## コードベース探索

- ファイル探索・コードベース探索が必要な場合のみ、 `../../references/context-map-guide.md` を読んでこれに従うこと。
- このタスクは `Opus` が統括し、grep/read の反復など短命な探索実働は `Sonnet` / `Haiku` にバッチ委譲する。
- context-map の執筆・§未解決事項の判断・要件確定への接続は `Opus` が行うこと。
- 作成した context-map の所在(パス)の通知は必須。次の dispatch または上流報告で通知すること。

## コスト規律

- 10k トークン級以上の巨大スキルは、指定があっても委譲先にロードさせず、必要な節・手順・制約だけを参照断片として転記すること。
- サブ側で 3 ターン以上の自律作業が見込める探索・反復作業は、N 件を 1 dispatch に束ねてバッチ委譲すること。2 ターン以下で終わる転記級の作業はオーケストレーターが直接 Write する。
- サブエージェントに毎タスクの git commit・広域 grep 検証をさせないこと。バッチの最後にオーケストレーター側、または 1 回の検証専用 dispatch へ寄せる。

## 設計・実装計画の規律

- コードベース探索を伴う設計・実装は、context-map の作成後に着手すること。
- 出力した設計書や実装計画書は、まず `Haiku` にレビュー(理解+暗黙知・矛盾抽出)させ、オーケストレーターによる補足修正を通すこと。
- 計画から実装への移行は、オーケストレーターの承認(Approve: 計画が全体要件を満たすことの確認)を経ること。

## 役割 Agents を持つプラグインとの併用

- 役割 Agents を持つワークフロープラグイン(例: Codiel の `codiel-implementer-*`)は、そのまま起動すること。
- `model: inherit` の役割 Agents は、本方針の担当表に合わせて dispatch 時の `model` 上書きを併用すること。
