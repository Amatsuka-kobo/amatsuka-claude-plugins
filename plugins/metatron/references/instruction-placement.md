# 指示の置き場の判定

今後の振る舞いを残すときは、文面の置き場を下の表で決め、例外なく守らせる決まりには強制の案を加える。

## 文面の置き場

上から順に当て、最初に当たった行の置き場を採る。

| 順 | 内容の性質 | 置き場 |
| --- | --- | --- |
| 1 | 設定ファイルやコードの 1 か所から全部得られ、方針・使い分け・前提を何も加えていない | 書かない |
| 2 | 利用者 1 人だけの好みや環境の事情(応答の口調、手元の環境のパスなど) | memory |
| 3 | 成果物の決まり(`document-boundary.md` で ARCHITECTURE に当たるもの) | ARCHITECTURE |
| 4 | 特定のパスを触るときだけ要り、compaction の後に一時的に読まれなくなっても困らない決まり | `paths` 付きの rules |
| 5 | 作業の進め方の決まり(`document-boundary.md` で CLAUDE.md に当たるもの)。たまにしか行わない作業に付く決まりも含む | CLAUDE.md |
| 6 | ときどき行う作業の手順そのもの(ステップの列) | スキル |
| 7 | 上のどれにも当たらない事実や参照先(期限、外部のダッシュボードの場所など) | memory |

- 1 行目は、導けるだけでは当てない。読まずに誤るおそれのある内容は、2 行目以降に当てる。
- 2 行目と 7 行目の memory は、worktree をまたいで読まれる。`CLAUDE.local.md` は作った worktree にしか無いので、ユーザーが名指ししたときだけ置き場にする。
- `paths` 付きの rules は、compaction の後、該当するファイルに次に触れるまでコンテキストから消える。消えると困る決まりは、`paths` を外した rules か、5 行目の CLAUDE.md に置く。
- 5 行目と 6 行目は、決まりか手順の列かで分ける。「PR の本文に close を書く」は 5 行目、「リリースの 8 つのステップ」は 6 行目に当たる。

## 強制の案

例外なく守らせる決まりには、文面の置き場に加えて次の手段を案として示す。強制の手段は文面を置き換えない。文面が無いと、止められた理由と代わりの手段が伝わらない。

| 決まりの形 | 強制の手段 |
| --- | --- |
| 特定のツールの呼び出しやパスへの書き込みを止める | hook、または permissions の deny |
| 構造の決まり(import の方向など) | lint などの検査 |
| 完了の前に必ず行う検査 | Stop hook など |
