# 指示の置き場の判定

今後の振る舞いを残すときは、文面の置き場を下の表で決め、例外なく守らせる決まりには強制の案を加える。ユーザーが置き場の名前を挙げて頼んだとき(「memory に保存して」「CLAUDE.md に書いて」)は、表で決め直さずにその置き場を採る。「覚えておいて」「ルールにして」は置き場の名前ではないので、表に当てる。

## 文面の置き場

上から順に当て、最初に当たった行の置き場を採る。

| 順 | 内容の性質 | 置き場 |
| --- | --- | --- |
| 1 | 設定ファイルやコードの 1 か所から全部得られ、方針・使い分け・前提を何も加えていない | 書かない |
| 2 | 利用者 1 人だけに当てる好みや環境の事情 | memory。どのリポジトリにも当てたいときはユーザー単位の `~/.claude/CLAUDE.md` |
| 3 | 成果物の決まり(`document-boundary.md` で ARCHITECTURE に当たるもの) | ARCHITECTURE |
| 4 | 特定のパスを触るときだけ要り、compaction の後に一時的に読まれなくなっても困らない決まり | `paths` 付きの rules |
| 5 | ときどき行う作業の手順そのもの(ステップの列) | スキル |
| 6 | 作業の進め方の決まりと、作業に使う参照先(`document-boundary.md` で CLAUDE.md に当たるもの)。たまにしか行わない作業に付く決まりも含む | CLAUDE.md |
| 7 | 上のどれにも当たらない事実 | リポジトリの全員が知るべき事実は CLAUDE.md、利用者 1 人だけが使う事実と期限のように古くなる事実は memory |

- 1 行目は、導けるだけでは当てない。読まずに誤るおそれのある内容は、2 行目以降に当てる。
- 2 行目に当てるのは、本人だけに当てると述べた好み(「私が出す PR は draft にして」)と、成果物に現れない好み(応答の口調や長さ、手元の環境のパス)である。「私の好み」と言われても、他の人も従うことになる成果物の決まり(コミットや PR の書き方)には当てず、3 行目以降に当てる。
- memory は worktree をまたいで読まれる。`CLAUDE.local.md` は作った worktree にしか無いので、ユーザーが名指ししたときだけ置き場にする。
- `paths` 付きの rules は、compaction の後、該当するファイルに次に触れるまでコンテキストから消える。消えると困る決まりは、`paths` を外した rules か、6 行目の CLAUDE.md に置く。
- 5 行目と 6 行目は、手順の列か決まりかで分ける。「リリースの 8 つのステップ」は 5 行目、「PR の本文に close を書く」は 6 行目に当たる。既存のスキルの手順に付く決まりは、そのスキルに追記する案も併せて示す。

## 強制の案

ユーザーが例外を認めないと述べた決まりと、違反すると取り消せない損害が出る決まりには、文面の置き場に加えて次の手段を案として示す。強制の手段は文面を置き換えない。文面が無いと、止められた理由と代わりの手段が伝わらない。

| 決まりの形 | 強制の手段 |
| --- | --- |
| 特定のツールの呼び出しやパスへの書き込みを止める | hook、または permissions の deny |
| 構造の決まり(import の方向など) | lint などの検査 |
| 完了の前に必ず行う検査 | Stop hook など |
