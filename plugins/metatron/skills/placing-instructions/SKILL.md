# 指示の置き場の判定

残す内容の置き場を決め、案を示す。ARCHITECTURE に当たる内容だけを書き込みまで進め、それ以外の書き込みはセッションに任せる。

## 手順

1. 残す内容を、1 つの決まりまたは 1 つの事実ごとに分ける。
2. ユーザーが置き場を名指しした件は、その置き場を採る。表に当てない。
3. 残りの件を 1 件ずつ `../../references/instruction-placement.md` の「文面の置き場」に上から当てる。ARCHITECTURE と CLAUDE.md の区別は `../../references/document-boundary.md` に従う。
4. 強制の案の条件に当たる件には、「強制の案」も当てる。
5. 置き場の案をユーザーに示し、件ごとに承認を得る。自分で残そうとした内容も同じく承認を得る。
   - 否認された件は、別の置き場を示し直すか、残さないかをユーザーに尋ねる。
   - ユーザーが別の置き場を選んだ件は、その置き場を採る。
6. 承認された置き場ごとに進める。ARCHITECTURE の件は、他の件を済ませた後に回す。
   - ARCHITECTURE 以外: 案を示して終える。書き込みはセッションに任せる。
   - ARCHITECTURE があるとき: `updating-architecture` スキルを起動し、承認済みの依頼された変更として渡す。
   - ARCHITECTURE が無いとき: `capturing-architecture` スキルで初版を作るかを尋ねる。初版を書き込んだ後に、`updating-architecture` スキルを起動して同じ件を依頼された変更として渡す。作らないと決まったら、CLAUDE.md を代わりの置き場として示し直す。
7. 承認された置き場が memory でない件は、memory に保存しない。自動 memory の規則が保存を促していても、承認された置き場を優先する。
8. 同じ内容が既に memory に保存されていて、承認された置き場が memory でないときは、その memory の項目を消す案を示し、承認を得てから消す。

## 提示の形

1 件を 1 行で示す。次は例示であり、値は実際の内容に置き換える。

```
1. 「PR の本文に close #<番号> を書く」 → CLAUDE.md(6 行目: 作業の進め方の決まり)
2. 「ビルド出力のディレクトリを手で編集しない」 → ARCHITECTURE(3 行目: 成果物の決まり) / 強制の案: hook で Edit を止める
3. 「応答は結論から書く」 → memory(2 行目: 成果物に現れない好み)
```

- 当たった行の番号と性質を添える。
- 強制の案に当たるときは、同じ行に併記する。

## 担わないこと

- 指示書の文面を書く規律と、hook や permissions の設定の手順は扱わない。案として示した後、書き込みはセッションに任せる。
