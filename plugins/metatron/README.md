# Metatron 📜

プロジェクトの技術的前提(`docs/ARCHITECTURE.md`)を管理するプラグインです。文書はプロジェクトの `CLAUDE.md` に書いた @メンション(`@docs/ARCHITECTURE.md` など)で毎セッション読み込まれ、サブエージェントにも同じ経路で届きます。

名前は天の書記天使 Metatron に由来します。神の記録を司り、人の行いを書き留める役です。プロジェクトの前提を書き留め続けるという、このプラグインの役割そのものを表しています。

## 何をするか

- **記録**: 文書の更新は決定的な CLI を通します。書式の検証と、差分の承認を経た書き込みを機械で保証します。
- **更新**: `/metatron:init` と `/metatron:update` が、コードベース解析から起こしたドラフトをセクション単位で確認しながら文書を育てます。
- **読み込みと案内**: ARCHITECTURE は `CLAUDE.md` の @メンションで読み込まれます。`/metatron:init` が @メンションを追記します。SessionStart hook は文書の本文を注入せず、CLI の絶対パスと、更新時のスキルの起動を案内します。

## 動作要件

フックとスクリプトは Node.js で動作します。`node` が PATH 上にあり、バージョンが 22 以上である必要があります。

Claude Code 本体はネイティブバイナリで配布され Node.js を同梱しないため、未導入の場合は別途インストールしてください。

**常駐プロセスはありません。** metatron は MCP サーバーではなく、CLI も hook のスクリプトもいずれも短命プロセスです。そのため「サーバーが起動していないので動かない」という故障はそもそも起こりません。MCP サーバー化を撤回した経緯は [`docs/rationale.md`](./docs/rationale.md) に残しています。

## コマンド

### `/metatron:init`

対象プロジェクトの ARCHITECTURE を初回生成します。最後に、ARCHITECTURE の @メンションを `CLAUDE.md` に承認を得てから追記します。まず CLI の `scan` がコードベースの事実(パッケージマネージャ・依存・スクリプト・ディレクトリ構造など)を集め、その事実からセクションごとのドラフトを起草します。ドラフトは「こう読み取ったが合っているか」という形でセクション単位に確認し、確定後に差分を全文提示して承認を得てから書き込みます。コーディング規約・ブランチ運用・完了条件は ARCHITECTURE で扱わず、`CLAUDE.md` に書きます。init はこれらを起草しません。既存の ARCHITECTURE に旧見出しがあるときは、初回生成をせず `/metatron:update` を案内して終わります。

### `/metatron:update`

現在のコードベースと ARCHITECTURE の乖離を検出し、更新します。CLI が決定的に検出するのは、ドメインマップの穴と死んだ glob、セクションの欠落です。書かれたパスがどこを基準にした相対パスかは決められないため、ディレクトリの消失は CLI が断定しません。ルートから実在を確かめられなかったパスを並べて返し、AI がどこを指すかを読んで確かめます。技術スタックとコマンド定義は、要約として書くセクションです。CLI はこの 2 つを照合せず、定義のありか(マニフェスト・タスクランナー・コンテナ定義のパス)だけを返します。書かれた技術やコマンドが今も残っているかは、AI がそれらのファイルを読んで確かめます。候補を一覧提示し、選ばれた分だけ差分提示と承認を経て書き込みます。

旧構成の ARCHITECTURE(後述の旧見出しを持つ文書)や、旧バージョンの rules(`.claude/rules/metatron/`)が残っているプロジェクトでは、1 件の「旧構成の移行」として移します。旧見出しの本文を新しい見出しへ振り分け、旧 rules の保護パスとテスト方針も同じ移行で ARCHITECTURE へ移します。規約は `CLAUDE.md` へ移し、旧ファイルを消します。旧見出しのセクションは、移行しないと直せず、削除しかできません。どの手順も承認を得てから書き込みます。

### `/metatron:audit`

既存の ARCHITECTURE を、書式と執筆規律の現行の規定に照らして監査します。metatron の更新で書式や規律が変わったときに、既存の文書を追随させるためのコマンドです。合わない箇所を当たった規定と一緒に一覧提示し、選ばれた分だけ書き直します。規定に合わせる候補は書き方だけを直し、書かれた事実は変えません。削れる内容(下記)の候補は、根拠を示したうえで消すか書き直します。

`/metatron:audit` と `/metatron:update` は、ARCHITECTURE から削れる内容も洗い出します。対象は、同じ決まりの重複(ARCHITECTURE の中と、プロジェクトの `CLAUDE.md` との間)、設定ファイルの写し、ドメインマップの glob の言い換え、古くなった記述の 4 種類です。消す案を選ばれた分だけ、承認を得てから消します。`CLAUDE.md` から消すときも、消す行を示して承認を得ます。

ARCHITECTURE は毎セッション読み込まれるため、行数の目安を 200 行にしています。`get architecture` と `stage-architecture` は行数(`lineCount`)と目安(`lineLimit`)を返し、超えたときは警告を出します。

## 指示の置き場の判定

「今後はこうして」「覚えておいて」のように、置き場を指定せずに今後の振る舞いを残すよう頼まれたとき、`placing-instructions` スキルが置き場を判定して案を示します。AI がユーザーの訂正を受けて自分で memory などに残そうとするときも、書く前にこのスキルを起動します。

- 置き場は CLAUDE.md・`paths` 付きの rules・スキル・memory・ユーザー単位の `~/.claude/CLAUDE.md`・ARCHITECTURE と、書かない、の中から決めます。チーム全員が使う参照先は CLAUDE.md、期限のように古くなる事実は memory に置きます。判定表は `references/instruction-placement.md` にあります。
- 例外なく守らせる決まりには、hook・permissions の deny・検査による強制の案も添えます。
- 案はユーザーの承認を得てから進めます。ARCHITECTURE に当たる内容だけを `/metatron:update` の手順で書き込み、それ以外の書き込みはセッションに任せます。
- 承認された置き場が memory 以外の内容は、memory に重ねて保存しません。既に memory にあれば、消す案を示します。置き場を名指しした依頼は、その置き場に従います。

## ARCHITECTURE のセクション構成

見出しの名前と順序は次の 8 つに固定されています。すべて任意で、欠けていても構いません。

| # | 見出し | 書くこと |
| --- | --- | --- |
| 1 | `## システム概要` | プロジェクトの目的・利用者・主要な技術的制約 |
| 2 | `## 技術スタック` | 役割ごとの採用技術 |
| 3 | `## ディレクトリ構成` | ツリーと各ディレクトリの責務、レイヤーと許される依存方向 |
| 4 | `## ドメインマップ` | ドメインごとのパスの glob(`metatron:domains` のブロック) |
| 5 | `## コマンド定義` | build・lint・typecheck・test などのコマンド |
| 6 | `## テスト方針` | テストの役割分担・配置・命名 |
| 7 | `## 禁止事項` | 禁止する依存方向・触らないパス・読まないパス。代わりの手段を同じ項目に併記する |
| 8 | `## 変更時の追随` | パスを変更したときに確かめること・同時に直すもの |

書くのは成果物の決まりです。ツールの選び方・Issue とブランチの運用・完了の判定・コーディング規約・作業に使う参照先のような作業の進め方は、`CLAUDE.md` に書きます。記入例は [`docs/ARCHITECTURE.example.md`](./docs/ARCHITECTURE.example.md) にあります。

### 旧構成の移行

0.6.3 までの文書は、`## レイヤー構造`・`## ディレクトリ構成と責務`・`## 保護パス` の旧見出しを持ちます。読み取りは旧見出しのままでも今までどおり動き、拒否も警告もしません。旧見出しのセクションへの書き込みだけが、移し先を添えて拒否されます(削除の `remove: true` は通ります)。

| 旧見出し | 移し先 |
| --- | --- |
| `レイヤー構造` | レイヤーと許される依存方向は `ディレクトリ構成`、禁止する依存方向は `禁止事項` |
| `ディレクトリ構成と責務` | `ディレクトリ構成` |
| `保護パス` | 触らないパスは `禁止事項`、変更に慎重を要するパスは `変更時の追随` |

`/metatron:update` が旧見出しを検出し、1 件の「旧構成の移行」として移します。

## CLI

```
node <metatron のプラグインルート>/scripts/metatron.mjs <サブコマンド> [オプション]
```

絶対パスは SessionStart の案内文と、直接編集を拒否したときのメッセージに載ります。インストール位置を自分で調べる必要はありません。

| サブコマンド | 種別 | 概要 |
| --- | --- | --- |
| `get config` | 読 | 解決済みの絶対パス、既定値が適用された項目、拒否された設定値 |
| `get architecture [--section <見出し>]` | 読 | 全文またはセクション単位の取得。全文では行数と目安も返し、目安の 200 行を超えると警告する |
| `get domains` | 読 | ドメインマップの構造化取得(パースの成否と理由も返す) |
| `scan` | 読 | コードベース解析の事実を返す(書き込みなし) |
| `diff-architecture` | 読 | 現行 ARCHITECTURE との乖離候補と、技術スタック・コマンドの定義のありかを返す。旧見出し(`## ADR 一覧` を含む)は見出しごとに、移し先を添えた `legacy_section` として返す |
| `stage-architecture --input <path>` | 段階 | セクション更新案を受け取り、書かずに差分と `stagingId` を返す。セクションの削除は `remove: true` で指定する。旧見出しに `body` を付けると `unknown_heading` で拒否し、移し先を添える |
| `commit-architecture --staging-id <id>` | 書 | `stagingId` を消費して書き込む |
| `link-claude-md` | 書 | `CLAUDE.md` へ ARCHITECTURE の @メンションを追記し(既にあれば何もしない)、`metatron.config.json` が無ければ作る |

### なぜ CLI を通すのか

書式検証と、差分の承認なしに書き換えないという規律を、AI への指示ではなく機械で保証するためです。指示は合理化して破られますが、CLI しか書き込み口が無ければ、壊れたドメインマップは書けません。ARCHITECTURE の更新に `stage-architecture` → `commit-architecture` の 2 段階を課しているのも同じ理由で、これには差分を計算せずに書き込む経路がコマンド体系上存在しません(`stagingId` は単回使用、既定 30 分で失効し、その間にファイルが変化していれば commit は失敗します)。

### 長い入力は `--input <path>` で渡す

書き込み系サブコマンドの入力 JSON は、一時ファイルに書いてパスで渡します。引数に直接埋めると引数長の上限に当たり、本文中の引用符・バッククォート・`$`・改行がシェルに解釈されて壊れるためです。ファイルへの書き込みは Write ツールが担うのでシェルを一切通らず、CLI に渡るのはパス 1 個だけになります。CLI は読み取り後に一時ファイルを削除しません(失敗時に内容を確認できるようにするためです)。出力は常に JSON を stdout へ返します。読み取り系は「読めなかった」も事実として返すため常に exit 0、書き込み系は拒否・失敗で非 0 になり、理由は JSON の `error` に入ります。

## 2 つのイベントに掛ける 2 つのスクリプト

| hook | 役割 |
| --- | --- |
| **SessionStart**(`scripts/inject-context.mjs`) | CLI の絶対パスと、委譲の依頼文への注意を案内します。ARCHITECTURE の更新は、CLI の書き込み手順を示さず `updating-architecture` スキルの起動へ誘導します。旧 rules が残っているときと、`CLAUDE.md` に @メンションが欠けているときは、`/metatron:update` での対応を促します。今後の振る舞いを残す前に `placing-instructions` スキルを起動するよう 1 行で案内します。文書の本文は注入しません |
| **PreToolUse**(`scripts/guard-docs.mjs`) | ARCHITECTURE への直接編集を拒否します。`updating-architecture` スキルの起動へ誘導し、どの拒否にも CLI の絶対パスが載ります |

### 拒否の範囲(正直な限界)

PreToolUse hook が拒否するのは **Edit / Write / NotebookEdit ツール経由の書き込みだけ**です。次は対象外です。

- **Bash のリダイレクト**(`echo >> docs/ARCHITECTURE.md` など)。matcher に掛かりません。
- **人間のエディタでの編集**。hook は AI のツール呼び出しにのみ介在します。人間が普通に読み書きできることは Markdown で保存している目的そのものであり、これは正しい挙動です。
- **hook 自身が失敗したとき**。metatron の不具合であらゆる編集が止まる損害のほうが大きいため、素通しします(フェイルオープン)。
- **`metatron.config.json` の書き換え**。設定ファイルは hook の対象外です。Bash などで正本のパスを別の場所へ向けると、元の場所の正本は保護されなくなります。
- **symlink を通したパスの扱い**。hook はパスを 2 通りに解釈します。字句で畳んだパスか、symlink を辿った実体のパスのどちらかが正本に当たれば拒否します。一方、設定ファイルのパスの検査(ルートの外へ出ないか)と CLI の書き込み先は字句で判定し、symlink の実体は見ません。

「回避を試みる AI を止める」機構ではなく、「知らずに直接編集する AI を正しい窓口へ導く」機構だと考えてください。ファイルは git 管理下にあるため、想定外の書き込みは差分で気づけます。

## 設定ファイル `metatron.config.json`(任意)

リポジトリのルート直下に置くと、文書のパスを変えられます。無くても全項目が既定値で動き、警告も出ません。`/metatron:init` と `/metatron:update` は、CLAUDE.md に @メンションを追記するときに `{ "version": 1 }` の設定ファイルを作ります。Codiel はこのファイルの有無で Metatron の利用を判定するので、消さずにコミットしてください。

@メンションが書かれているかの判定は、ルートの `CLAUDE.md` と `.claude/CLAUDE.md` だけを見ます。他のファイル経由の import、`CLAUDE.local.md`、親ディレクトリの CLAUDE.md に書いた @メンションは数えません。

```json
{
  "version": 1,
  "paths": {
    "architecture": "docs/ARCHITECTURE.md"
  }
}
```

上の内容は既定値そのものです。`paths.architecture` が文書の位置です。パスを変えたら、`CLAUDE.md` の @メンションも合わせて直します(`/metatron:update` が欠けを案内します)。旧バージョンの `paths.rulesDir`・`paths.gotchas`・`injection` は無視されます。

- パスは設定ファイルのある位置(git リポジトリルートにフォールバック)からの**相対パス**です。絶対パスとルート外へ出るパスは拒否され、その項目だけ既定値に戻ります。ルートの外かどうかは字句で判定し、symlink の実体がルートの外でも拒否しません。
- 環境変数によるパス指定はありません。共有資産の位置は、リポジトリにコミットされる場所で宣言します。
- 壊れた JSON や未知の `version` でも停止せず、既定値で動作します。

## 他プラグインとの関係

### Codiel

Codiel は **metatron が無くても動きます。** `/codiel:init` は ARCHITECTURE を作りません。ARCHITECTURE が無いか、ドメインマップが読めないときは、`/codiel:run` がドメイン別の境界を設けずに進めてよいかを確かめ、許可されればドメイン分割なしで進みます。metatron を併用すると、`/metatron:init` がシステム概要・ディレクトリ構成・ドメインマップ・テスト方針・禁止事項まで含む前提を作り、Codiel はそれをそのまま利用します。両者が共有するのはファイルの書式だけで、Codiel が metatron のインストール位置を参照することはありません。

Codiel の `capturing-intent` スキルによる ASIS 探索も、ARCHITECTURE を材料に使います。ドメインマップは探索スコープの決定にも使えます。こちらもファイルを直読するだけで、metatron の CLI には依存しません。

## 移行の注意

以前のバージョンを使っていたプロジェクトでは、次を確かめてください。

- 以前の ADR と GOTCHAS の機能は廃止しました。`AMATSUKA_METATRON_ENABLE_ADR` と `AMATSUKA_METATRON_ENABLE_GOTCHAS` は読まれません。`.claude/settings.json` の `env` に書いてあるときは削除して構いません。
- `metatron.config.json` の `paths.gotchas` は無視されます。警告は出ません。
- ARCHITECTURE に `## ADR 一覧` が残っているときは、`/metatron:update` が本文を退避するかを確かめます。退避するなら、削除の前に本文を写してください。
- 0.6.3 までの旧見出し(`## レイヤー構造`・`## ディレクトリ構成と責務`・`## 保護パス`)が残っているときは、`/metatron:update` の「旧構成の移行」で新しい見出しへ移してください。移すまで、旧見出しのセクションへの書き込みは拒否されます。
- `link-claude-md` が過去に `CLAUDE.md` へ足した `@docs/GOTCHAS.md` の行は、metatron は消しません。手で消してください。

## 文書の置き場

- `README.md`(このファイル): 利用者が読まなければこのプラグインを使えない情報
- `docs/rationale.md`: 設計根拠(MCP サーバー化を撤回した経緯を含む)
- `references/`: AI が実行時に読む正本(ARCHITECTURE の書式、ARCHITECTURE と `CLAUDE.md` の境界、設定スキーマ、CLI の使い方、執筆規律)
