# 固定データの採取手順

固定データは Playwright 1.63.0 と Chromium で一度だけ採取する。一時スクリプトから Playwright を読み込み、各 `.html` を `page.setContent` に渡してから `page.ariaSnapshotJSON()` の戻り値を `JSON.stringify(value, null, 2)` で同名の `.json` に保存する。JSON は手で編集しない。

通常モードでは `aria-hidden` 要素は戻り値に含まれず、`ariaHidden` フィールドは AI モードでのみ現れる。Chromium の起動に OS 共有ライブラリが必要な場合は、その依存関係を環境で利用可能にするか、採取コマンドの実行時だけ `LD_LIBRARY_PATH` を設定する。


## MCP サーバーを選んだ理由

- Jev の呼び出しには API キーと HTTP 通信が必要で、スキルの指示だけでは実行できません。ツールを動かす実行主体が必要です。
- ブラウザ系ツールは、ブラウザの状態を保ったまま多数の操作と判断を繰り返します。短命な CLI を操作ごとに起動するより、1 回の呼び出しでループを完結できる常駐プロセスが適しています。
- MCP の入力スキーマを使えば Claude Code がツール呼び出しを組み立てられます。スキルは利用場面や組み合わせ方の説明に集中できます。

## 不採用案

- コミュニティ製 MCP やそのツール体系には依存しません。公式 SDK を使い、判断・ブラウザ・API の用途に合わせた独自のツール群にします。
- 別のブラウザ MCP を経由する構成は採りません。ツール呼び出しの中で操作と判断のループを閉じ、安全装置もコード側で制御するためです。
- セットアップ用シェルスクリプトは同梱しません。Claude Code から呼べる `browser_setup` を使います。Playwright は自身のファイルとブラウザ本体を別に必要とするため、バンドルにも含めません。
- API キーがない場合に CLI へフォールバックしません。経路によって判断の型や提供価値が変わることを避け、テストと説明を一本化します。
- 文書化されていない `aria-ref=` セレクターや、表示向けで解析契約のない YAML のスナップショットは使いません。型付きの `ariaSnapshotJSON()` を使います。
- 特定の他プラグインに固有の概念はツールに持ち込みません。単独でも運用できる構成を保ちます。
- 入力値そのものを判断サービスへ送らず、必要な場合も入力名を使います。
- 送信後に 400 / 422 が返ったリクエストを分割して再送する方式は採りません。追加の課金や往復を避け、事前見積もりに余裕を持たせます。

## 不採用案(OpenAPI 連携)

- 新ツール `api_run_spec_goal` は追加しません。ループ・証跡・終了条件が同じ 2 ツールに分かれ、選び分けと説明の手間が増えます。一覧の出し方と値の作り方の違いは、既存の `api_run_goal` への引数 1 つで表せます。
- ループの複製、または既存ループ内の分岐は採りません。複製は終了条件と記録を 2 か所で直す必要が生じ、分岐にすると複数箇所に散ります。テンプレートと OpenAPI の継ぎ目は、注入点(リクエスト源)の 1 点に集めます。
- OpenAPI 文書の `servers` を送信先や許可ホストの既定にはしません。文書は未信頼の入力であり、文書の作成者が送信先や許可ホストを決められてしまいます。送信先は常に呼び出し側が渡す `baseUrl` とします。
- 本文をフィールド単位で値埋めする方式は採りません。質問数がスキーマの大きさに比例して増え、呼び出し量と予算の見通しが立たなくなります。入れ子の整合を保つ仕組みも必要です。本文を丸ごと選ぶ方式で主な用途は足ります。
- ajv などによる応答のスキーマ検証は行いません。依存が増え、OpenAPI 3.0 と 3.1 の方言差を吸収する手間も生じます。合否は `assertions` と最終判定で決め、ステータスの記録で足ります。
- Swagger 2.0 への対応は行いません。変換ツールで利用者が 3.x へ移行できます。読み込み・本文・認証の規則を 2 系統持つことになります。
- 同一文書の外を指す `$ref`(外部参照)の解決は行いません。取得の連鎖、取得先の制限、循環の検出が複雑になります。バンドル済みの文書であれば足ります。
- `inputs` の型をオブジェクトへ広げる案は採りません。初版の契約と `resolveTemplate` の型が変わってしまいます。JSON 文字列として渡す方式で足ります。

## 実装・保守上の残余リスク

- Jev のトークナイザと事前のトークン見積もりが一致しない場合、上限超過や過剰な分割が起こり得ます。見積もりに余裕を設け、`usage.input_tokens` との比を記録して見直せるようにします。
- Playwright の版上げで `ariaSnapshotJSON()` の形が変わると抽出が失敗する可能性があります。抽出を専用モジュールに閉じ、固定データのテストで守り、キャッシュ版を 1.63 系に固定します。
- MCP サーバーの作業ディレクトリがプロジェクトと異なると、Playwright の解決先や証跡の保存先がずれる可能性があります。プロジェクト環境変数を優先し、実際の実行環境で確認します。
