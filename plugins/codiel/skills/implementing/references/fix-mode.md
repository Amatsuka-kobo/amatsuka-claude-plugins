# 修正モード

test-loop の修正と fix-loop の修正では、次のどちらかの入力を受け取る。

- (a) test-loop の NG 由来。`running-regression-tests` から渡されたケース ID・再現手順・期待結果・実際の結果
- (b) レビュー所見由来。所見(severity・対象・内容・根拠・提案)と対象ファイル

どちらでも、`fixing-failures` スキルの手順で再現、根本原因の特定、最小修正、回帰を行う。
修正後に検証コマンドを再実行し、SKILL.md のコミット規約でコミットする。
「テストの方が間違っている」(期待結果が受け入れ基準と食い違うなど)と判断したときは、`cases.md` やテストコードを書き換えず、修正せずに報告する(ASK の材料にする)。`dev-plan.md` に記載のないファイルの変更が要るときも、無断で広げず報告する。
完了報告は SKILL.md の `## 完了報告` に従う。
