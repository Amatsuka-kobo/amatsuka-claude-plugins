# 持続層への取り込み

承認済みの intent から、領域ごとの持続層(`docs/intents/domains/<領域>.md`)へ制約を取り込む。受け入れ基準等の反映とは別の作業で、intent の `domains` が領域を持つときに読む。

## 手順

1. intent 文書のパスと、取り込み先の領域(intent の frontmatter `domains`)を読み取る。領域が複数あれば、領域ごとにこの手順を繰り返す。
2. 領域ファイルが無ければ、書式の正本(`intent-format.md` の「持続層」セクション)どおりの見出し(`## 失敗の記録` を除く)だけを持つ空のファイルを作る。
3. intent の `## 目的` を読み、領域ファイルの `## 目的` へ取り込む。
4. intent の `## 意図的な制約`(「制約 | 理由」の表)の行を、1 行を 1 件として、領域ファイルの `## 意図的な制約` へ取り込む。行の「制約」列を `- constraint:`、「理由」列を `- reason:` に対応させる。表の行はすべて取り込む。
   - 既存の制約と同じ内容を別の intent が持ち込んだときは、制約を増やさず、その項目に `- sourceIntent: <今回の intent のパス>` の行を加える。
   - 既存の制約と矛盾する内容は、上書きせず、矛盾の内容を書かずにユーザーへ確認する。
   - 改修前の形のエントリ(キーが `制約`・`理由`・`出典 intent` のもの、見出しに `[ADR 候補: <ID>]` の印が付いたもの、`関連 ADR` の行を持つもの)も、通常の制約として読む。上の 2 つの規則のほかには書き換えない。
5. intent の `## 非スコープ` を読み、領域ファイルの `## 非ゴール` へ取り込む。
6. 領域ファイルの `## 由来` に、今回取り込んだ intent のパスを `- docs/intents/YYYY-MM-DD-<slug>.md(取り込み日 YYYY-MM-DD)` の形で 1 行加える。
7. 取り込みで引いた出典があれば、領域ファイルの `## 出典` へ追記する。`## 出典` は常に最後のセクションに保つ。
8. 取り込んだ領域ファイルのパスと、書かずに終えた矛盾を、`.codiel/runs/<slug>/try-<n>/steps/intent-sync/report.md` に書き残す。このファイルはコミットしない。再開では、このファイルがあれば領域ファイルへの取り込みは済んでいる。領域ファイルのコミットは、ゲート通過直後に行う。

intent の `## 合意済み事項` と `design.md` の採用案は、領域ファイルへ取り込まない。
