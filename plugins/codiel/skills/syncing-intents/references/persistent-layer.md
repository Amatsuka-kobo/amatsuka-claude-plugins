# 持続層への取り込み

承認済みの intent から、領域ごとの持続層(`docs/intents/domains/<領域>.md`)へ制約を取り込む。受け入れ基準等の反映とは別の作業で、intent の `domains` が領域を持つときに読む。

## 手順

1. intent 文書のパス、取り込み先の領域(intent の frontmatter `domains`)、`state.knowledgeTarget` の値を読み取る。領域が複数あれば、領域ごとにこの手順を繰り返す。
2. 領域ファイルが無ければ、書式の正本(`intent-format.md` の「持続層」セクション)どおりの見出し(`## GOTCHAS 候補` を除く)だけを持つ空のファイルを作る。
3. intent の `## 目的` を読み、領域ファイルの `## 目的` へ取り込む。
4. intent の `## 意図的な制約`(「制約 | 理由」の表)の行を、1 行を 1 件として、領域ファイルの `## 意図的な制約` へ取り込む。行の「制約」列を `- 制約:`、「理由」列を `- 理由:` に対応させる。
   - 既存の制約と同じ内容を別の intent が持ち込んだときは、制約を増やさず、その項目の `出典 intent` に今回の intent のパスを加える。
   - 既存の制約と矛盾する内容は、上書きせず、矛盾の内容を書かずにユーザーへ確認する。
   - 参照形のエントリは確定済みとして扱い、全文を書き戻さない(参照形とは `関連 ADR: ADR-NNN(候補 ID: <候補 ID>)` の 1 行だけを持つエントリである)。今回の変更がその制約を変える内容なら、書かずにユーザーへ確認する。
   - ADR の 3 条件(覆すコストが大きい・選択肢が実在した・理由が自明でない)を満たす新しい判断は、次の「`knowledgeTarget` による書き分け」に従う。
5. intent の `## 非スコープ` を読み、領域ファイルの `## 非ゴール` へ取り込む。
6. 領域ファイルの `## 由来` に、今回取り込んだ intent のパスを `- docs/intents/YYYY-MM-DD-<slug>.md(取り込み日 YYYY-MM-DD)` の形で 1 行加える。
7. 取り込みで引いた出典があれば、領域ファイルの `## 出典` へ追記する。`## 出典` は常に最後のセクションに保つ。
8. 取り込んだ領域ファイルのパス、書かずに終えた矛盾、finalize の結果レポートに挙げる ADR 候補を、`.codiel/runs/<slug>/try-<n>/steps/intent-sync/report.md` に書き残す。このファイルはコミットしない。再開では、このファイルがあれば取り込みは済んでいる。領域ファイルのコミットは、ゲート通過直後に行う。

## `knowledgeTarget` による書き分け

ADR の 3 条件を満たす判断は、`state.knowledgeTarget` の値で `[ADR 候補]` の扱いを書き分ける。

- `metatron` のとき: 持続層に本文を書かず、`関連 ADR` に番号だけを書く形を将来のために残す。判断の内容は領域ファイルへ書かず、`steps/intent-sync/report.md` に ADR 候補として書き残し、finalize の結果レポートで挙げる。内容は、タイトル・制約・背景・選択肢・結論・理由・影響範囲である。
- `intents` のとき: 該当する領域ファイルの `## 意図的な制約` に、`[ADR 候補: <候補 ID>]` の形で全文を書く。候補 ID は `codiel-state next-adr-candidate-id --file <領域ファイルのパス> --domain <正規化後の領域名>` を呼んで得る。出力の `candidateId` を、そのまま候補 ID に使う。

新しい ADR 級の判断を見つけたら、新しい候補 ID で新しいエントリとして書く。既存の参照形のエントリは書き換えず、候補 ID も使い回さない。
