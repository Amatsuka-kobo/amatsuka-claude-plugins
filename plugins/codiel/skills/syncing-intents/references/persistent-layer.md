# 持続層への取り込み

承認済みの intent から、領域ごとの持続層(`docs/intents/domains/<領域>.md`)へ制約を取り込み、今回の変更で古くなった記述を改訂・削除する。受け入れ基準等の反映とは別の作業で、intent の `domains` が領域を持つときに読む。

## 手順

1. intent 文書のパスと、取り込み先の領域(intent の frontmatter `domains`)を読み取る。下の「再開」に従って済んだ領域を除き、残りの領域に手順 2〜6 を行う。手順 2 を全領域に行ってから手順 3 に進む。順序は、全領域の手順 2、1 回の手順 3、全領域の手順 4、1 回の手順 5、領域ごとの手順 6 とする。
2. 領域ファイルが無ければ、書式の正本(`intent-format.md` の「持続層」セクション)どおりの見出し(`## 失敗の記録` を除く)だけを持つ空のファイルを作る。
3. `orchestrating-runs` の `references/failure-records.md` の「持続層への写し」の intent-sync の規則に従い、未写しの失敗の記録を領域ファイルへ写す。取り込み先でない領域への incident の記録の写しも、このときに行う。写しの規則はそのファイルが正本である。写した incident の記録は、1 件ごとに report.md へ `写し:` の行で残す。
4. 領域ファイルを読み、次の 3 つを洗い出す。どれも、まだ書かない。
   - 既存の制約と矛盾する、intent の `## 意図的な制約` の行。
   - 今回の変更で古くなった既存の記述。下の「古い記述の洗い出し」に従う。
   - run の差分だけが既存の制約と食い違う違反。下の「古い記述の洗い出し」に従う。
5. 手順 4 で 1 件以上を洗い出したら、`codiel-state mark-ask intent-sync --slug <slug> --kind confirm` で `awaiting_human` にし、AskUserQuestion で 1 件 1 問にして聞く。1 回の呼び出しで聞くのは 4 問までとし、残りは続けて聞く。全件の答えを受けてから `codiel-state resume --slug <slug>` で戻す。
   - 矛盾は、既存の項目と intent の行を並べて示し、選択肢を「今回の intent に合わせて既存の項目を書き換える」「既存の項目を保ち、今回の行を取り込まない」にする。
   - 古い記述は、既存の文面と、改訂後の文面か削除の案を示し、選択肢を「案のとおり書く」「書き換えずに残す」にする。
   - 同じ項目が矛盾と古い記述の両方に当たるときは、1 問にまとめて矛盾として聞く。古い記述の案が矛盾の書き換えと異なるときは、その案を 3 つ目の選択肢に加える。
   - 違反は、制約と食い違う差分の箇所を示し、選択肢を「制約を保ち、review に任せる」「intent に合意を足してから制約を改訂する」にし、前者を推奨にする。後者の答えでは、ユーザーの答えを intent の原文(`## TOBE`)の末尾に日付・話者・出所つきで追記し、`SKILL.md` の手順 3 と 4 で派生文のセクションと `## 変更履歴` へ反映する。その後に、制約を改訂する案を古い記述として同じ確認の中で聞く。
   - どの問いも、推奨する選択肢を先頭に置き、ラベルの末尾に「(推奨)」と付ける。選択肢の外の答えも受け、その内容で書く。
   - `resume` の後に intent をもう一度読み、`domains` が手順 1 の値から変わっていたら、加わった領域だけを手順 2 から行う。外れた領域には書かず、手順 2 で作ったファイルを消し、手順 3 でその領域ファイルへ写した記録を消して元に戻し、その領域の `写し:` の行を report.md から消す。手元の記録には `写し先` の行がまだ付いていないので、後の run が写し直す。
6. 領域ファイルに次の順で書き、書き終えた直後にその領域の行を report.md へ追記する。
   1. intent の `## 目的` を、領域ファイルの `## 目的` へ統合する。下の「目的と非ゴールの統合」に従う。
   2. intent の `## 意図的な制約`(「制約 | 理由」の表)の行を、1 行を 1 件として、領域ファイルの `## 意図的な制約` へ取り込む。行の「制約」列を `- constraint:`、「理由」列を `- reason:` に対応させる。手順 5 で取り込まないと答えた行を除き、表の行はすべて取り込む。
      - 既存の制約と同じ内容を別の intent が持ち込んだときは、制約を増やさず、その項目に `- sourceIntent: <今回の intent のパス>` の行を加える。
      - 手順 5 で書き換えると答えた矛盾は、既存の項目の `constraint` と `reason` を今回の行の内容へ書き換え、`- sourceIntent: <今回の intent のパス>` の行を加える。新しい項目は作らない。
      - 手順 5 で既存の項目を保つと答えた矛盾は、取り込まず、report.md の「書かずに終えた矛盾」に書く。
      - 手順 5 で 3 つ目の選択肢(古い記述の案)を選んだ矛盾は、今回の行を取り込まず、古い記述の案を手順 6 の 4 で書き、report.md の「書かずに終えた矛盾」にその行を載せる。
   3. intent の `## 非スコープ` を、領域ファイルの `## 非ゴール` へ統合する。下の「目的と非ゴールの統合」に従う。
   4. 手順 5 で承認された古い記述の改訂と削除を書く。
      - 制約の改訂は、`constraint` と `reason` を今の姿へ書き換え、`- sourceIntent: <今回の intent のパス>` の行を加える。
      - 失敗の記録の改訂は、`task`・`mistake`・`cause`・`countermeasure` を書き換え、`date` と `run` は変えない。
      - `## 目的`・`## 非ゴール` の改訂・削除は、項目(箇条書きの 1 行)を書き換えるか消す。
      - 制約と失敗の記録の削除は、エントリを `###` 見出しごと消す。
      - 項目やエントリの一部だけを消したときは、改訂として扱う。
      - 最後の項目・エントリを消したセクションは、見出しだけを残し、本文を書かない。「なし」とは書かない。
   5. 領域ファイルの `## 由来` に、今回取り込んだ intent のパスを `- docs/intents/YYYY-MM-DD-<slug>.md(取り込み日 YYYY-MM-DD)` の形で 1 行加える。既存の記述を改訂・削除したときは、その行の末尾に `intent-format.md` の「持続層」の形で添え書きを付ける。同じ intent の行が既にあれば、行を加えず、その行の末尾に添える。その行に添え書きが既にあれば ` ; ` で区切って後ろに足し、無ければ区切りを置かずにそのまま続ける。
   6. 取り込みで引いた出典があれば、領域ファイルの `## 出典` へ追記する。`## 出典` は常に最後のセクションに保つ。
7. 領域ファイルのコミットは、ゲート通過直後に行う。改訂と削除も、追加の取り込みと同じコミットに入れる。report.md はコミットしない。

`sourceIntent` の行を加えるときは、同じ intent のパスの行が既にある項目には加えない。

改修前の形のエントリ(キーが `制約`・`理由`・`出典 intent` のもの、見出しに `[ADR 候補: <ID>]` の印が付いたもの、`関連 ADR` の行を持つもの)は、通常の制約として読み、同じ内容の制約への `sourceIntent` の追加のほかには書き換えない。例外は次の 2 つである。

- 手順 6 の 2 の矛盾の書き換えと手順 6 の 4 の改訂では、今の書式(英語のキー、印と `関連 ADR` の行を外す)で 1 つの項目に書き直す。
- 手順 5 で承認された削除では、エントリを消す。

intent の `## 合意済み事項` と `design.md` の採用案は、領域ファイルへ取り込まない。

Raguel の ASK の裁定 A で領域ファイルを直したときは、直した内容に合わせて、その領域の report.md の行と `## 由来` の添え書きも直す。

## 目的と非ゴールの統合

`## 目的`・`## 非ゴール` の項目の単位は、箇条書きの 1 行である。

- 承認なしで行えるのは、新しい項目の追加と、文面が同じ項目の重複の除去だけである。
- 既存の項目の意味か文面を変えるもの(書き換え・削除・複数の項目を 1 つにまとめること)は、手順 4 の洗い出しの案に出し、手順 5 で承認を得てから書く。
- 既存の記述が箇条書きでないときは、箇条書きへ移す改訂の案を 1 件出す。承認されなければ、既存の文章をそのまま残し、追加する項目だけを箇条書きで足す。

## 古い記述の洗い出し

洗い出しの材料は、今回の intent と、`design-docs.md` の「入力」と同じ `design.md`(軽量の run では intent の `## 実装方針`)と run の差分である。差分の範囲も「入力」と同じにする。材料に照らして事実でなくなった記述を、古い記述とする。

- 対象のセクションは `## 目的`・`## 意図的な制約`・`## 非ゴール`・`## 失敗の記録` である。対象の領域は、取り込み先の領域に限る。
- `## 意図的な制約` が古いかは、今回の intent と `design.md`(軽量の run では intent だけ)で合意した内容だけで判定する。run の差分だけが制約と食い違うときは、古い記述の案にせず、違反として洗い出す。
- 次の失敗の記録は対象にしない。前の try や中断の前に写したエントリも、これで見分ける。
  - 今の run(slug)のすべての try の手元の記録と、見出し・`mistake` が同じエントリ。
  - この intent-sync の手順 3 で写した incident の記録。report.md の `写し:` の行の見出しで見分ける。
- 改修前の `## GOTCHAS 候補` は対象にしない。
- `## 目的`・`## 非ゴール` で意味の重なる項目は、1 つにまとめる案を出す。
- try-2 以降では、同じ intent の `## 由来` の添え書きにある、前の try の改訂・削除も対象にする。今回の intent と食い違うときは、git の履歴の文面に戻す書き戻しの案を出す。書き戻しは、report.md と `## 由来` では改訂として書く。
- 今回の変更と関係の無い記述は、内容が古く見えても案にしない。
- 1 件ごとに、改訂か削除のどちらかの案を作る。記述の一部がまだ事実なら改訂、全体が事実でなくなったら削除にする。

案の例を示す。

- 今回の intent が、`## 非ゴール` に書かれた機能を実装した。その項目を削除する案にする。
- 今回の差分が、失敗の記録の `cause` にある仕組みを取り除いた。そのエントリを削除する案にする。
- 今回の intent が、制約の `reason` の前提を変えたが、制約そのものは今も守る。`reason` を書き換える改訂の案にする。

## report.md の形

`.codiel/runs/<slug>/try-<n>/steps/intent-sync/report.md` に、領域ごとに次の行を追記する。ファイルが無ければ作る。値は例であり、実際のパスと記述に置き換える。記述の名指し方は、`intent-format.md` の「持続層」の添え書きと同じにする。

```markdown
写し: docs/intents/domains/billing.md / 「## 失敗の記録 / 請求の締め日がずれる」
取り込み: docs/intents/domains/auth.md
改訂: docs/intents/domains/auth.md / 「## 意図的な制約 / セッションの保存先」
削除: docs/intents/domains/auth.md / 「## 非ゴール / 管理画面からの一括削除」
見送り: docs/intents/domains/auth.md / 「## 失敗の記録 / ログアウト後にフォームが消える」
書かずに終えた矛盾: docs/intents/domains/auth.md / なし
違反: docs/intents/domains/auth.md / 「## 意図的な制約 / トークンを保存領域に置かない」 / 制約を保ち、review に任せる
```

- `写し` の行は手順 3 で書き、領域の行とは別に置く。
- `取り込み` の行を最初に書き、その領域の行の始まりとする。
- `違反` の行には、手順 5 の答えを末尾に添える。
- `改訂`・`削除`・`見送り`・`書かずに終えた矛盾`・`違反` は 1 件 1 行で書き、無ければ領域ファイルのパスの後に「なし」と書く。
- `見送り` には、手順 5 で書き換えずに残すと答えた古い記述を書く。
- 選択肢の外の答えは、書いた結果に応じて `改訂`・`削除`・`見送り` のどれかの行に載せる。どれにも当たらないときは `見送り` に載せ、行の末尾に答えの要旨を添える。

## 再開

- report.md に `取り込み` の行がある領域は、済んだものとして飛ばす。
- 行が無い領域で、`## 由来` に今回の intent の行があり、その行が HEAD の領域ファイルに無い(未コミットの変更である)ときは、取り込み済みとして手順 2〜6 を飛ばす。添え書きのうちこの try で付けた部分(HEAD のその行に添え書きがあれば最後の ` ; ` より後、無ければ添え書きの全体)から、その領域の `取り込み`・`改訂`・`削除` の行を復元して report.md に追記し、`見送り`・`書かずに終えた矛盾`・`違反` は「なし」とする。
- 上のどちらにも当たらない領域は、手順 2 から行う。
- 取り込み先の全領域の `取り込み` の行がそろったら、領域ファイルへの取り込みは済んでいる。
