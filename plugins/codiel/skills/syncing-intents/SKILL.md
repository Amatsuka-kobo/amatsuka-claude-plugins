# intent-sync 運転規約

## 概要

intent-sync フェーズでオーケストレーターが使うスキルである。このフェーズは 2 つの作業を担う。

- 書き戻し: 実装中に承認された受け入れ基準の変更と、intent-sync より前のフェーズで原文(`## ASIS` / `## TOBE`)の末尾に追記された要望を、intent 文書の派生文のセクションへ書き戻し、`## 変更履歴` に 1 行加える。書く時点で、内容は人の確認を終えている。この確認は、このスキルの手順の前にオーケストレーターが行う。
- 持続層への取り込み: 承認済みの intent の `## 目的` / `## 意図的な制約` / `## 非スコープ` を、領域ごとの持続層(`docs/intents/domains/<領域>.md`)へ取り込む。

## 担い手の分担

書き戻しと持続層への取り込みは、オーケストレーターが自分で書く。書く前の確認、state の操作、書き戻し後のコミットも同じオーケストレーターが行う。

- 書き戻す範囲を洗い出し、`codiel-state mark-ask intent-sync --slug <slug> --kind confirm` で run を `awaiting_human` にして、反映内容をユーザーに確認する。確認を終えたら `codiel-state resume --slug <slug>` で `in_progress` に戻す。
- 書くのは、確認済みの反映内容だけである。確認の無い内容に気づいたら、書かずにユーザーへ確認する。
- 原文のセクション(`## ASIS` / `## TOBE`)は読むだけで、書き換えない。
- このスキルで呼ぶ `codiel-state` は、確認のための `mark-ask` と `resume`、候補 ID を採番する読み取り専用の `next-adr-candidate-id` に限る。
- 書き戻し後の intent 文書のコミットは、ゲート通過直後に行う。

## 共通規律

- intent 文書の書式は `../../references/intent-format.md` に従う。原文のセクションと派生文のセクションの区別、`## 変更履歴` の記録方法はここに従う。
- 派生文のセクションへ書く文は `../../references/intent-writing.md` の文の組み立ての規則に従う。原文のセクションには適用しない。
- 領域ファイル(持続層)の書式は `../../references/intent-format.md` の「持続層」セクションに従う。5 つのセクションの構成、`[ADR 候補]` の書式、候補 ID の採番規則、参照形への縮約はここが正本である。

## 手順

1. intent 文書のパスと、確認済みの反映内容(受け入れ基準の変更点、反映する原文の追記の範囲、それぞれの反映先セクション)を読み取る。
2. 承認済みの受け入れ基準の変更を書き戻す。変更点を `## 受け入れ基準`(変更の性質によっては `## 要求` や `## 実装方針` など、関係する派生文のセクション)へ、確認済みの内容のとおりに反映する。要約や言い換えで内容を変えない。
3. intent-sync より前に原文へ追記された要望を派生文のセクションへ反映する。反映先は `## 現状調査` や `## 要求` など、追記の内容に対応するセクションである。反映する範囲は確認済みの範囲に限り、まだ確認されていない追記には触れない。
4. `## 変更履歴` に 1 行加える。行には、日付・セクション名・変更内容の要約・承認の経路(Raguel の evaluationId、`mark-ask --kind confirm` による確認である旨など)を書く。intent の `status` は変えない。`done` は finalize だけが判定して付ける。
5. 書き戻した箇所(ファイルパスとセクション名)を確かめる。
6. 持続層への取り込みへ進む。intent の `domains` が空のときは、取り込みを行わずに終える。finalize の結果レポートに、取り込みを行わなかった理由(取り込み先の領域が空)と、intent の `## 意図的な制約` に行があったかを書く。`domains` が空でないときは、`references/persistent-layer.md` を Read して従う。持続層の既存の制約と矛盾する内容に気づいたら、確認を待たずに上書きせず、`mark-ask --kind confirm` の後にユーザーへ確認し、確認の結果を受けてから書く。

## `## 変更履歴` の記録例

値は例であり、実際の日付・セクション名・内容・承認の経路に置き換える。

```markdown
## 変更履歴

- 2026-10-05 / `## 受け入れ基準` / 「保存状態を画面右上にも表示する」を追加 / `mark-ask --kind confirm` で確認済み
```
