# 入口ごとの取り込み

手順 2 で、起動時の引数が Issue 番号・intent パスのどちらかのときに読む。

## Issue 番号

github モードでは `gh issue view`、読めなければ GitHub MCP の読み取りで本文とコメントを得る。local モードではユーザーに本文を貼ってもらう。正本は以後 intent 文書になる。

- 本文にあるマーカーで原文と派生の扱いを決める。対応は `intent-format.md` の「intent-issue の本文」に従う。
- 人が書いたコメントは、話者と日付つきで原文のセクションに記録する。bot のコメントと `<!-- codiel:generated -->` を持つコメントは除く。
- 取り込んだ記録のうち原文から除くものは、手順 4 の承認ゲートでユーザーが選ぶ。

## intent パス

手順 0 と同じ照合(frontmatter の `run` と state の `intent`)で未終端の run が見つかれば、`orchestrating-runs` の `references/resume.md` でその run を続ける。state の `intent` だけで当たった run は、内容(slug・intent のパス・現在のフェーズ)を示してユーザーに確かめてから続ける。

- 照合する run が無く、作業ツリーにも intent のファイルが無いときは、パスが無いことを示してユーザーに確かめる。
- run が無くファイルがあれば、記載済みの内容を確定扱いにして、聞き取りの不足分から手順 3 を始める。

## intent パスで frontmatter が `intent: v1` のとき

v2 へ昇格して再開する。変換は `intent-format.md` の v1 から v2 への変換に従う。

- 既存のセクションは確定済みとして扱い、不足する原文の `## ASIS` / `## TOBE` と、`## 目的` と `## 意図的な制約` だけを聞き取る。原文はユーザーに尋ねて、ユーザーの言葉のまま埋める。
- 昇格したドラフトを全文提示し、手順 4 の承認ゲートを取り直す。
- 保存は元のパスへの上書きとし、`## 変更履歴` に v1 からの昇格を 1 行記録する。
