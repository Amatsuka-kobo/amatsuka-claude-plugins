# NG ケース修正(systematic-debugging)規約

## チェックリスト

1. 入力系統を確認する。(a) test-loop の NG 由来なら `running-regression-tests` から
   渡された NG ケースの 4 項目(ケース ID・再現手順・期待結果・実際の結果)、(b) レビュー所見由来
   なら `fixing-review-findings` から渡された所見(severity・対象・内容・根拠・提案)+ 対象ファイル
   が揃っているか確認する。いずれかが欠けている場合、推測で埋めず、差し戻し元(オーケストレーター
   経由で `running-regression-tests` または `fixing-review-findings`)に不足分の提示を求める。
2. **再現する**: 依頼文が最新の E2E のレポート(`failure.md`・`results.json`・画像)の絶対パスを渡したときは、
   それらを読み、以前の状態と失敗の出方から直し方を決める材料にする。
   (a) test-loop の NG 由来では渡された再現手順どおりに手を動かし(または既存のテスト
   を実行し)、実際の結果が報告どおりに再現することを確認する。(b) レビュー所見由来では
   指摘された問題を該当ファイル・行で再現・確認する(`fixing-review-findings` で検証済みの根拠を
   引き継ぎ、ゼロから調べ直さない)。いずれの系統でも再現しない場合は、環境差・タイミング差・
   認識違いの可能性を疑い、再現条件を絞り込むまで根本原因の特定に進まない。
3. **根本原因を特定する**: コード・ログ・実行結果を読み、原因を**1 文で言語化**する
   (例:「`formatDate` がタイムゾーンを考慮せず UTC のまま表示している」)。
4. **裏取りする**: 3 で言語化した原因が正しければ再現手順の結果を説明できるはずである。
   実際にその原因が成立している箇所(該当コード・該当ログ)を指し示して確認する。
   説明できない場合は原因の仮説が誤りであり、2 に戻ってさらに調べる(先に進まない)。
5. **最小修正を実装する**: 3〜4 で特定した原因を解消する最小限の変更のみを行う。
   原因と無関係な箇所の「ついでの修正」は行わない。
   例外を `catch` して握り潰す、エラーを無視して処理を続行させる、タイムアウトを延長するだけで待機条件を直さない、といった「NG という表示だけを消す」修正は、根本原因を放置したまま偽装したパスなので行わない。
6. **対象の解消を再確認する**: 系統 (a) では修正した NG ケースを再実行し OK になることを、
   系統 (b) では指摘された事象が解消したことを(手順 2 で再現に使った方法の再実行で)、
   いずれも実際の実行出力で確認する(見た目で「直ったはず」と判断しない)。
7. **回帰(全件)を再実行する**: 対象ケースの修正が既存の他ケースを壊していないか確認するため、`running-regression-tests` の回帰の範囲全体を自分で実行する。`running-regression-tests` から参照するのは範囲だけで、実行の担い手の記述(オーケストレーターと `e2e/` の委譲先の分担)には従わない。対象ケースだけの再実行で完了としない。回帰で別ケースが壊れた場合は手順 2 に戻る。3 巡しても収束しないときは修正を止め、
   オーケストレーターへ差し戻す。回帰の実行で環境の失敗が出たら、broken・NG のどちらにも数えず、
   理由と出力の抜粋を完了報告に挙げる。
8. 検証コマンド・回帰結果が揃ったら、`implementing` のコミット規約(`codiel(test-loop): <修正内容>
   (<slug> try-<n>)` または `codiel(fix-loop): <修正内容> (<slug> try-<n>)`。呼ばれたフェーズ名に
   合わせる)でコミットし、完了報告(下記)を最終の返答に書く。報告のファイルは書かない。

## 「最小修正」の判断基準

- 3〜4 で特定した根本原因と、変更したコードの行が **1 対 1 で対応している**ことを自分で説明できるか。
  説明できない変更(「念のため」「たぶん関係ある」)は最小修正ではない。

## 完了報告

`implementing` の `## 完了報告` に従う。加えて次の項目を含める。

- 根本原因(手順 3 で言語化した 1 文)
- 対象ケースと回帰の再実行結果
- 失敗が E2E の仕様のディレクトリのものなら、直した実行ごとのディレクトリの名前と直し方
