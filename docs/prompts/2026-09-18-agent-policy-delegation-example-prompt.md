# agent-policy の委譲依頼における説明用例示を扱う規律の実装プロンプト

以下を goal コマンドの入力として使う。

---

`plugins/agent-policy/references/orchestration-discipline.md` の文書作成を委譲する規律を見直し、説明のための例示が成果物の要件として混入しないようにせよ。最初に `harness-docs/handover/2026-09-18-agent-policy-delegation-example-handover.md` を全文読み、確定事項、未決定の検討点、スコープを守ること。

この昇格は、ユーザーが急を要する課題と判断して指示した例外である。同種の昇格候補が 5 件に達していないことを理由に差し戻さないこと。

## 目的

文書作成を委譲する依頼文で、成果物の本文に書く例示と依頼を説明するためだけの例示を区別できる規律を定める。説明用の例示が、本文の列挙や閉じた集合として成果物へ入る失敗を防ぐ。

現行の L74–75 は、依頼文に書ける事項と、対象ファイルの文体による段落または貼り付け可能な完成文を禁じている。単語レベルの説明用例示は、許可も禁止もされていない。この空白を扱う。

## 確認済みの事実

- 同一セッションで、説明用の例示が成果物へ 3 回連続して混入した。委譲先の不遵守ではなく、依頼文が例示の扱いを確定していなかったことが原因である。
- 1 回目の「`description` が使う語だけで問を作らない」では、対象を指す `agents/` まで問から外れ、正解ラベルが成立しなくなった。2 回目の「行為を指す語を避ける」では、実際の依頼で最も使われる語が全問から消えた。3 回目の「（『レビュー』『監査』『評価』のような）」では、3 語が本文の列挙として書かれた。
- `harness-docs/GOTCHAS.md` の `GOTCHA-002` は昇格候補 Yes である。`plugins/metatron/references/gotchas-format.md` は同種のパターンが 5 件以上たまったときにスキルまたは Hook への昇格を検討すると定め、現在の昇格候補は 2 件であり下限未満である。
- それでもユーザーは、同一セッションでの 3 回連続の発生頻度、AI 向け指示書の改訂が頻繁な作業であること、誤った内容が気づかれず残り得ることを理由に、急を要する課題として例外的な昇格を指示した。

## 検討する点

1. 例示を L74 の許可リスト、L75 の禁止事項、または別の条項のどこで扱うか。
2. 本文に書く例と説明だけの例を、依頼文でどう書き分けるか。書式または注記の文言を定めるか。
3. `plugins/*/skills/*/SKILL.md`、`plugins/*/references/`、`.claude/rules/` の項目を書き換える依頼で、語の例を渡さず判断の軸だけを渡すことを規律にするか、推奨にとどめるか。

案を本プロンプトの記載だけから結論として扱わず、選んだ方針と根拠を報告すること。

## 影響範囲と制約

- 主な変更対象は `plugins/agent-policy/references/orchestration-discipline.md` である。AI 向け指示書の編集では `prompt-smith:prompt-smith` の規律に従うこと。
- 同種の条項が `plugins/agent-policy/assets/roles/ja/_common.md` と `plugins/agent-policy/assets/roles/en/_common.md` にある。両言語を整合させ、英語側は `compose.test.ts` の英語純度検査を満たすこと。
- 規律本文の変更は `src/agents/__test__/discipline-role-table.test.ts` の直接の対象ではないが、節見出しを増やすと `extractRoleBandSection` の走査範囲へ影響する可能性がある。
- `agent-policy` の `plugin.json` と `package.json` のバージョンを、現在の `0.19.4-dev` から同じ値へ上げること。
- `pnpm run test` を実行すること。
- 担当表、役割の定義、委譲先の解決順、`prompt-smith` の測定基盤、`GOTCHA-002` の内容自体は変更しないこと。

- 日本語・英語の共通 role 文書への追随内容
- バージョン変更、実行した検証、変更したファイル
- 未決定または残る懸念
