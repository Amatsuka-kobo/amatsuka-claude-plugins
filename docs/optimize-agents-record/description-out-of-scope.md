# description を prompt-smith の対象外とする根拠

`prompt-smith` は AI 向け指示書の本文だけを対象とし、frontmatter の description を対象外とする。その根拠となる実測結果をまとめた人間向けの参照文書である。

## 本文と description では最適化の目標が違う

本文は、読んだ AI の振る舞いを決める。冗長な記述は判断を鈍らせ、根拠や言い換えは振る舞いを変えないまま入力トークンを消費するので、削ることが効く。

description は、そのスキルを読むかどうかだけを決める。読まれなければ本文の質は一切影響しない。したがって簡潔さより発火の確実性が優先される。

## 実測(2026-08-01, task-utility の 6 スキル)

`prompt-smith` の基準で本文を整えた際、description にも同じ基準で負の境界(「明示的な依頼があったときのみ使い、自律的には発動しない」)を加えた。この形で発火精度を測ったところ、誤発火は 6 スキル・72 問すべてでゼロだった一方、発火漏れが 48 問中 4 件残った。

漏れたのはいずれも口語の省略形である。

- chat: 「この設計議論、記録に追記しといて」
- issue-craft: 「さっきの改善案、issue にしといて」

`skill-creator` の基準で description を書き直した際は、口語の言い回しを例示として足す(pushy 化)ことと、対象範囲を限定することを同じ改稿で行った。結果は改善 2 件・悪化 0 件で、pushy 化しても誤発火は増えなかった。

総合スコアは 158/168 から 161/168 に改善した。

## 削る基準を description に当ててはならない理由

description における「重複」や「言い換え」は、本文とは働きが異なる。同じ意図を別の言い回しで重ねて書くことが、多様な依頼文への一致を増やす。本文の基準で「重複」として削ると、その分だけ発火する依頼の幅が狭まる。

例示も同様である。本文では「例は 1 つで伝わるなら 2 つ目以降を削る」が成り立つが、description の例示は理解のためではなく一致のためにあるので、削ると効果が落ちる。

## 測定手順

発火精度の測定は `optimize-agents:skill-eval` が担当する。手順とスクリプトの使い方はそちらにある。

skill-creator の `run_eval.py` は測定対象を `.claude/commands/` に登録するため現行の Claude Code では発火を検出できない。詳細は `plugins/task-utility/evals/README.md` に記録がある。

## 追記(2026-08-02): 圧縮と一般化は正例だけを落とす

skill-creator の description 生成基準(個別クエリを列挙せずカテゴリへ一般化、100-200 words へ圧縮)を、optimize-agents 3 スキル 80 問で現行方針と比較測定した。

| 種別 | 現行方針 | skill-creator 流 | 差 |
| --- | ---: | ---: | ---: |
| trigger | 21/24 | 17/24 | -4 |
| short | 22/24 | 14/24 | -8 |
| fp | 30/32 | 30/32 | ±0 |
| 計 | 73/80 | 61/80 | -12 |

fp は 32 問すべてで発火回数まで一致した。**圧縮は誤発火の抑制に寄与せず、正例だけを失う。**

この文書が主張する「description の削減基準は本文と別」という判断が、外部の対抗案との比較でも支持された。詳細は `skill-creator-intake.md`。

## 追記(2026-08-02): 別種の対象を指す例示は正例の発火を落とす

commands を対象範囲へ加える改稿で、`prompt-smith` の description に「対象列挙への追記」と「依頼文の例示 3 種」を同時に足したところ、`evals/trigger/prompt-smith.json` の発火が落ちた。

| 構成 | 結果 |
| --- | --- |
| 改稿前 | 3/3 |
| 改稿前の description + 改稿後の本文 | 3/3 |
| 改稿後の description(例示 3 種を含む) | 1/3 |
| 対象列挙のみ追記(例示なし) | 8/8 |

本文の改稿は発火に影響しない。原因は description に足した別ドメインの例示である。

この文書が記録している「description の例示は一致の幅を広げる」という性質は、**同じ対象を指す言い換え**について成り立つ。対象そのものを広げる例示には成り立たない。区別は `references/description-guide.md` の §対象を広げるとき に規律として書いた。

## 基準の導出範囲(2026-08-02 時点)

`references/description-guide.md` の基準は、skill の発火精度を 168 問で測って導いたものである。

Agents 定義については同じ測定を行っていない。同ガイドの §Agents 定義での違い は Anthropic 公式ドキュメントの記述に基づく準用であり、このリポジトリでの実測はない。方向は一致している(公式も発火を強める句を推奨している)。

`<example>` ブロックを使わない判断も、効果を測った結果ではなく、公式ドキュメントに記述がないことによる。詳細は `agent-creator-rationale.md`。

Agent が呼ばれる経路は、オーケストレーターが担当表を見て選ぶものが主である。このため作業種別と隣接 Agent との境界を書く方針をとっている。

## description の担当(2026-08-02 以降)

`prompt-smith` が description を対象外としたことで生じる空白は、次の 2 スキルが埋める。

| 対象 | 担当 |
| --- | --- |
| SKILL.md の description | `skill-eval` |
| Agent 定義の description | `agent-creator` |

どちらも `references/description-guide.md` を基準として参照する。
