## セッション 1: プラグインスクリプトのコンテキスト消費について

# phyllis998

> Claude Codeにプラグインを導入するとき、モデルのコンテキストにプラグインが持つスクリプトファイルの情報は入りますか？入る場合、そのスクリプトのサイズがコンテキストや使用トークン量を増加させることはありますか？

# AI

**結論**: プラグインが持つスクリプトファイルの中身(ソースコード)がモデルのコンテキストに自動で読み込まれることは基本的にない。トークン消費に効いてくるのは「スクリプトが吐き出す出力」であって、「スクリプト自体のサイズ」ではない。

Claude Code の公式ドキュメントベース(claude-code-guide エージェント経由)で確認した、コンポーネント種別ごとの詳細な挙動:

- **Skills**: SKILL.md の frontmatter(name/description)のみセッション開始時にロード。本文は Skill ツールで invoke した時だけ。参照ファイルは明示的に Read しない限り読まれない。
- **Agents**: description のみ起動時にロード。本体の system prompt は起動された Agent 自身の隔離された context window 内でのみ展開。親セッションのコンテキストに混ざらない。
- **Commands**: 一覧に名前程度。本文は実行時に展開。
- **Hooks**: ソースコード自体は読まれず、シェル/インタプリタが直接実行。モデルが見るのは stdout/stderr のみ。
- **plain scripts**(node script.mjs 等): 同様に出力のみ。
- **MCP サーバー**(raguel-mcp 等の TypeScript 実装): ツール名のみ deferred でロード。実装ソースはプロセスとして別プロセスで動くだけで、コンテキストには現れない。`ToolSearch` で該当ツールを呼んだ時に、そのツールの JSON Schema だけがロードされる。

**例外的にサイズが効いてくるケース**:
- スクリプトの実行結果(stdout)が巨大な場合(例: 冗長なログ、ファイル内容を丸ごと cat)
- コマンドや Skill の Markdown 本文にスクリプトのコードをベタ書きで埋め込んでいる場合
- モデルが Read ツールでスクリプトファイルを明示的に開いた場合(デバッグ目的など)

**このプラグインリポジトリでの実装例との対応**:
raguel-mcp(TypeScript MCP サーバー)や scripts/ 配下のスクリプトがどれだけ肥大化しても、それ自体がコンテキストや通常のトークン消費を増やすことはない。増えるのは MCP ツールが返す tool_result の中身(例: ゲーティング結果の JSON)や、スクリプトが console.log で吐く出力が大きい場合のみ。これは CLAUDE.md に記載の「LLM の処理はメインセッション/サブエージェント/claude CLI headless 実行に閉じる」という制約とも整合している。

**トークン使用量の確認方法**: `/context` コマンドで現在のセッションの内訳を確認できる。
