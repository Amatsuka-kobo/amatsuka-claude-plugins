**何をしたか**：CLAUDE.md のエージェント運用方針と、実際の agents 定義（codex/ 配下の GPT エージェント＋旧 `.claude/agents/`）の整合を検査。各ファイルを確認し、方針との乖離箇所を特定した。

**検査の構成**：
- CLAUDE.md の「エージェント運用方針」節（セッション全体・レビュー・設計・コーディング・その他）と対比

**検査結果サマリー**：大部分は整合しているが、方針の直近変更が gpt-sol の定義に追従していない不整合が 1 件、および配置に関する注意点が 1 件見つかった。

**不整合 1（要修正）：gpt-sol の「複雑な作業」表現が方針変更後の文言と乖離（中程度）**

CLAUDE.md は直近の変更で「**複雑な**レビュー・調査・分析は GPT Sol」→「**通常の**レビュー・調査・分析は GPT Sol」に改められている（軽いものは Opus）。しかし定義側は旧方針のままである：

- `codex/gpt-sol.md:3` — description「レビュー・調査・分析など**複雑な作業**を委譲するとき」
- `codex/gpt-sol.md:9` — 本文「**複雑な知的作業**を単独で遂行」

description はメインセッションが委譲先を選ぶトリガー文なので、「複雑なとき」という条件が残っていると、通常レベルのレビュー・調査で GPT Sol が選ばれにくくなり、方針（通常は GPT Sol / 軽いものだけ Opus）と実挙動がずれる。「通常のレビュー・調査・分析（軽いレビュー・調査・分析は `Opus` を使う）」に沿った文言への更新を推奨する。

**不整合 2（軽微〜中）：設計書・実装計画書の Haiku レビュー工程が gpt-sol に未反映**

CLAUDE.md「設計・実装計画」節の「設計書・実装計画書はまず Haiku にレビューさせる」という工程が、gpt-sol の「実装オーケストレーションの方針」の委譲マトリクス（codex/gpt-sol.md:26-32）に含まれていない。GPT Sol が実装オーケストレーション中に計画書を作る場面があるなら、マトリクスへの 1 項目追加を推奨する（この工程を Fable 側の責務と割り切るなら現状維持でも可）。

**注意点（構成）：`codex/` は Claude Code のエージェント自動発見パスではない**

エージェントの発見対象は `.claude/agents/`・`~/.claude/agents/`・プラグインの `agents/` のみで、`codex/` はどれにも該当しない。現在 `.claude/agents/` はディレクトリごと消えており、`.gitignore` に `.claude/agents` が追加されている。今セッションで gpt-* が使えているのはセッション開始時に読み込まれたスナップショットのためで、**次回セッション以降は GPT エージェントが発見されなくなる**。

「`codex/` を追跡ソースとし、`.claude/agents/` へコピー/シンボリックリンクで配備（配備先は gitignore）」という運用を意図されているように見えるが、その場合も現時点で配備が行われていないため、リンクまたはコピーの再作成が必要。

**整合 OK と確認できた観点**：

- **gpt-sol の委譲マトリクス本体**（codex/gpt-sol.md:28-32）：通常コーディング→Sonnet / 複雑→Opus / その他→GPT Terra / 軽量大量→GPT Luna / 軽量単発→Haiku と、各フォールバックは CLAUDE.md の表と**完全一致**。
- **gpt-terra / gpt-luna の役割記述**：description・When to invoke とも方針の切り分け（その他⇔軽量大量⇔軽量単発）と文言レベルで整合。
- **フォールバック記述**：3 ファイルとも「GPT が使えない場合」（Sol→Opus / Terra→Sonnet / Luna→Haiku）と一致。
- **Fable / Opus / Sonnet / Haiku に定義ファイルが無いこと**：これらはモデル指定で表現される組み込みの名前であり、カスタム定義不要。問題なし。
- **frontmatter**：model 名（`claude-gpt-5-6-*`）・color は一貫。唯一 `tools: ["*"]` が gpt-sol だけ明示されているが、省略時も全ツール継承なので実効差はない（揃えるなら 3 ファイルとも省略が簡潔）。

**検査における洞察**：
- サブエージェントの frontmatter `description` は「人間向けの説明」ではなく、メインセッションが Agent ツールの委譲先を選ぶための**マッチング条件**として機能する。CLAUDE.md の方針を変えたら description も同時に更新しないと、方針と実際のルーティングが静かに乖離する。
- エージェント定義の発見パスは固定（プロジェクト/ユーザーの `.claude/agents/` とプラグインの `agents/`）なので、「ソースは別ディレクトリで管理し配備先を gitignore」する構成では、配備の仕組み（symlink やコピースクリプト）が構成の生命線になる。

**修正未実施**：上記の不整合と注意点を報告し、修正はユーザー指示待ち。
