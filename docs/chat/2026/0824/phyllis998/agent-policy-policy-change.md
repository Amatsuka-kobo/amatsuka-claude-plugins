## 設計骨子

### 1. 同梱エージェント: 7本 → 4本

- 残す: `gpt-sol` / `gpt-terra` / `gpt-luna`
- `grok-implementer` → **`grok`** へ改名し、researcher 役を吸収
- 廃止: `claude-researcher` / `gpt-researcher` / `grok-researcher`

Claude 帯(コードレビュー・アドバイザー・文書レビュー)は `model` 上書きで足りるので定義を持たない。リサーチ用の定義が要る利用者は、役割マーカー付きで自作する。

**捨てる利点を明記しておく** — 08-16 設計書 §6 は「探索実働を researcher へ寄せることで、探索の実行帯が権限面でも読み取り専用に固定される」と書いた。researcher 廃止でこれは失われ、探索実働は `Write`/`Edit`/`Bash` を持つ実装エージェントが担う。読み取り専用の担保は依頼文の制約へ移る。意図的な取り消しとして設計書に記録する。

### 2. MCP の削除

- `tools:` から `mcp__*` を全削除。残るのは `Read, Grep, Glob, Write, Edit, Bash, Skill, LSP, Agent` 等の素のツール
- 本文「ツール運用」節を丸ごと削除
- 削除で消える規律のうち、MCP と独立なもの(GitHub への書き込みはしない、ブラウザ操作は閲覧のみ)は「制約」節へ退避する。権限規律まで落とすと定義が緩む

### 3. 役割マーカー

frontmatter に `agent-policy-role:` を置き、値は役割 ID の CSV。

```yaml
---
name: my-heavy-coder
description: ...
model: my-custom-alias
tools: Read, Grep, Glob, Write, Edit, Bash
agent-policy-role: complex-impl, explore
---
```

SessionStart フックが `.claude/agents/*.md` を走査してマーカーを収集し、「担当表の『複雑または重要な実装』帯は `my-heavy-coder` を使う」と additionalContext へ注入する。方針スキル側に「注入された対応表は担当表より優先する」の一文を置く。

役割 ID は担当表の帯すべてに割り当てる(`research` / `realtime-research` / `design` / `explore-lead` / `explore` / `complex-impl` / `normal-impl` / `light-impl` / `code-review` / `advisor` / `doc-review` / `independent-review` / `general`)。フックは値を素通しするだけなので、ID を増やしても実装は変わらない。同じ役割を複数定義が宣言したらすべて列挙し、選択はオーケストレーターに委ねる。

### 4. フックの責務を「読んで注入する」に一本化

**ここが今回いちばん壊れやすい箇所。** 現行 `session-start.ts:107-146` は、エイリアス差分がある限り毎セッション同梱定義ベースで `.claude/agents/` を上書きする。setup でカスタムした tools は次のセッションで消える。

自動生成を廃止し、フックは次だけを行う:

- 方針スキルの注入(現行どおり)
- 役割マーカーの走査と対応表の注入(新規)
- エイリアス差分があるのに定義ファイルが無い → setup スキルの実行を促す(生成はしない)
- 旧定義(`claude-researcher` / `gpt-researcher` / `grok-researcher` / `grok-implementer`)の残骸通知

書き込みは setup スキルだけが行う。

### 5. setup-gpt / setup-grok の差分確認

テンプレート源は同梱 `agents/*.md`。`assets/` は持たない(二重管理を避ける)。`model:` 行だけ差し替える現フック方式を流用する。

上書き時の流れ:

1. `--check` がスクリプトから構造化差分を返す — `tools` の集合差(既存にしか無い / テンプレートにしか無い)、`model`、**テンプレートに存在し得ない frontmatter キー**(役割マーカー・ユーザー独自キー)、本文見出しの集合差(既存にしか無い節)
2. スキルが差分を提示し、`AskUserQuestion` で方針を選ばせる。推奨案は「既存にしか無い tools・未知キー・既存にしか無い節を残してマージ」
3. 選択を `--write --keep <...>` でスクリプトへ渡し、合成と書き込みはスクリプトが行う

書き込みをスクリプトに閉じることで再現性を確保する。節の中身の一部改変までは検出できないので、その旨を差分提示に添える。

## 経路2: プラグイン ↔ 利用者の `.claude/agents/`

setup が生成した定義はプラグイン更新に自動追随しない。プラグイン側の断片を直しても、利用者の手元は古いまま。**これは同梱 agents の有無と無関係に発生する** — setup スキルが存在する限り必ず起きる。0.6.0 以前も同じ問題を抱えていて、それが 0.7.0 で同梱化した動機だった。

`★ Insight ─────────────────────────────────────`
