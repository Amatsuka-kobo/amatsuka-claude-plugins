## 結論: as-is が正しい状態。挙動は意図的な設計判断

`/metatron:init` が `GOTCHAS.md` を作らないのは仕様。実装漏れではない。

### 根拠(直接の明文)

- `plugins/metatron/skills/capturing-architecture/SKILL.md:154` — 「GOTCHAS の台帳は初回生成では作らない。最初のエントリを記録するときに `append-gotcha` が台帳ごと作る」
- `plugins/metatron/references/gotchas-format.md:14` / `skills/recording-gotchas/SKILL.md:51` — 「自前でファイルを作らない」を二重に規律化
- `plugins/metatron/src/lib/gotchas.ts:616-620` — append-gotcha が未存在時に雛形ごと作る実装。生成コードパスは**ここにしか無い**。init/stage/commit のどこにも無い
- git 履歴: 非生成の明文と生成フォールバックが metatron 初出コミット `1e4508b` で**同時導入**。後付けの辻褄合わせではない

### なぜ生成しないか(2層)

**第1層(設計上の役割分担)**: GOTCHAS は「起きてから記録する資産」。init が扱う ARCHITECTURE(構造の記述)とは資産の性質が違う。同型の `## ADR 一覧` も同じ理由で初回生成の対象外(`harness-docs/design/2026-08-16-metatron-design.md:1489`)。

**第2層(その判断の理由)**: `同design:1779-1782` に明記 — 「記録の契機は失敗発生時であり、そこで『初期化してください』と止めるのは**学習機会の損失**になる」。だから台帳の有無をブロッカーにせず、記録の瞬間に台帳ごと作る。旧 Codiel 方式(`install-harness.sh` での `GOTCHAS.example.md` コピー)は `同design:1653` で**意識的に削除**されている。

codiel も完全に同思想(`plugins/codiel/commands/init.md:2`、`skills/recording-gotchas/SKILL.md:141`)。両プラグインで揃っている。

`★ Insight ─────────────────────────────────────`
- `get gotchas` は未存在時に `error:"not_created"` を返すが **exit 0**(`src/cli/output.ts:32-40` が `process.exitCode` を触らない)。「無い」を異常ではなく状態として扱う設計が、エラー設計の層でも一貫している。
- 一方 `tag-gotcha` は未存在時に `throw`(`src/lib/gotchas.ts:990-993`)。append は作る/tag は落ちる、という非対称は「書き込みの契機か、既存物への操作か」で切り分けられている。
`─────────────────────────────────────────────────`

ご指定の to-be は設計判断の反転を意味する。推奨は **案1(挙動は変えず文面を直す)**。

理由: 非生成には理由付きの設計判断があり、codiel と 2 プラグインで揃っている。反転すると codiel 側の `src/__test__/install-harness.test.ts:44`(「GOTCHAS.md を作ってはいけない」を明示アサート)まで巻き込む。そして今回の不満の実体は「台帳が無いこと」ではなく「作られると思ったのに作られない」という期待のズレなので、文面の是正で解消する。
