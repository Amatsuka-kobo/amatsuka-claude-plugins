# phyllis998

> task-utilityプラグインに、GitHub Issueを起票するスキルを追加したいです。
> プラグインがインストールされたプロジェクトのリモートリポジトリが対象です。
> インストールされたプロジェクトがgitリポジトリではない場合は、gitリポジトリにするよう推奨しつつSTOPします。
> MCPサーバーなどから提供されるToolでGitHubが操作できる環境であった場合はそのToolを、そうでなかった場合はghコマンドを使用します。
> ユーザーから与えられた情報をもとに、ユーザーとのブレインストーミングをもってIssueの内容を決めていきます。
> ユーザーとのディスカッションには、ユーザーが使用する言語の使用を厳密に守る必要があります。(有意義な対話にするため)
> 対象のリポジトリにIssue Templateが設定されている場合、ユーザーとのディスカッションの中でどのテンプレートを使用するか、あるいはテンプレートは使用しないか、最初に確認をとる必要があります。
> このスキルの名前は何がよいかを含め、一緒に設計を考えてください。

ユーザーから GitHub Issue 起票スキル追加の要件を受け取った。対象の範囲、環境チェック、操作手段の選択、ユーザーとのディスカッションプロセス、テンプレート対応、スキル名検討まで含めた総合設計を求めている。

# AI

task-utility プラグインの構造と既存スキル( `chat` など)を確認した後、brainstorming スキルに従い、段階的に設計を詰めていった。

**環境チェック**: リモートリポジトリへのアクセス・git リポジトリ化の判断は、外部スクリプトで事実を収集し、SKILL.md のフロー内でモデルが判断する責務分割を採用。

**操作手段**: MCP Tool の有無の判定はモデルのコンテキストにのみ存在するため、スクリプトからは GitHub 操作系 MCP Tool の有無を観測できず、この部分だけスキル内での判定とすることを説明。

**Issue 本文の言語**: リポジトリの README・既存 Issue から言語を推定し、ユーザーに確認してから確定。推定される言語とユーザーの実際の使用言語が異なる場合のため、明示確認ステップとした。

**メタデータ(ラベル等)**: ラベルのみを既存ラベルから提案。アサイン・マイルストーン等については SKILL.md の仕様に含めない(ユーザーが後で手動で追加可能な判断)。

**対話スタイル**: 完全自由対話ではなく、Issue 種別ごとの観点チェックリスト( バグ報告: 再現手順・期待/実際の動作・環境、機能要望: 背景課題・提案・スコープ外、タスク: 目的・完了条件)を用意し、1問ずつ不足観点を質問する形式を案として提示。テンプレート選択時はテンプレートの項目がチェックリストになる。

**スキル名**: 初期候補として `open-issue`, `create-issue`, `issue-craft` を提示。ユーザーが `issue-craft` を選択。「下書きと起票を統一的に扱う」というニュアンスが要件に合致した選択と判断。

**実装アプローチ**: 案 A(SKILL.md 内に全ロジック)と案 B(スクリプト `check-issue-env.mjs` で環境チェック、node --test でテスト可能)を提示。ユーザーが案 B を採択し、テスト可能性と責務分割を重視。
