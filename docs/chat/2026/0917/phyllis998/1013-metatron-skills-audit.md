## eval が 20/20 でも実運用で発火しない理由

測定環境と実運用の差:

| | 測定環境 | 実運用 |
| --- | --- | --- |
| 競合するスキル | ほぼ無し | codiel・sandalphon・prompt-smith・chat-history など多数 |
| 依頼の明示度 | **全問が目的を明示** | 「ついでに」「これ合ってる?」など暗黙 |
| 文脈 | クエリ 1 本のみ | CLAUDE.md・進行中の作業・直前の会話 |

現行 eval の `should_trigger: true` 30 問を見直すと、**全問が「文書を作りたい」「古い」「記録して」と目的を明示している**。実運用の発火失敗はこの外側で起きているはずで、今の eval にはその形が 1 問も無い。

欠けている形の例:
- 目的が暗黙 —「新しく入れた依存、どこかに書いておく必要ある?」「ARCHITECTURE って今の実装と合ってる?」
- 別作業のついで —「この PR マージする前にアーキ文書も揃えといて」
- 語彙が違う —「同じミス繰り返さないようにメモ残して」(「台帳」「GOTCHAS」を使わない)
- rules 起点 —(updating の実測失敗 `#5` `#9` がまさにこの系統)

false 側も、隣接プラグインと competing する場面が手薄い。
